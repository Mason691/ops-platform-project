请基于当前 Git 差异（git diff）生成规范的 Pull Request 描述，使用自然语言，结构必须包含以下部分：

1. **标题**  
   - 用一句话概括本次改动，简明扼要，如"新增用户登录接口，支持 JWT 认证"。

2. **动机**  
   - 说明为什么要做这个改动，解决了什么问题，或满足了什么需求。

3. **模块级变更列表**  
   - 按模块或文件分类，列出主要变更内容和目的。  
   - 例如："auth 模块：新增 Token 生成与验证逻辑；user 模块：接口参数增加校验"。

4. **影响范围**  
   - 指出哪些模块、接口、页面或数据流会受此改动影响，便于 reviewer 聚焦。  
   - 若有对外部系统或 API 消费者的影响，也需说明。

5. **测试建议**  
   - 给出 reviewer 应重点测试的功能点、边界条件、异常场景等。  
   - 可提及需要手动测试或自动化测试覆盖的部分。

6. **风险提示**  
   - 列出已知的风险、未解决的问题、潜在副作用等。  
   - 如果此前的代码审查（如 /code-review）发现过严重问题并已修复，请在此处明确说明问题及修复措施。

输出格式应为整洁的 Markdown，可以直接粘贴到 PR 描述框中使用。
保存后，在 Claude Code 中输入 /pr 即可自动按此模板生成 PR 描述。
