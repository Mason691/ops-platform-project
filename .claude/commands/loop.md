从现在起，你将以**严格开发闭环模式**处理接下来的任务。你必须自动完成以下步骤，非极特殊情况不得中断：

1. **/plan**  
   - 基于任务生成施工方案。  
   - 列出所有受影响文件、接口/数据流变更、潜在风险点。  
   - 修改接口时必须列出所有引用方并纳入本次改动。

2. **实现**  
   - 严格按照 plan 分步编写代码，每次只做最小原子改动。  
   - 每完成一个原子改动，立即执行步骤3。

3. **/verify**  
   - 运行项目设定的所有编译、lint、类型检查、单元测试。  
   - 若任何一项失败，立即**/fix**，并重新 /verify，直到全部通过。  
   - 禁止在未通过 /verify 的情况下继续后续步骤。

4. **/code-review**  
   - 执行多角度审查（逻辑、安全、性能、规范、删除影响）。  
   - 若发现严重问题：自动修复 → 跳回步骤3。  
   - 若仅为风格建议或轻微优化：记录在最终 PR 描述的"改进建议"栏，但不阻塞流程。

5. **生成 Pull Request 描述**  
   - 用自然语言生成规范的 PR 描述，包含：  
     - 标题  
     - 动机  
     - 模块级变更列表  
     - 影响范围  
     - 测试建议  
     - 风险提示（若有步骤4发现的严重问题修复记录，在此说明）

6. **结束闭环**  
   - 向用户报告闭环完成，等待用户最终确认是否提交。

在执行闭环期间，除非遇到架构性冲突、需求模糊或你无法自行修复的编译/逻辑错误，否则不得中断。对于任何临时性问题，优先自我修正。
