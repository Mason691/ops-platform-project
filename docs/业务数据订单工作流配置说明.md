# 业务数据订单工作流配置说明

> 版本：2026-11-14
> 适用：底座平台（ai-native-platform）+ ops 运营平台
> 目标：业务数据订单的「经办人上报 → 部长审核 → 财务核对 → 派工出库 → 施工中 → 施工完成 → 售后维护」全部由底座工作流组件驱动；ops 不再保留硬编码的财务核对入口、派工单、公众号模板配置。

---

## 一、部署顺序（必须先做）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 平台库 `ai_platform` 执行 `doc/migration_workflow_business_flow.sql` | 工作流节点业务字段、回调地址、角色审批人 |
| 2 | 平台库执行 `doc/add_business_order_status_dict.sql` | 业务状态字典 `business_order_status`（0~6） |
| 3 | ops 库 `mall_db` 执行 `sql/migrate_business_order_biz_status.sql` | 订单加 `biz_status/wf_instance_id/...`；从旧派工回填；建 `ops_business_flow_record` |
| 4 | 发布新平台后端 JAR、新 ops 后端 JAR | 两者必须同时具备新接口（工作流内部发起 + ops 业务回调） |
| 5 | 发布平台主站前端、ops H5 | 业务数据列表、工作流节点配置、流程处理页 |
| 6 | ops 库执行 `sql/archive_and_drop_dispatch_wx.sql` | **新 JAR 上线后**归档并删除旧派工/公众号模板表 |
| 7 | 平台库执行 `doc/remove_dispatch_wx_template_menus.sql` | 下线「派工单管理」「公众号消息模板」菜单 |
| 8 | host nginx 增加 `/ops/business-data/flow-task` 白名单 | 指向主站 9081，见第七节 |

> 回滚：`sql/rollback_archive_dispatch_wx.sql` 恢复归档表（先用历史 DDL 重建空表）；平台迁移回滚语句见 `migration_workflow_business_flow.sql` 文件末尾。

## 三、角色准备

工作流节点支持「按企业角色名」实时解析处理人（`sys_corp_user_role.role_name`）。请在每个城市合伙人组织下创建并绑定以下角色（名称必须一致）：

| 角色名 | 用途 |
|---|---|
| 部长 | 部长审核节点 |
| 财务 | 财务核对节点 |
| 派工员 | 派工出库节点 |
| 施工员 | 施工中节点（兜底；正常由派工单动态指派） |
| 验收员 | 施工完成节点 |
| 售后 | 售后维护节点（可选） |

> 角色解析规则：`INITIATOR_CORP` = 订单归属组织；`OPERATOR_TREE` = 运营商及全部下级组织。建议财务/部长使用 `INITIATOR_CORP`；如运营商财务需要代办下级订单，可在节点上**同时**添加运营商财务为指定审批人（指定审批人与角色可并存）。

## 四、工作流定义配置

### 4.1 流程基本信息

登录平台 → 运营管理 → 工作流配置 → 新建工作流：

| 字段 | 值 |
|---|---|
| 工作流编码 | `biz_order_flow` |
| 工作流名称 | 业务数据订单处理流程 |
| 业务类型 | `OPS_BUSINESS_ORDER` |
| 业务回调地址 | 生产 unified 部署（platform/ops 均 host 网络）：`http://localhost:8082/api/internal/workflow/business-order/event`；本地：`http://localhost:8084/api/internal/workflow/business-order/event`；若 platform 为 bridge 网络，改为 `http://172.17.0.1:8082/...` 或 ops 容器名 |
| 状态 | 启用 |

> ops 后端通过环境变量 `WORKFLOW_BUSINESS_ORDER_DEFINITION_CODE` 指定编码（默认 `biz_order_flow`）；平台与 ops 的 `platform.internal-token` 必须一致。
>
> 回调会携带 `X-Internal-Token`，平台对目标主机做白名单校验：
> `workflow.business-callback-allowed-hosts`（默认 `localhost,127.0.0.1,172.17.0.1`，`*` 表示不限制）。
> 跨主机部署时把 ops 主机加入该配置，否则回调会被拒绝。

### 4.2 节点配置

按下表逐节点配置（节点序号从 1 开始；节点 0 用「发起节点」表示）：

| 序号 | 节点名称 | 节点类型 | 审批模式 | 业务状态值 | 审批人/角色 | 驳回方式 | 退回状态值 | 节点动作 | 业务页 URL |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 经办人上报 | 发起节点 START | 或签 | 0 | 无需配置 | 退回发起人 | 0 | 无 | 无 |
| 2 | 部长审核 | 审批 APPROVAL | 或签 | 1 | 角色「部长」，范围「订单归属组织」 | 退回发起人 | 0 | 无 | 无 |
| 3 | 财务核对 | 审批 APPROVAL | 或签 | 2 | 角色「财务」，范围「订单归属组织」+（可选）运营商财务指定审批人 | 退回发起人 | 0 | 财务核对 | `/ops/business-data/flow-task?taskId={taskId}` |
| 4 | 派工出库 | 审批 APPROVAL | 或签 | 3 | 角色「派工员」，范围「订单归属组织」 | 退回上一节点 | 2 | 派工出库 | `/ops/business-data/flow-task?taskId={taskId}` |
| 5 | 施工中 | 审批 APPROVAL | 或签 | 4 | 角色「施工员」（兜底；派工节点会动态指派上门员工） | 退回上一节点 | 3 | 施工记录 | `/ops/business-data/flow-task?taskId={taskId}` |
| 6 | 施工完成 | 审批 APPROVAL | 或签 | 5 | 角色「验收员」，范围「订单归属组织」 | 退回上一节点 | 4 | 施工验收 | `/ops/business-data/flow-task?taskId={taskId}` |
| 7 | 售后维护（可选） | 审批 APPROVAL（末节点） | 或签 | 6 | 角色「售后」，范围「订单归属组织」 | 退回上一节点 | 5 | 售后维护 | `/ops/business-data/flow-task?taskId={taskId}` |

配置要点：

1. **发起节点自动跳过**：类型为「发起节点」的节点不创建审批任务；订单创建时 ops 已写入 `biz_status=0`。
2. **末节点**：若配置售后节点，售后节点勾选「末节点」；不配置售后时，施工完成节点勾选「末节点」。
3. **动态指派**：派工出库节点提交后，ops 回调返回 `assigneeUserId`，工作流自动把下一节点（施工中）的任务指派给该员工；无需在节点上配置具体人。
4. **表单字段**：用于工作流任务详情页的通用表单；业务数据订单推荐填写 `formUrl`，由 ops 流程处理页渲染富表单。两者可同时配置，`formUrl` 优先。
5. **退回**：部长/财务「退回发起人」会把实例置为 REJECTED 并回调 `biz_status=0`；经办人在业务数据列表点「重新提交」发起新实例。施工完成「退回上一节点」会把实例退回到施工中节点并重建任务。

## 五、公众号消息模板申请与配置

### 5.1 微信公众平台申请模板

1. 登录 `mp.weixin.qq.com` → 功能 → 模板消息 → 我的模板（公众号需已认证并开通模板消息权限）。
2. 从模板库搜索「待办提醒 / 审核提醒 / 任务通知 / 工单通知」，选择最接近的模板；必要时申请新模板（使用场景示例：业务订单待办处理提醒）。
3. 记录：模板 ID、模板标题、模板内容（含 `{{thing1.DATA}}` 等变量）、每个变量的含义与长度限制。
4. 建议按场景准备多条模板（也可复用一条通用待办模板，用变量区分）：
   - 待办通知（审核/财务/派工/施工/验收）
   - 审批结果通知（通过/驳回）
   - 异常告警（消息发送失败/处理人未绑定）

### 5.2 平台配置消息模板

登录平台 → 运营管理 → 工作流 → 消息模板 → 新增：

| 字段 | 说明 |
|---|---|
| 模板名称 | 与微信后台一致，如「业务订单待办通知」 |
| 业务场景 | `TASK_CREATED`（待办）/ `APPROVED`（通过）/ `REJECTED`（驳回）/ `TERMINATED`（终止）/ `CC`（抄送）/ `ALERT`（告警） |
| 微信模板 ID | 粘贴 5.1 记录的 ID |
| 关联公众号 | 平台当前只支持配置的单一服务号（`WECHAT_APP_ID`）；模板 `appId` 留空即可 |
| 模板内容 | 原样粘贴微信后台内容，保留 `{{xxx.DATA}}` |
| 字段映射 | JSON：`{"thing1":"{nodeName}","number2":"{businessId}","time3":"{submitTime}","thing4":"{businessSummary}"}` |
| 跳转链接 | 待办类（`TASK_CREATED`）：`https://boss.jdzn99.com/ops/business-data/flow-task?taskId={taskId}`；结果类：`https://boss.jdzn99.com/workflow/task/{taskId}` |

可用变量（工作流组件内置）：

| 变量 | 含义 |
|---|---|
| `{instanceId}` / `{taskId}` | 实例/任务 ID |
| `{businessType}` / `{businessId}` / `{businessSummary}` | 业务类型/业务单据 ID/摘要 |
| `{initiatorName}` / `{applicantName}` | 发起人 |
| `{nodeName}` | 当前节点名称 |
| `{approverName}` / `{receiverName}` | 接收人 |
| `{submitTime}` | 提交时间（yyyy-MM-dd HH:mm） |
| `{opinion}` | 审批/驳回意见 |
| `{jumpUrl}` | 渲染后的跳转链接 |

> 字段名（thing1/number2/time3...）必须与微信后台模板真实字段一致。平台消息模板页提供「读取公众号模板」，可按字段中文标签自动推断映射；未映射必填字段禁止保存。

### 5.3 节点消息触发

工作流组件按「任务创建 / 审批通过 / 驳回 / 终止 / 抄送」自动发送，无需逐节点绑定：

| 事件 | 接收人 | 场景 |
|---|---|---|
| 节点任务创建 | 该节点审批人/角色解析出的员工 | `TASK_CREATED` |
| 实例完成/通过 | 发起人 + 全部审批人 | `APPROVED` |
| 实例驳回 | 发起人 + 全部审批人 | `REJECTED` |
| 实例终止 | 发起人 + 全部审批人 | `TERMINATED` |
| 抄送节点 | 抄送人 | `CC` |
| 发送失败/处理人未绑定 | 运营商管理员 + `workflow.alert-user-ids` | `ALERT` |

发送为异步，失败落 `wf_message_send_log` 与工作流异常中心，可在「异常处理中心 → 重新推送」手动重发。员工需已关注公众号并完成绑定（「我的 → 微信绑定」）。

### 5.4 测试

1. 消息模板页 → 「发送测试」→ 选择测试员工 → 确认微信收到并正确渲染。
2. 发起一笔测试订单 → 部长收到待办消息 → 点击消息进入审批详情 → 同意 → 财务收到消息 → …按第六节走通全流程。

## 六、端到端验证

1. 员工 H5 新增一笔业务数据（或后台导入）→ `ops_business_order.biz_status=0`、`wf_instance_id` 非空。
2. 部长账号在「我的待办」看到任务 → 查看订单详情 → 同意 → `biz_status=1`。
3. 财务账号处理 → 填写收据号/财务收款日期/横排数/是否收款/核对结论：
   - 通过 → `biz_status=2`，进入派工；
   - 不通过 → 填写原因（≥5 字）→ 退回经办人，`biz_status=0`；
   - 暂缓 → 字段保存，任务停留当前节点。
4. 派工员处理 → 选择上门员工/时间/工单类型/商品 → 提交 → SCM 生成未审核销售出库单 → `biz_status=3`，进入施工中且任务指派给所选员工。
5. 施工员工提交施工/完工记录 → `biz_status=4`，进入施工完成。
6. 验收员通过 → `biz_status=5`；配置售后节点则进入 `6`，否则流程结束。
7. 验收不通过 → 退回施工中节点（`biz_status=4`）。
8. 重复提交派工 → SCM 按 taskId 幂等，不重复出库；订单已有有效出库单时直接拦截。
9. 提成计算/上报集团：在任意业务状态下均可执行；`calc_status` 变化不影响 `biz_status`；已上报集团仍锁定删除/修改/重算/财务核对（沿用原规则），但**不阻断**已核对订单的派工与施工。

## 七、前端路由与 nginx

新增页面：`/ops/business-data/flow-task`（平台主站 `views/biz/BusinessDataFlowTask.vue`）。

host nginx（`/data2/nginx/conf/conf.d/boss.conf`）增加白名单，否则刷新会落到 Ops H5：

```nginx
location ^~ /ops/business-data/flow-task {
    proxy_pass http://172.17.0.1:9081;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_read_timeout 300s;
    proxy_buffering off;
}
```

执行 `docker exec nginx nginx -t && docker exec nginx nginx -s reload`。校验：`curl -I https://boss.jdzn99.com/ops/business-data/flow-task` 的页面标题应为「协同平台」。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 发起流程报「未找到已发布的工作流」 | 检查工作流编码 `biz_order_flow` 是否已发布；ops 环境变量是否一致 |
| 节点无待办/消息 | 检查角色名是否与组织内 `sys_corp_user_role.role_name` 完全一致；员工是否停用/未绑定公众号 |
| 节点动作报「未配置业务回调地址」 | 工作流定义的「业务回调地址」为空；按 4.1 配置 |
| 财务核对保存失败 | 收据号被其他客户占用 / 财务收款日期早于市场收款日期 / 订单含已上报集团数据 |
| 派工提示「供应链服务不可用」 | SCM 未启动或 `scm-service.base-url` 配置错误；系统 fail-closed，不推进 |
| 派工提示「已产生销售出库单」 | 订单已有有效出库单，禁止重复派工；在 SCM 核对 |
| 施工完成退回后任务没有指派给原施工员工 | 退回上一节点按节点配置的角色解析处理人（施工员角色），不保留动态指派；如需固定人员，请在节点上配置指定审批人 |
| 历史订单没有流程实例 | 历史数据不回填流程；如需纳入，管理员在业务数据列表调用 `POST /orders/{id}/start-flow`（状态 0 时） |
| 运营终止流程后业务状态不变 | 当前版本终止只结束实例，不改变 `biz_status`；如需「已终止」状态，在字典新增项并在节点/定义扩展中配置（本期未内置） |
| `biz_status` 显示原始数字 | 字典 `business_order_status` 未建或平台不可达；执行字典 SQL / 检查 `platform.base-url` |

## 九、关键约束

1. **业务状态与提成状态解耦**：工作流只写 `biz_status`；提成计算/上报集团只写 `calc_status`，两者互不影响。
2. **节点动作失败不推进**：财务核对、派工出库在审批任务落库前同步回调 ops；业务失败（如出库单创建失败）时审批失败，任务保持待处理。
3. **出库防重**：SCM 按 `taskId` 幂等；ops 在派工前查询订单是否已有有效出库单，fail-closed。
4. **消息失败不阻断审批**：消息异步发送，失败落异常中心；审批状态不受影响。
5. **流程版本**：已运行实例按原定义版本执行；修改流程需停用后新建同编码版本。
6. **删除旧功能**：旧派工单表、公众号模板表、菜单、H5 页面、接口均已删除；仅保留 `WechatOfficialAccountClient` 供公众号 JSSDK access_token 使用。
