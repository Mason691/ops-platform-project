# 第三章 基础资料

基础资料是供应链所有单据的取值来源。本章覆盖商品、品牌、类别、单位、标签、供应商、客户、仓库八类资料。先理解三条总规则，再看具体功能：

1. **金蝶是商品资料与仓库的权威源**：商品、品牌、类别、单位、仓库均以金蝶云星辰为准；平台只做同步、查询与归属管理，不提供本地新增/改编码。
2. **供应商共享、仓库归属到组织**：供应商按运营商体系共享（`parent_corp_id`），城市合伙人直接使用运营商的供应商；仓库通过“分配归属”落到具体组织（`corp_id`），归属后只有该组织能把它设为默认仓库。
3. **默认值分两级**：默认供应商由运营商设置，整个运营商体系共用一个；默认仓库由每个组织各自设置，只能设本组织自己的仓库。两者用于制单预填和以旧换新自动采购单，未配置会直接影响业务。

> 本章所有页面均在**平台主站**：`https://boss.jdzn99.com` → 左侧菜单“供应链管理”。公众号 H5 不提供基础资料维护入口。

## 3.1 商品信息

### 【功能说明】

商品信息是采购、入库、销售、出库、退货、盘点和物料领用/核销的商品主数据。平台从金蝶云星辰同步商品编码、名称、规格型号、品牌、类别、基本单位、批次管理、保质期和标签，供各单据选择。商品是否启用批次管理、是否有保质期，会直接决定入库/出库时是否必须录入批次和有效期，因此商品资料必须在做业务前同步完整。

### 【适用角色】

- 运营商：供应链管理、采购、销售、仓库、财务可查看；有同步权限的角色可执行“从金蝶同步”。
- 城市合伙人：可查看运营商共享的商品资料，用于本组织制单；不能本地新增、改编码、删除商品。
- 【不可见项】城市合伙人不显示“新增商品/编辑商品”入口（当前版本商品资料只读，商品维护请在金蝶完成）。

### 【操作入口】

- 平台主站 → 供应链管理 → 商品信息（`/subsystem/scm/bd/material`）。
- 采购订单、采购入库、销售订单、销售出库、销售退货、盘点、物料领取等页面的商品下拉，均取这里的商品。

### 【前置条件】

1. 运营商已在“供应链管理 → 金蝶账套配置”完成金蝶账套授权，且配置可用；
2. 商品已在金蝶云星辰维护完成（编码、名称、单位、批次/保质期属性）；
3. 当前账号有“商品信息”菜单权限；执行同步还需要同步按钮权限。

### 【操作步骤】

#### 从金蝶同步商品

1. 进入“供应链管理 → 商品信息”。
2. 点击右上角“从金蝶同步”。系统按最后同步时间增量拉取新增/变更商品。
3. 如需首次初始化或修复历史数据，点击“全量重新同步”。全量同步会重新拉取全部商品，但**不会清空本地表**，也不会删除已存在的商品。
4. 等待提示“同步完成：共 X 条，跳过 Y 条”。跳过表示本地已存在且无需更新，或该商品缺少关键字段。
5. 若提示“保质期字段不完整”，到商品详情检查金蝶侧的保质期单位和数值；修正后再次同步。

#### 查询商品

1. 在“商品名称”输入框输入关键字，支持模糊查询。
2. 可按“品牌”“规格型号”“批次管理（是/否）”筛选。

#### 查看商品详情

1. 在目标商品行点击“详情”。
2. 右侧抽屉展示商品编码、名称、规格型号、条形码、类别、品牌、基本单位、批次管理、保质期管理、保质期、金蝶 ID、同步状态。
3. 关闭抽屉返回列表。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 商品编码 | 系统带出 | 金蝶商品编码，平台内唯一；单据按编码取值 | `SP00012` |
| 商品名称 | 系统带出 | 金蝶商品名称 | `美的空调 1.5 匹` |
| 规格型号 | 系统带出 | 金蝶规格型号，可为空 | `KFR-35GW` |
| 条形码 | 系统带出 | 金蝶条形码，可为空 | `6901234567890` |
| 品牌 | 系统带出 | 取商品品牌资料 | `美的` |
| 商品类别 | 系统带出 | 取商品类别树 | `空调` |
| 基本单位 | 系统带出 | 取计量单位资料；单据的库存数量按基本单位 | `台` |
| 批次管理 | 系统带出 | 是=该商品入库/出库必须选择批次；否=不按批次管理 | 是 |
| 保质期管理 | 系统带出 | 是=入库需录生产日期/有效期；否=不管理 | 是 |
| 保质期 | 系统带出 | 数值 + 单位（天/月/年） | `365 天` |
| 标签 | 系统带出 | 商品关联的标签名称，可多个 | `热卖`、`新品` |
| 金蝶 ID | 系统带出 | 金蝶内部 ID，用于推送单据 | `2609487734758226944` |
| 同步状态 | 系统带出 | 已同步/失败/未推送；失败常见原因是保质期字段不完整 | 已同步 |

### 【业务规则与校验】

1. 商品资料以金蝶为唯一权威源，平台不提供本地新增、编辑、删除；需要改商品名称、单位、批次属性时，请先在金蝶修改，再回平台同步。
2. 增量同步按最后同步时间拉取；全量同步重新拉取全部商品，但不清空本地表、不删除历史商品。
3. 商品编码是单据取值键，**不要在金蝶随意改编码**；改编码会导致历史单据与商品资料对不上。
4. 批次管理=是的商品，在采购入库、销售出库、销售退货、盘点、物料领用/核销中必须选择批次；未选批次会被校验拦截。
5. 保质期管理=是的商品，入库时需要录入生产日期/有效期；近效期/过期库存在库存查询中单独提示。
6. 商品未同步金蝶（同步状态≠已同步或缺少金蝶 ID）时，以旧换新自动采购单、采购订单推送金蝶会失败；这类商品不能用于自动生成采购单。
7. 商品资料按运营商体系共享：城市合伙人看到的是所属运营商的商品，不是自己独立的一份。

### 【操作结果】

- 同步成功后，列表出现新增/更新的商品，同步状态变为“已同步”；
- 各单据的商品下拉立即可选到新商品；
- 商品详情展示最新批次/保质期属性；
- 同步失败的商品保留原记录，状态标记失败，不影响已存在单据。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “同步失败”或接口报错 | 金蝶账套配置错误、授权过期、网络不通 | 到“金蝶账套配置”检查账套与授权；确认服务器可访问金蝶后重试 |
| 提示“共 X 条，跳过 Y 条” | 本地已存在且无变更，或关键字段缺失 | 查看商品详情；若为保质期字段不完整，先修金蝶资料再全量同步 |
| 单据选不到新商品 | 未同步或同步失败 | 先在商品信息页执行“从金蝶同步” |
| 单据提示“该商品启用批次管理，请选择批次” | 商品批次管理=是 | 在单据的批次列选择具体批次；无批次可选时先做采购入库生成批次 |
| 单据提示“商品未同步金蝶” | 商品缺少金蝶 ID 或同步状态异常 | 在商品信息页重新同步；仍失败时检查金蝶商品状态 |
| 列表商品重复 | 金蝶存在重复编码，或历史同步异常 | 以金蝶为准清理重复商品；平台按编码合并，不要手工建重复商品 |

### 【注意事项】

1. 商品资料的修改入口在金蝶，不在平台；平台页面的“同步”是单向拉取。
2. 全量同步不会清空本地表，也不会删除已停用商品；历史单据仍能显示原商品名称。
3. 批次/保质期属性一旦被单据使用，不建议在金蝶随意切换；切换后新旧单据的批次要求会不一致。
4. 城市合伙人不要自行在金蝶另建一套商品；应与运营商使用同一账套、同一商品编码。
5. 商品标签在平台“商品标签”页维护，商品与标签的关联以金蝶同步结果为准。

### 【测试验证要点】

1. 增量同步后新增商品出现在列表，同步状态=已同步。
2. 全量同步不清空本地商品，历史商品仍可查询。
3. 批次管理=是的商品，在入库/出库/领用单据中必须选批次，未选被拦截。
4. 保质期管理=是的商品，入库必须录生产日期/有效期。
5. 未同步金蝶的商品无法生成以旧换新自动采购单，错误提示明确。
6. 城市合伙人能选到运营商商品，但不能新增/编辑商品。
7. 商品详情展示的金蝶 ID、同步状态与列表一致。

### 【常见问题】

> **Q：为什么商品信息页没有“新增”按钮？**
> A：商品以金蝶为唯一权威源，平台只做同步与查询。请在金蝶云星辰新增商品，再回平台点“从金蝶同步”。

> **Q：同步完成但单据里还是选不到商品？**
> A：先确认同步状态为“已同步”、商品未被停用；再刷新单据页面。若仍选不到，检查商品是否属于当前运营商账套。

> **Q：批次管理可以改成“否”吗？**
> A：可以在金蝶修改后同步，但已发生库存的商品不建议切换；切换后历史批次与新单据的批次要求会不一致。切换前请与仓库、财务确认。

## 3.2 商品品牌

### 【功能说明】

商品品牌用于商品分类展示和筛选，数据来自金蝶云星辰。平台提供品牌列表、Logo 展示和同步状态，不提供本地新增/编辑/删除。

### 【适用角色】

- 运营商：供应链管理、采购、销售可查看；有同步权限的角色可同步。
- 城市合伙人：可查看共享品牌资料。
- 【不可见项】两类角色均不显示本地新增/编辑/删除品牌入口。

### 【操作入口】

- 平台主站 → 供应链管理 → 商品品牌（`/subsystem/scm/bd/brand`）。

### 【前置条件】

1. 金蝶账套配置可用；
2. 品牌已在金蝶维护；
3. 有“商品品牌”菜单权限。

### 【操作步骤】

1. 进入“供应链管理 → 商品品牌”。
2. 点击“从金蝶同步”做增量同步；首次初始化或修复数据时点击“全量重新同步”。
3. 查看列表：品牌编码、品牌名称、Logo、同步状态。
4. 如需确认 Logo 是否正确，直接查看列表中的缩略图；Logo 缺失时显示“—”。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 品牌编码 | 系统带出 | 金蝶品牌编码 | `PP001` |
| 品牌名称 | 系统带出 | 金蝶品牌名称 | `美的` |
| Logo | 系统带出 | 金蝶品牌 Logo 地址；无则为空 | `https://...` |
| 同步状态 | 系统带出 | 已同步/失败/未同步 | 已同步 |

### 【业务规则与校验】

1. 品牌以金蝶为权威源，平台只读；品牌编码不要随意变更。
2. 品牌被商品引用；删除/停用品牌前先确认没有在用商品。
3. 同步不会删除本地品牌；金蝶删除品牌后，商品资料上的品牌名称按品牌表匹配，可能显示为空；历史单据仍保留品牌快照。
4. 商品筛选按品牌 ID 过滤，品牌名称变更后同步即可更新。

### 【操作结果】

- 同步后品牌列表更新，商品筛选下拉可用新品牌；
- Logo 更新后列表缩略图同步变化；
- 同步状态反映最近一次同步结果。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 品牌列表为空 | 未同步或金蝶无品牌 | 先同步；金蝶无品牌时先在金蝶维护 |
| 品牌重复 | 金蝶存在重复编码 | 以金蝶为准清理；平台按编码合并 |
| Logo 不显示 | Logo 地址为空或外链不可访问 | 在金蝶补 Logo；确认外链可访问 |
| 商品筛选没有新品牌 | 未同步 | 执行“从金蝶同步” |

### 【注意事项】

1. 品牌资料不在平台维护；需要新增品牌请到金蝶。
2. 全量同步不会清空本地品牌，不会影响历史单据。
3. 品牌 Logo 是外链图片，内网环境可能无法显示，不影响业务。

### 【测试验证要点】

1. 增量/全量同步后品牌列表正确。
2. 商品筛选可选到新品牌。
3. 品牌同步状态正确。
4. 城市合伙人可查看品牌，但不能本地新增/编辑。

### 【常见问题】

> **Q：品牌名称改了，商品列表还是旧名称？**
> A：先同步品牌，再同步商品；商品列表取商品资料中的品牌名称，需两次同步都完成。

> **Q：可以只给某个城市合伙人单独建品牌吗？**
> A：不可以。品牌按运营商体系共享，城市合伙人使用运营商的品牌资料。

- 类别层级与金蝶一致；
- 历史单据保留类别快照；商品资料上的类别按类别表匹配展示。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 类别树为空 | 未同步或金蝶无类别 | 先同步；金蝶无类别时先维护 |
| 层级不正确 | 金蝶父类别设置错误 | 在金蝶修正父子关系后全量同步 |
| 商品表单选不到类别 | 未同步或类别被停用 | 同步类别；确认类别状态 |

### 【注意事项】

1. 类别不在平台维护；新增/调整层级请到金蝶。
2. 全量同步不会清空本地类别，也不会删除历史类别。
3. 类别名称变更后，商品列表需同步商品才能显示新名称。

### 【测试验证要点】

1. 类别树层级与金蝶一致。
2. 商品表单/筛选可选到新类别。
3. 全量同步不影响历史商品。
4. 城市合伙人可查看类别树，不能本地新增/编辑。

### 【常见问题】

> **Q：为什么类别不能拖动排序？**
> A：类别层级和排序由金蝶维护，平台只读同步。

> **Q：类别删除了，历史商品怎么办？**
> A：历史单据保留类别快照；商品资料上的类别名称按类别表匹配，类别删除后可能显示为空；新商品不能再选该类别。

4. 单位变更后历史单据仍显示原单位。

## 3.5 商品标签

商品标签用于商品打标和筛选（如“热卖”“新品”），是**平台自维护**的资料，不走金蝶同步。标签编码会作为推送金蝶时的 `mullabel_number` 使用，因此编码必须与金蝶标签编码一致。

### 【适用角色】

- 运营商：供应链管理可新增、编辑、删除标签。
- 城市合伙人：可查看共享标签；当前版本不提供城市合伙人独立维护入口。
- 【不可见项】城市合伙人不显示“新增标签/编辑/删除”按钮。

### 【操作入口】

- 平台主站 → 供应链管理 → 商品标签（`/subsystem/scm/bd/material-label`）。

### 【前置条件】

1. 有“商品标签”菜单权限；
2. 标签编码已在金蝶确认（如需要推送金蝶）；
3. 标签名称、编码在平台内唯一。

2. 点击“新增标签”。
3. 填写“标签编码”（如 `HOT`），填写“标签名称”（如 `热卖`）。
4. 选择状态：启用/停用。
5. 点击“保存”，提示“保存成功”。

>
> 图注：列表列标签编码、标签名称、状态、操作（编辑/删除）；弹窗包含标签编码（提示“推送金蝶 mullabel_number 用”）、标签名称、状态开关、保存/取消。此处需补充实际界面截图。

#### 编辑/停用/删除标签

1. 在目标标签行点击“编辑”，修改名称或状态后保存。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 标签编码 | 必填 | 平台内唯一；推送金蝶时作为 `mullabel_number`，必须与金蝶标签编码一致 | `HOT` |
| 标签名称 | 必填 | 展示名称，可中文 | `热卖` |
| 状态 | 必填 | 启用=可选；停用=不在商品表单/筛选中出现 | 启用 |

### 【业务规则与校验】

1. 标签编码、标签名称均为必填；编码重复时提示“标签编码已存在：XXX”。
2. 标签编码会用于推送金蝶，编码不一致会导致金蝶侧标签匹配失败；修改编码前必须与金蝶确认。
3. 删除为逻辑删除；已关联商品的历史展示保留，后续商品不再可选。
4. 标签按运营商体系共享，城市合伙人使用运营商标签。
5. 标签不是金蝶同步的，平台新增后不会反向同步到金蝶；如需金蝶侧也有该标签，请先在金蝶维护相同编码。

### 【操作结果】

- 新增/编辑后标签列表更新；
- 启用的标签出现在商品表单和筛选；
- 停用/删除的标签不再可选；
- 商品详情按 `mullabel_number` 与标签表匹配展示；删除标签后该名称不再显示（编码仍保留在商品资料中）。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “标签编码与标签名称均为必填” | 有字段为空 | 补齐编码和名称 |
| “标签编码已存在：XXX” | 编码重复 | 换一个编码，或编辑已有标签 |
| 商品表单选不到新标签 | 标签停用或未保存 | 确认状态为启用并保存成功 |
| 推送金蝶提示标签不存在 | 平台标签编码与金蝶不一致 | 在金蝶维护相同编码，或修正平台编码后重新推送 |

### 【注意事项】

1. 标签编码是推送金蝶的键，**不要随意改**；改编码前先确认金蝶侧。
2. 删除标签是逻辑删除，不影响历史商品展示，但新单据不能再选。
3. 标签不参与金蝶同步，平台与金蝶需要各自维护相同编码。

### 【测试验证要点】

1. 新增标签后列表与商品表单可选。
2. 编码重复被拦截，提示明确。
3. 停用/删除后商品表单不再出现该标签。
4. 推送金蝶时 `mullabel_number` 使用标签编码。
5. 城市合伙人不能新增/编辑/删除标签。

### 【常见问题】

> **Q：标签需要先在金蝶建吗？**
> A：如果商品要推送金蝶并携带标签，建议先在金蝶建相同编码的标签；平台标签编码会作为 `mullabel_number` 推送。

> **Q：删除标签会影响已生成的单据吗？**
> A：历史单据保存的是商品/标签快照，不受影响；商品资料上的标签名称按标签表匹配，删除标签后不再显示该名称，但商品上的标签编码仍保留。

## 3.6 供应商管理（含默认供应商）

### 【功能说明】

供应商是采购订单、采购入库的来源主数据，数据来自金蝶云星辰。供应商按**运营商体系共享**：运营商及其下辖城市合伙人使用同一批供应商。运营商可以设置**默认供应商**，用于以旧换新自动采购单；整个运营商体系只有一个默认供应商。

### 【适用角色】

- 运营商：供应链管理、采购可查看与同步；有权限的运营商管理员可设置默认供应商。
- 城市合伙人：可查看运营商共享的供应商，用于本组织采购制单；**不能设置默认供应商**。
- 【不可见项】城市合伙人不显示“设为默认”按钮（后端同样拒绝）。

### 【操作入口】

- 平台主站 → 供应链管理 → 供应商管理（`/subsystem/scm/supplier`）。

### 【前置条件】

1. 金蝶账套配置可用；
2. 供应商已在金蝶维护并启用；
3. 设置默认供应商：当前账号为运营商、有 `scm:supplier:default` 权限；供应商状态为正常且已同步金蝶。

### 【操作步骤】

#### 同步与查询供应商

2. 点击“从金蝶同步”增量同步；首次或修复数据时点击“全量重新同步”。
3. 在搜索框输入“供应商名称 / 编码 / 联系人”后回车或点击“搜索”。
4. 列表展示供应商编码、名称、联系人、电话、地址、默认标记、状态。
5. 状态说明：正常、停用、黑名单；停用/黑名单供应商不能用于新单据（以页面校验为准）。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 供应商编码 | 系统带出 | 金蝶供应商编码，体系内共享 | `GYS00004` |
| 供应商名称 | 系统带出 | 金蝶供应商名称 | `物资公司` |
| 联系人 | 系统带出 | 可为空 | `张三` |
| 电话 | 系统带出 | 可为空 | `13800000000` |
| 地址 | 系统带出 | 可为空 | `甘肃省...` |
| 默认 | 系统标记 | 整个运营商体系只有一个默认供应商 | 默认 |
| 状态 | 系统带出 | 0=停用，1=正常，2=黑名单 | 正常 |

### 【业务规则与校验】

1. 默认供应商按 **`parent_corp_id`（运营商）唯一**：整个运营商体系共用一个，不是每个城市合伙人各一个。
2. 只有运营商可以设置默认供应商；城市合伙人调用接口会被拒绝：“仅运营商可设置默认供应商”。
3. 设置默认前必须同时满足：供应商状态=正常、同步状态=已同步、金蝶 ID 非空；否则提示“供应商已停用，不能设为默认”或“供应商未同步金蝶，不能设为默认”。
4. 设置成功会自动清除原默认；同一事务内先清旧再设新，数据库唯一索引兜底并发。
5. 金蝶同步只更新供应商名称、联系人、电话、地址、金蝶 ID、同步状态；**不会覆盖默认标记**。
6. 默认供应商用于以旧换新自动采购单：生成采购单时自动带出；未设置/停用/未同步时，自动采购单生成会被拒绝，业务订单 H5 会显示失败原因。
7. 财务核对触发自动审核时，会再次校验默认供应商仍有效且未变更；变更会导致自动审核失败，采购单保持草稿，需运营商修正后重新触发。

### 【操作结果】

- 默认标记移动到新供应商；
- 后续以旧换新自动采购单使用新默认供应商；
- 已生成的历史采购单不受影响（保持原供应商）；
- 原默认供应商标记被清除。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 看不到“设为默认”按钮 | 当前账号不是运营商或无权限 | 用运营商账号登录；确认已授予 `scm:supplier:default` |
| “供应商已停用，不能设为默认” | 供应商状态不是正常 | 在金蝶启用供应商并同步 |
| “供应商未同步金蝶，不能设为默认” | 没有金蝶 ID 或同步状态异常 | 在供应商管理页重新同步；仍失败时检查金蝶供应商状态 |
| “仅运营商可设置默认供应商” | 城市合伙人调用 | 由运营商设置；城市合伙人只能使用 |
| “默认供应商设置冲突，请重试” | 并发设置/唯一索引冲突 | 刷新列表后重新设置 |
| 以旧换新采购单生成失败：“当前运营商未设置默认供应商” | 未设置默认供应商 | 运营商设置默认供应商后，重试生成/重新触发 |
| 以旧换新采购单生成失败：“默认供应商未同步金蝶” | 默认供应商失效 | 重新同步或更换默认供应商 |

### 【注意事项】

1. 默认供应商是运营商级配置，不是城市合伙人级；城市合伙人不能各设一个。
2. 更换默认供应商不会修改已生成的采购单；若采购单还在草稿且等待财务核对，自动审核会因“默认供应商已变更”失败，需要重新生成或修正草稿后重试。
3. 金蝶同步不会冲掉默认标记；但如果供应商被金蝶停用，默认标记仍在，自动审核会因“默认供应商已停用”失败。
4. 建议选择长期合作、已同步金蝶、状态正常的供应商作为默认，避免自动采购单频繁失败。

### 【测试验证要点】

1. 运营商可设置默认供应商，原默认自动取消，唯一性生效。
2. 城市合伙人看不到“设为默认”，接口调用返回 403。
3. 停用/未同步供应商不能被设为默认，提示明确。
4. 金蝶同步后默认标记保留。
5. 未设置默认供应商时，新以旧换新采购单生成失败，提示“未设置默认供应商”。
6. 更换默认供应商后，财务核对自动审核按新默认校验，失败时不生成错误已审核单。
7. 历史采购单供应商不因默认变更而改变。

### 【常见问题】

> **Q：城市合伙人可以自己设默认供应商吗？**
> A：不可以。默认供应商按运营商体系唯一，只有运营商能设置；城市合伙人直接使用运营商的默认供应商。

> **Q：为什么设了默认供应商，以旧换新采购单还是显示“待财务核对”？**
> A：生成阶段本来就是草稿，待业务订单财务核对后才自动审核；如果财务核对后仍失败，查看采购单的“自动审核失败原因”，常见原因是默认供应商被停用/未同步或默认仓库变更。

> **Q：同步供应商会不会把默认标记冲掉？**
> A：不会。同步只更新金蝶字段，显式排除 `is_default/default_flag_key`；但供应商被金蝶停用后，默认仍指向它，自动审核会失败，需要重新选择默认。

## 3.7 客户管理（含客户转组织）

### 【功能说明】

客户是销售订单、销售出库、销售退货的结算对象。客户资料可由运营商新建，也可从金蝶同步。运营商可以把一个客户**转为平台组织**：系统按客户名称创建组织，业务联系人成为该组织管理员，联系人手机号即登录账号。该操作不可撤销，用于把客户发展为城市合伙人/独立组织。

### 【适用角色】

- 运营商：可查询、新建客户、维护联系人、启用/停用、从金蝶同步、创建组织。
- 城市合伙人：可查看所属运营商的客户资料，用于本组织销售制单；不能新建、编辑联系人、启停、创建组织。
- 【不可见项】城市合伙人看不到“新建客户 / 编辑联系人 / 创建组织 / 启用停用 / 从金蝶同步”按钮（后端同样按运营商校验）。

### 【操作入口】

- 平台主站 → 供应链管理 → 客户管理（`/subsystem/scm/bd/customer`）。

### 【前置条件】

1. 有“客户管理”菜单权限；
2. 新建/同步/转组织需要当前账号为运营商；
3. 客户转组织前：客户已有业务联系人和 11 位手机号，且客户未创建过组织。

### 【操作步骤】

#### 查询客户

1. 进入“供应链管理 → 客户管理”。
2. 在“客户编码 / 名称 / 联系人”输入框输入关键字。
3. 可按“客户状态（启用/停用）”筛选。
4. 点击“查询”；列表展示客户编码、名称、状态、简称、分类、地址、业务联系人、联系人手机、组织状态。
5. 组织状态：已创建/未创建；已创建表示该客户已转为平台组织。

#### 新建客户（运营商）

1. 点击“新建客户”。
2. 填写客户编码（全局唯一，如 `KH-WY-001`）、客户名称（必填）。
3. 按需填写客户状态、客户分类、客户简称、客户地址、业务联系人、联系人手机。
4. 点击“保存”，提示保存成功，列表出现新客户。

1. 在目标客户行点击“启用”或“停用”。
2. 在确认框中确认。
3. 提示“客户已启用/停用”，列表状态更新。

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 客户编码 | 必填 | 全局唯一；建议与金蝶编码一致 | `KH-WY-001` |

| 客户状态 | 选填 | 启用/停用；停用客户不能用于新单据 | 启用 |
| 客户分类 | 选填 | 客户分类名称或 ID | `经销商` |
| 客户简称 | 选填 | 列表展示用 | `武威商贸` |
| 客户地址 | 选填 | 客户地址 | `甘肃省武威市...` |
| 业务联系人 | 转组织时必填 | 客户对接人姓名 | `张三` |
| 联系人手机 | 转组织时必填 | 11 位、以 1 开头；转组织后作为管理员登录账号 | `13800000000` |
| 组织状态 | 系统带出 | 已创建/未创建；已创建不可再次创建 | 未创建 |

### 【业务规则与校验】

1. 客户编码全局唯一；重复提示“客户编码已存在”。
2. 新建客户必须填客户编码和客户名称；联系人/手机可后补，但转组织前必须补齐。
3. 客户列表按运营商关系表过滤：运营商看本运营商客户；城市合伙人看所属运营商的客户，只读。
4. 金蝶同步按客户编码合并；平台新建且金蝶不存在的客户，后续金蝶出现同编码客户时会合并，不产生重复。
5. 客户转组织是一次性操作：已创建组织的客户再次点击会被拒绝（“该客户已创建组织”）；前端在已创建后隐藏按钮，后端最终校验。
6. 转组织要求：业务联系人非空、联系人手机为 11 位有效手机号；否则提示“请先维护业务联系人”或“联系人手机号格式不正确”。
7. 转组织会调用平台内部接口创建组织，并把业务联系人设为组织管理员；初始密码由平台线下提供，不在页面展示。
8. 转组织不可撤销；创建前必须核对客户名称、联系人、手机号。

### 【操作结果】

- 新建/同步后客户列表更新；
- 联系人修改后列表与详情更新；
- 停用客户不能用于新单据；
- 转组织成功后客户“组织状态=已创建”，平台新增一个组织，业务联系人获得该组织管理员账号；
- 转组织后客户资料仍保留，可作为该新组织的客户继续使用。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “客户编码不能为空 / 客户名称不能为空” | 必填项缺失 | 补齐后保存 |
| “客户编码已存在” | 编码重复 | 换编码，或同步/编辑已有客户 |
| 城市合伙人看不到新建/编辑按钮 | 当前账号不是运营商 | 正常权限隔离；由运营商维护 |
| “请先维护业务联系人” | 客户无联系人 | 先点“编辑联系人”补齐 |
| “联系人手机号格式不正确” | 手机号不是 11 位或以 0 开头 | 改为 11 位手机号 |
| “该客户已创建组织” | 重复转组织 | 正常拦截；到组织管理查看已创建组织 |
| “该客户不属于当前运营商” | 客户关系不属于当前运营商 | 切换正确运营商；核对客户归属 |
| 同步后客户重复 | 金蝶编码不一致/手工建了不同编码 | 以金蝶编码为准合并；不要重复建客户 |

### 【注意事项】

1. 客户转组织不可撤销；创建前核对客户名称、联系人、手机号。
2. 转组织后手机号即管理员登录账号，必须真实可用；离职/换人需在用户管理中调整。
3. 城市合伙人只能查看所属运营商的客户，不能修改；如客户信息有误，联系运营商维护。
4. 停用客户前先确认没有在途销售订单/出库单；停用不影响历史单据查询。
5. 客户编码与金蝶保持一致，便于后续同步合并不产生重复。

### 【测试验证要点】

1. 运营商新建客户成功后列表可见，编码重复被拦截。
2. 城市合伙人只读，新建/编辑/转组织按钮不可见，接口调用被拒绝。
3. 编辑联系人要求 11 位手机号。
4. 客户转组织要求联系人和手机号；成功后组织状态=已创建，组织管理员账号生成。
5. 已创建组织的客户不能重复转组织。
6. 金蝶同步按编码合并不产生重复。
7. 停用客户不出现于新单据可选列表。

### 【常见问题】

> **Q：客户转组织后还能改客户名称吗？**
> A：客户资料仍保留，但组织名称已按客户名称创建；改名不会自动改组织名称。组织名称调整需在组织管理中处理。

> **Q：转组织失败提示“组织创建失败”，怎么办？**
> A：检查联系人手机号是否已被其他账号占用、客户名称是否重复、平台组织创建接口是否可用；根据错误详情修正后重试。

> **Q：城市合伙人能看到客户手机号吗？**
> A：客户列表对所属运营商体系可见，包含业务联系人和手机号；城市合伙人只读，不能修改。

## 3.8 仓库管理（含默认仓库、仓库分配）

### 【功能说明】

仓库是采购入库、销售出库、销售退货、盘点、物料领用/核销的库存地点。仓库以金蝶云星辰为权威源，平台只做同步、归属分配和默认仓库设置。仓库归属决定数据边界：运营商可查看本级 + 下辖全部仓库；城市合伙人只看归属本组织的仓库。默认仓库用于制单预填和以旧换新自动采购单，每个组织各自一个。

### 【适用角色】

- 运营商：查看全部仓库（本级 + 下辖），可同步、分配/取消分配归属、设置本级默认仓库。
- 城市合伙人：查看归属本组织的仓库，可同步、设置本组织默认仓库；不能分配归属、不能设置其他组织默认仓库。
- 【不可见项】城市合伙人不显示“分配归属/取消分配”按钮；运营商对下辖仓库不显示“设为默认”（不能代下级设置）。

### 【操作入口】

- 平台主站 → 供应链管理 → 仓库信息（`/subsystem/scm/warehouse`）。

### 【前置条件】

1. 金蝶账套配置可用；
2. 仓库已在金蝶维护并启用；
3. 设置默认仓库：仓库归属当前组织、启用且未禁用；有 `scm:warehouse:default` 权限；
4. 分配归属：当前账号为运营商，且目标组织是当前运营商下辖的城市合伙人。

### 【操作步骤】

#### 同步仓库

1. 进入“供应链管理 → 仓库信息”。
2. 点击“从金蝶同步”增量同步；首次或修复数据时点击“全量重新同步”。
3. 同步完成后提示“共 X 条，保留归属 Z 条，跳过 Y 条”。保留归属表示已分配的仓库不会被同步冲掉归属。
4. 运营商可在“按归属组织归组 / 按金蝶仓库分类归组”之间切换；城市合伙人默认只看“按金蝶仓库分类归组”。

#### 设置默认仓库（本组织）

1. 在归属本组织的仓库行点击“设为默认”。
2. 系统弹出确认框：“将 XXX 设为默认仓库，原默认将自动取消，确认？”
3. 点击“确认设置”。
4. 提示“默认仓库已更新”；该行显示“默认”标签，原默认标记消失。
5. 已禁用仓库的“设为默认”按钮置灰，提示“仓库已禁用，不能设为默认”。

#### 分配仓库归属（仅运营商）

1. 在未分配的仓库行点击“分配归属”。
2. 在弹窗中选择“城市合伙人”（只列出本运营商下辖合伙人）。
3. 点击“确认分配”，提示“分配成功”。
4. 该仓库归属变为所选城市合伙人；原默认标记被清空，新归属组织需重新设置默认。
5. 分配后，城市合伙人在自己的仓库页面可见该仓库；运营商仍可查看。

#### 取消分配（仅运营商）

1. 在已分配仓库行点击“取消分配”。
2. 提示“已取消分配”，仓库归属回到运营商本级。
3. 原归属组织的默认标记被清空；如需继续使用，由运营商或新归属组织重新设置默认。

2. 右侧抽屉展示仓库编码、名称、归属组织、仓库分类、金蝶 ID、启用状态、最后同步时间。

|---|---|---|---|
| 仓库编码 | 系统带出 | 金蝶仓库编码，单据按编码取值 | `CK00011` |
| 仓库名称 | 系统带出 | 金蝶仓库名称 | `美家本部仓` |
| 默认 | 系统标记 | 每个组织只有一个默认仓库 | 默认 |
| 金蝶仓库分类 | 系统带出 | 金蝶仓库分类名称，可为空 | `成品仓` |
| 归属组织 | 系统带出 | 仓库归属的运营商/城市合伙人；未分配=运营商直管 | `金昌美家` |
| 启用 | 系统带出 | 启用/禁用；禁用仓库不能设为默认、不能用于新单据 | 启用 |
| 金蝶 ID | 系统带出 | 金蝶内部 ID | `2609...` |
| 最后同步时间 | 系统带出 | 最近一次同步时间 | `2026-11-19 10:00:00` |

### 【业务规则与校验】

1. 默认仓库按 **`corp_id`（组织）唯一**：每个组织各一个，不是运营商体系共用一个。
2. 只能设置**归属本组织**的仓库为默认；运营商不能替城市合伙人设置，城市合伙人也不能设置其他组织的仓库。
3. 设置默认前仓库必须启用且未禁用（`enable_flag=1` 且同步状态不是 `DISABLED`）；禁用仓库按钮置灰，后端拒绝“仓库已禁用，不能设为默认”。
4. 设置成功会自动清除本组织原默认；数据库唯一索引兜底并发；冲突提示“默认仓库设置冲突，请重试”。
5. 分配归属会把仓库 `corp_id` 改为城市合伙人，并**清空默认标记**；新归属组织需要重新设置默认。
6. 取消分配把仓库归还运营商本级，同样清空默认标记。
7. 金蝶同步只更新名称、分类、启用状态、金蝶 ID、最后同步时间；**不会覆盖仓库归属和默认标记**。
8. 默认仓库用于采购入库、销售出库、销售退货、物料领用/核销等制单预填；以旧换新自动采购单的收货仓库取业务订单归属组织的默认仓库。
9. 未设置默认仓库时，制单页提示“当前组织未设置默认仓库，请手动选择收货仓库”；以旧换新自动采购单生成失败，提示“当前组织未设置默认仓库，无法自动生成采购订单”。

### 【操作结果】

- 默认标记移动到目标仓库；
- 制单页默认带出新默认仓库；
- 以旧换新自动采购单使用新默认仓库；
- 分配/取消分配后归属组织变化，原默认失效；
- 历史单据仓库不变。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 看不到“设为默认”按钮 | 仓库不属于当前组织，或当前账号非运营商且无权限 | 确认仓库归属；城市合伙人只能设本组织仓库 |
| “仓库已禁用，不能设为默认” | 仓库启用状态=0 或同步状态 DISABLED | 在金蝶启用仓库后同步；或选择其他启用仓库 |
| “只能设置本组织的仓库为默认仓库” | 试图设置下级组织仓库 | 由该组织自己设置；运营商不能代设 |
| “默认仓库设置冲突，请重试” | 并发设置/唯一索引冲突 | 刷新后重新设置 |
| 制单页没有默认仓库 | 本组织未设置默认仓库 | 到仓库信息页设置默认 |
| 以旧换新采购单生成失败：“当前组织未设置默认仓库” | 业务订单归属组织未设默认仓库 | 该组织设置默认仓库后重试生成/重新触发 |
| 分配归属下拉为空 | 当前运营商没有下辖城市合伙人 | 确认组织层级；先创建/挂接城市合伙人 |
| 同步后仓库归属丢失 | 旧版本同步逻辑问题 | 当前版本已改为只更新金蝶字段、保留归属；如仍出现请检查日志并重新分配 |

### 【注意事项】

1. 默认仓库是组织级配置，每个城市合伙人都要各自设置；运营商不能代下级设置。
2. 分配/取消分配会改变仓库归属并清空默认；操作前确认该组织当前没有依赖该默认仓库的在途单据。
3. 金蝶同步不会覆盖归属与默认标记；但仓库被金蝶停用后，默认仍指向它，制单/自动采购会失败，需要重新选择默认。
4. 禁用仓库不要直接删除；保留历史单据可追溯。
5. 仓库编码不要在金蝶随意修改；改编码会导致历史单据与仓库资料对不上。

### 【测试验证要点】

1. 运营商按归属组织归组能看到本级 + 下辖仓库；城市合伙人只看到本组织仓库。
2. 运营商可分配/取消分配；城市合伙人按钮不可见。
3. 默认仓库唯一性生效，原默认自动取消。
4. 运营商不能设置下辖仓库为默认；城市合伙人不能设置其他组织仓库。
5. 禁用仓库不能设为默认。
6. 分配/取消分配后默认标记清空，新归属组织需重设。
7. 金蝶同步保留归属和默认标记。
8. 未设置默认仓库时，制单提示手动选择，以旧换新采购单生成失败并提示明确。
9. 历史单据仓库不因默认变更而改变。

### 【常见问题】

> **Q：运营商为什么不能给城市合伙人设默认仓库？**
> A：默认仓库按组织隔离，每个组织只能设置本组织仓库；这是数据主权与权限边界的一部分。请由城市合伙人自己的账号设置。

> **Q：分配仓库后，原来的默认仓库怎么没了？**
> A：分配会改变仓库归属，原组织的默认不再成立，系统会清空默认标记；新归属组织需要重新设置默认。

> **Q：同步金蝶会不会把“默认”冲掉？**
> A：不会。同步只更新金蝶字段，显式排除 `is_default/default_flag_key`；但如果仓库被金蝶停用，默认仍指向它，需要重新设置。

## 本章 FAQ 汇总

> **Q：基础资料为什么大多是只读？**
> A：商品、品牌、类别、单位、仓库以金蝶云星辰为唯一权威源，平台同步后只读，避免两套数据不一致；供应商也以金蝶为准，仅默认供应商标记在平台维护。客户与标签是平台可维护的资料。

> **Q：城市合伙人和运营商看到的基础资料一样吗？**
> A：商品、品牌、类别、单位、供应商按运营商体系共享；仓库按归属组织隔离，城市合伙人只看本组织仓库；客户按运营商关系共享，城市合伙人只读。

> **Q：默认供应商和默认仓库有什么区别？**
> A：默认供应商按运营商体系唯一，仅运营商可设，用于以旧换新自动采购单；默认仓库按组织唯一，每个组织各自设置，用于制单预填和自动采购单的收货仓库。

> **Q：以旧换新采购单生成失败，先查哪里？**
> A：先查“默认供应商是否设置且正常/已同步”，再查“业务订单归属组织是否设置默认仓库”，最后查旧品商品是否都在商品库且已同步金蝶。采购单详情的“自动审核失败原因”会给出具体原因。
