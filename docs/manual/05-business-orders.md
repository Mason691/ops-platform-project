# 第五章 业务数据订单

业务数据订单是员工在公众号 H5 工作台发起的销售业务单据，也是派工出库、物料领用/核销、以旧换新采购单的起点。本章覆盖经办创建、订单类型、业务状态流转、审批流、待办事务和公众号审批消息。所有入口在 **OPS 公众号 H5**：`https://boss.jdzn99.com/ops/`（微信中打开）；PC 端仅用于查看/核审待办（平台主站“我的待办”）。

> 本章的“业务数据订单”与供应链的“采购/销售单据”不是同一概念：业务数据订单由员工发起，走 `biz_order_flow` 审批；供应链单据由供应链人员/系统生成，走各自的审核与金蝶推送。

## 5.1 经办创建（H5 工作台）

### 【功能说明】

员工在公众号员工工作台发起业务数据订单：录入客户、小区、商品、收款与凭证信息，提交后生成订单编号并进入“部长审核”流程。制单采用 5 步向导（基础信息 → 商品明细 → 支付信息 → 凭证信息 → 确认提交），支持本地草稿、缺项就地补填、提交防重。订单可包含全款、定金、以旧换新三种销售条件。

### 【适用角色】

- 城市合伙人内部员工（业务员基础角色、部长、派工员、施工员等）：可发起本组织业务订单；订单进入本组织部长审核。
- 运营商内部员工：可发起本级业务订单；运营商可查看下辖订单，但制单归属当前组织。
- 【不可见项】外部施工员（`userType=1`）不能发起业务订单（工作台可发起业务类型白名单为空）；未登录/未绑定员工无法进入制单页。

### 【操作入口】

- 公众号 → 员工工作台（`pages/employee/dashboard`）→ “新增业务”/“业务数据”卡片。
- 公众号 → 员工工作台 → 业务数据（`pages/employee/business-data`）→ 右上角“新增业务”。
- 直接打开：`https://boss.jdzn99.com/ops/?route=pages/employee/business-data-new`。

### 【前置条件】

1. 员工已登录 H5，且当前组织有业务订单发起权限；
2. 客户手机号可查询会员（未找到会员时提交会自动创建会员）；
3. 组织已配置所属区县（新建小区需要）；小区、批次、商品、品牌、型号、标准售价已由供应链/管理员维护；
4. 收款凭证、合同附件可上传；
5. 以旧换新：商品所属品牌“旧品”下有可选旧品，或使用“其他旧品”手工填写。

### 【操作步骤】

#### 第 1 步：基础信息

1. 进入“新增业务”，页面顶部显示 5 步步骤条：基础信息、商品明细、支付信息、凭证信息、确认提交。
2. “批次”：选择未上报集团的批次，或选择“新建批次”（系统按 `{公司简称}-{yyyyMM}` 自动生成）；提交后自动生成订单编号。
3. “客户手机”：输入 11 位手机号，点击“查询”。系统匹配平台会员：找到时提示“已匹配平台会员，客户名称可继续修改”；未找到时提示“未找到会员，保存时将自动创建会员”。
4. “客户名称”：查询后自动填充，也可手动修改（最多 50 字）。
5. “小区”：选择小区；小区多于 8 个时用底部弹层搜索。组织已配置区县时可点“＋ 新建小区”现场创建；未配置区县时提示联系管理员。
6. “详细地址”：填写楼栋/单元/门牌号（必填，最多 200 字）。
7. “经办人”：选择一名或多名经办人（最多 20 名，必须包含本人）。
8. 点击“下一步”。

1. 在商品卡片选择“品类”“品牌”“型号”；型号选定后系统自动查询标准售价。
2. 填写“销售单价”（大于 0）和“销售数量”（正整数）。

7. 点击“下一步”。

#### 第 3 步：支付信息

1. 选择“支付方式”：二维码 / 现金 / 转账（必填）。
2. 选择“市场收款日期”（必填，默认当天）。
3. 可填写“备注”（最多 500 字）。
4. 页面只读展示付款方式（全款/定金）与特批商品数量；特批字段在商品明细维护。
5. 点击“下一步”。

#### 第 4 步：凭证信息

1. “收据图片”（选填）：上传收据原图（1 张，≤20MB）；系统自动 OCR 识别收据号（优先右上角红色数字，未命中回退“入账日期”后 NO. 规则），识别结果可人工修改。
2. “收据号”（必填）：可手填或由 OCR 填入；只能包含字母、数字、短横线、下划线和斜杠；系统校验长度与重复占用。
3. “支付凭证”（必填）：上传银行或微信支付凭证，1~3 张，图片自动压缩。
4. “合同附件”（必填）：上传合同，1~5 份，支持 JPG/PNG/PDF，单个≤10MB。
5. 点击“下一步”。

1. 页面顶部“待补充事项”列出前面遗漏的必填项；可直接在下方补填，无需返回上一步。
2. 下方按“基础信息 / 商品明细 / 支付信息 / 凭证信息”展示只读汇总；每块右侧“修改”可跳回对应步骤。

#### 草稿恢复

1. 制单过程中退出页面，系统自动保存本地草稿（按组织+员工隔离，保留 7 天）。
2. 再次进入“新增业务”，系统提示是否恢复草稿；选择恢复后回到上次步骤与内容。
3. 提交成功后草稿自动清除；切换组织/切换员工不会串用草稿。

### 【业务规则与校验】

1. 客户手机必须是 11 位有效手机号；客户名称必填；小区和详细地址必填。
2. 经办人 1~20 名，且必须包含本人；多经办人订单的提成/待办按各自经办关系处理。
3. 商品行最多 50 行；同品类+品牌+型号不能重复，重复提示合并数量。
4. 销售单价必须 >0；销售数量必须为正整数；标准售价缺失/未配置时阻止制单。
5. 销售单价低于标准售价时自动标记特批：特批文件与提成比例（0~100）必填。
6. 以旧换新：抵扣金额 >0 且不超过商品金额；旧品至少 1 件、数量正整数；每行最多 50 件、整单最多 100 件；旧品可选“旧品”品牌商品或“其他旧品”手工填写。
7. 定金支付：定金 >0 且小于应付合计（应付=销售金额−抵扣），应补余款自动计算；全额支付请选全款。
8. 收据号必填，长度/字符集受限，系统校验重复占用；OCR 识别结果可人工修改，手工修改后不再自动覆盖。
9. 支付凭证 1~3 张、合同附件 1~5 份，格式/大小受限。
10. 提交时服务端再次全量校验；订单编号由服务端生成，前端只读；提交按钮防重，重复点击不会生成多单。
11. 草稿按组织+员工隔离保留 7 天；提交成功后清除；草稿恢复不覆盖已提交订单。

### 【操作结果】

- 提交成功生成业务订单编号，业务状态=0 经办人上报；
- 系统异步发起 `biz_order_flow` 实例，下一节点=部长审核，成功页显示下一审批人；
- 含以旧换新的订单同时生成旧品采购单草稿（见 4.1），待财务核对后自动审核推送；
- 订单出现在“业务数据”列表，经办人可查看进度；
- 草稿清除，可继续制单。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “请输入正确的11位手机号” | 手机号格式错误 | 改为 11 位手机号 |
| “请输入客户名称” | 客户名称为空 | 填写客户名称 |
| “请选择小区 / 请输入详细地址” | 基础信息缺失 | 选择小区并填写门牌号 |
| “当前组织未配置所在区县，请联系管理员完善组织信息后再新建小区” | 组织区县未配置 | 联系管理员配置区县，或选择已有小区 |
| “请选择经办人 / 经办人必须包含本人” | 经办人未选/未含本人 | 至少选择本人 |
| “该商品未配置售价，请联系管理员” | 商品标准售价缺失 | 联系供应链管理员配置标准售价 |
| “低于标准售价，请上传特批文件 / 请输入0-100的提成比例” | 低价特批字段缺失 | 上传特批文件并填写提成比例 |
| “以旧换新抵扣金额必须大于0 / 抵扣金额不能超过商品金额” | 抵扣不合法 | 调整抵扣金额 |
| “以旧换新至少录入1件旧品” | 旧品未录 | 添加旧品明细 |
| “定金金额必须小于应付合计，全额支付请选择全款支付” | 定金≥应付 | 减少定金或改全款 |
| “请填写收据号 / 收据号只能包含字母、数字…” | 收据号缺失/格式错误 | 补填或修正 |
| “收据号已存在” | 收据号被占用 | 核对收据号，避免重复 |
| “请上传支付凭证 / 请上传合同附件” | 凭证/合同缺失 | 上传后再提交 |
| 提交后页面无反应/重复点击 | 网络慢或防重遮罩 | 等待遮罩结束；刷新订单列表确认是否已生成 |
| 草稿没有恢复 | 超过 7 天/换组织/换员工 | 重新录入；草稿不跨组织/员工 |

### 【注意事项】

1. 订单编号在提交后生成，制单过程中显示“提交后自动生成”，不要手填。
2. 特批商品必须上传特批文件并填写提成比例，否则无法提交。
3. 以旧换新订单提交后会自动生成旧品采购单草稿；财务核对前不会自动审核，H5 成功页会显示“待财务核对后自动审核”。
4. 定金金额以抵扣后的应付合计为基数；定金不能等于或超过应付。
5. 收据号是财务核对的重要依据，OCR 识别后请人工核对，避免识别错位。
6. 切换组织/员工后草稿不通用；提交成功后草稿自动清除。

### 【测试验证要点】

1. 5 步向导步骤条、上一步/下一步、确认页就地补填正常。
2. 手机号查询会员/未找到提示正确；客户名称可修改。
3. 小区选择/新建小区（区县配置/未配置两种场景）。
4. 商品品类/品牌/型号联动，标准售价查询；低价特批校验。
5. 以旧换新抵扣/旧品校验；旧品采购单生成。
6. 全款/定金切换与定金校验；应补余款计算。
7. 支付方式/收款日期/备注；收据 OCR/收据号校验；凭证/合同上传。
8. 提交防重，成功后订单编号生成、下一审批人显示。
9. 草稿 7 天恢复、按组织+员工隔离、提交后清除。
10. 外部施工员无法发起业务订单。

### 【常见问题】

> **Q：提交后多久进入部长审核？**
> A：提交成功即异步发起流程，部长待办通常几秒内出现；若长时间没有，到“待办任务”刷新或联系管理员检查工作流配置。

> **Q：以旧换新采购单为什么显示“待财务核对”？**
> A：采购单生成时是草稿，业务订单到“财务核对”并提交后才会自动审核推送金蝶；不是制单失败。

> **Q：草稿能保存多久？换手机还能恢复吗？**
> A：草稿保存在当前手机本地，保留 7 天，按组织+员工隔离；换手机/清缓存/换组织不能恢复。

## 5.2 订单类型：全款、定金、以旧换新

### 【功能说明】

业务订单按收款方式分为全款订单、定金订单；按是否抵扣旧品分为普通订单、以旧换新订单。三者可以组合（如“定金 + 以旧换新”）。订单类型决定金额计算、收款字段、审批关注点和后续单据（以旧换新会生成旧品采购单）。

### 【适用角色】

- 城市合伙人/运营商内部员工：制单时选择付款方式与是否以旧换新。
- 财务：在财务核对节点核对收据号、收款日期、是否收款、核对结论；关注定金订单的应补余款。
- 供应链/采购：处理以旧换新生成的旧品采购单。
- 【不可见项】外部施工员不能制单，也不参与订单类型选择。

### 【操作入口】

- H5 新增业务 → 第 2 步“商品明细”底部“付款方式”（全款/定金）。
- H5 新增业务 → 商品卡片“是否以旧换新”（抵扣金额 + 旧品明细）。
- 业务数据订单详情/列表查看订单类型与金额。

### 【前置条件】

1. 全款/定金：已完成商品录入，应付合计 >0；
2. 以旧换新：商品金额 >0，旧品可选（“旧品”品牌商品或“其他旧品”手工填写）；
3. 定金：定金金额 >0 且小于应付合计；
4. 以旧换新：运营商已设置默认供应商，订单归属组织已设置默认仓库（否则旧品采购单生成失败，见 4.1）。

### 【操作步骤】

#### 全款订单

1. 商品明细底部“付款方式”选择“全款支付”。
2. 应付合计即客户本次应付金额；无需填写定金。
3. 继续支付信息/凭证信息，提交。

#### 定金订单

1. “付款方式”选择“定金支付”。
2. 填写“定金金额”（>0 且小于应付合计）。
3. 系统自动计算“应补余款 = 应付合计 − 定金金额”，不可手工填写。
4. 提交后订单记录定金与余款；财务核对时关注是否收齐/余款安排。
5. 后续如需补录余款，走“货款补录/收款补录”流程（见第 7 章相关入口）。

#### 以旧换新订单

1. 在商品卡片打开“是否以旧换新”。
2. 填写“抵扣金额”（>0 且不超过商品金额）。
3. 点击“＋ 添加旧品”，选择“旧品”品牌商品或“其他旧品（手工填写）”；填写旧品名称/数量。
4. 核对“抵扣后小计”和底部“应付合计”。
5. 提交后系统自动生成旧品采购单草稿；业务订单进入审批流。
6. 业务订单财务核对后，旧品采购单自动审核并推送金蝶（见 4.1）。

>
> 图注：付款方式全款/定金切换；定金金额与应补余款；以旧换新开关、抵扣金额、旧品明细、添加旧品；抵扣后小计/应付合计。此处需补充实际界面截图。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 付款方式 | 必填 | 全款支付/定金支付 | 定金支付 |
| 定金金额 | 定金时必填 | >0 且小于应付合计 | `1000.00` |
| 应补余款 | 系统计算 | 应付合计 − 定金金额 | `1999.00` |
| 是否以旧换新 | 选填 | 是/否 | 是 |
| 抵扣金额 | 以旧换新必填 | >0 且不超过商品金额 | `500.00` |
| 旧品明细 | 以旧换新必填 | 名称/数量；至少 1 件 | 旧空调 1 台 |
| 商品合计 | 系统计算 | Σ(销售单价×数量) | `2999.00` |
| 抵扣合计 | 系统计算 | Σ抵扣金额 | `500.00` |
| 应付合计 | 系统计算 | 商品合计 − 抵扣合计 | `2499.00` |

### 【业务规则与校验】

1. 全款/定金互斥；切换付款方式会二次确认并清空已填定金。
2. 定金必须 >0 且小于应付合计；定金等于/超过应付时提示改全款。
3. 应补余款由系统计算，不能手工填写。
4. 以旧换新抵扣 >0 且不超过该商品销售金额；旧品至少 1 件，数量正整数。
5. 旧品可选商品库中品牌=“旧品”的商品，或“其他旧品”手工填写；普通销售商品不能混入旧品。
6. 以旧换新订单提交后自动生成旧品采购单草稿；生成依赖默认供应商/默认仓库，缺失时订单详情显示失败原因。
7. 提成按销售额计算，抵扣不冲减提成基数（最终以服务端结果为准）。
8. 定金订单的“是否收齐全款”与“付款方式”是两个概念，不要在财务核对时混用。

### 【操作结果】

- 全款订单：应付=商品合计−抵扣；无余款。
- 定金订单：记录定金与应补余款；财务核对可据此确认收款进度。
- 以旧换新订单：生成旧品采购单草稿；财务核对后自动审核推送；施工完成提醒旧品入库。

### 【状态流转表】

| 订单类型 | 关键动作 | 金额影响 | 关联单据 | 库存影响 |
|---|---|---|---|---|
| 全款 | 提交 | 应付=商品合计−抵扣 | 无 | 不变 |
| 定金 | 提交 | 记录定金/余款 | 货款补录（如需） | 不变 |
| 以旧换新 | 提交 | 应付=商品合计−抵扣 | 旧品采购单草稿 | 不变（采购入库后增加） |
| 以旧换新 | 财务核对 | 不变 | 采购单自动审核推送 | 不变（入库后增加） |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “定金金额必须大于0” | 定金为空/0 | 填写定金 |
| “定金金额必须小于应付合计，全额支付请选择全款支付” | 定金≥应付 | 减少定金或改全款 |
| “以旧换新抵扣金额必须大于0” | 抵扣为空/0 | 填写抵扣金额 |
| “抵扣金额不能超过商品金额” | 抵扣过高 | 降低抵扣 |
| “以旧换新至少录入1件旧品” | 旧品未录 | 添加旧品 |
| 旧品采购单生成失败“当前运营商未设置默认供应商” | 默认供应商未设 | 运营商设置默认供应商后重试 |
| 旧品采购单生成失败“当前组织未设置默认仓库” | 默认仓库未设 | 组织设置默认仓库后重试 |
| 旧品采购单“待财务核对” | 正常状态 | 财务核对后自动审核 |

### 【注意事项】

1. 定金不是“部分收款方式”，而是订单销售条件；与支付方式（二维码/现金/转账）不同。
2. 以旧换新抵扣不能超过商品金额，避免负应付。
3. 旧品采购单生成失败不阻塞业务订单审批，但需尽快修复默认配置并重试，否则施工完成无法提醒旧品入库。
4. 提成基数按销售额，不按抵扣后金额；特批商品提成比例按商品行维护。

### 【测试验证要点】

1. 全款/定金切换确认与定金校验。
2. 应补余款自动计算，不可手工改。
3. 以旧换新抵扣/旧品校验；旧品只能选“旧品”品牌或手工。
4. 以旧换新订单生成旧品采购单草稿；默认配置缺失时显示失败原因。
5. 财务核对后采购单自动审核推送。
6. 提成按销售额计算。
7. 定金订单与“是否收齐全款”不混淆。

### 【常见问题】

> **Q：定金订单可以在 H5 补录余款吗？**
> A：余款补录走“货款补录/收款补录”入口（工作台/待办），不是在原订单上改金额；具体以当前组织开通的补录功能为准。

> **Q：以旧换新抵扣会减少提成吗？**
> A：不会。提成按销售额计算，抵扣不冲减提成基数；特批商品按商品行提成比例计算。

> **Q：旧品必须选商品库里的商品吗？**
> A：可以选“旧品”品牌商品，也可以选“其他旧品”手工填写；手工旧品后续在采购单完善时需映射到真实商品才能推送金蝶。

## 5.3 订单业务状态流转

### 【功能说明】

业务订单的业务状态（`biz_status`）由底座工作流驱动，字典 `business_order_status` 定义 0~7 与 -1（6=完工验收，7=历史归档）。状态决定当前由谁处理、订单出现在谁的待办、H5/PC 显示什么进度。它与提成计算状态（`calc_status`）、供应链单据审核状态完全解耦。

### 【适用角色】

- 全部内部员工：可查看自己经办/有权限的订单状态。
- 部长/财务/派工员/施工员/订单主经办人：按节点处理，推动状态前进。
- 运营商：可查看下辖订单状态；财务可核对下辖订单（如配置）。
- 【不可见项】外部施工员只能看到被指派的施工任务相关订单，不能查看全量业务数据。

### 【操作入口】

- H5 → 业务数据（`pages/employee/business-data`）→ 订单列表/详情 → 进度步骤条。
- H5 → 待办任务 → 任务卡片显示当前节点。
- PC → 业务数据后台（`/ops/business-data`）→ 业务状态列/筛选。

### 【前置条件】

1. 订单已提交并成功发起工作流实例；
2. 字典 `business_order_status` 已配置；
3. 工作流定义 `biz_order_flow` 已发布且节点/角色配置正确。

### 【操作步骤】

1. 在业务数据列表找到订单，查看“业务状态”列或详情页进度步骤条。
2. 状态含义：
   - `0 经办人上报`：订单已提交，等待部长审核；退回草稿也回到 0。
   - `1 部长审核`：当前节点为部长审核。
   - `2 财务核对`：部长通过后进入财务核对。
   - `3 派工出库`：财务核对通过后进入派工。
   - `4 施工中`：派工出库完成，施工员工上门施工。
   - `5 施工完成`：施工员确认完工说明/现场照片，等待完工验收。
   - `6 完工验收`：订单主经办人验收（通过/不通过），末节点。
   - `7 历史归档`：历史已完结的“售后维护”订单归档，不再流转。
   - `-1 作废退款`：作废退款流程完成（见第 6 章）。
3. 点击订单查看当前/下一节点、处理人与流程记录。
4. 有处理权限的员工在“待办任务”中处理，状态随节点动作推进。

### 【字段说明】

| 字段 | 说明 | 示例 |
|---|---|---|
| 业务状态 | 字典 `business_order_status` 中文名 | 财务核对 |
| 当前节点 | 工作流当前节点名称 | 财务核对 |
| 当前审批人 | 当前节点处理人 | 财务：李四 |
| 流程实例 | `wf_instance` 编号 | `12345` |
| 草稿标记 | `draft_flag=1` 表示退回草稿 | 是 |
| 提成状态 | `calc_status`，仅提成维度 | 已计算 |

### 【业务规则与校验】

1. 业务状态由工作流节点 `biz_status` 驱动；节点进入/完成/驳回/终止回调更新，前端不硬编码中文。
2. 节点顺序：0 经办人上报 → 1 部长审核 → 2 财务核对 → 3 派工出库 → 4 施工中 → 5 施工完成 → 6 完工验收 → 完成。
3. 退回：部长/财务可退回发起人（回 0，草稿标记=1）；派工/施工/完工验收可退回上一节点（派工→2，施工→3，完工验收→5）。
4. 作废退款：走独立流程 `biz_order_void_flow`，终审后 `biz_status=-1`（见第 6 章）。
5. 业务状态与提成状态解耦：作废订单保留列表供审计，但排除销售/提成统计。
6. 状态变化不直接改变库存；库存变化在销售出库审核、物料核销通过等环节。
7. 施工中节点处理人优先取派工返回的上门员工（动态指派），“施工员”角色仅兜底；完工验收处理人固定为订单主经办人（`agent_phones` 第一个手机号），不再使用“验收员/售后”角色。

### 【操作结果】

- 订单列表/详情展示最新业务状态与当前处理人；
- 当前处理人待办出现任务；
- 通过后进入下一状态，驳回后回到指定状态；
- 作废退款完成后状态=-1，统计数据排除。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| 0 经办人上报 | 提交订单 | 经办人 | 1 部长审核 | 不变 | 不推送 |
| 1 部长审核 | 部长通过 | 部长 | 2 财务核对 | 不变 | 不推送 |
| 1 部长审核 | 部长退回发起人 | 部长 | 0 经办人上报（草稿） | 不变 | 不推送 |
| 2 财务核对 | 财务通过 | 财务 | 3 派工出库 | 不变 | 不推送（旧品采购单此时自动审核推送） |
| 2 财务核对 | 财务退回发起人 | 财务 | 0 经办人上报（草稿） | 不变 | 不推送 |
| 2 财务核对 | 财务暂缓 | 财务 | 2 财务核对（停留） | 不变 | 不推送 |
| 3 派工出库 | 派工提交 | 派工员 | 4 施工中 | 销售出库草稿生成（未扣库存） | 不推送 |
| 4 施工中 | 施工记录/完工确认 | 上门员工 | 5 施工完成 | 不变（核销通过才扣物料库存） | 核销通过时推送其他出库单（不随状态） |
| 5 施工完成 | 确认完工并提交 | 施工员 | 6 完工验收 | 不变 | 不推送 |
| 6 完工验收 | 验收通过 | 订单主经办人 | 完成 | 出库单审核后扣库存 | 出库单推送 |
| 6 完工验收 | 验收不通过 | 订单主经办人 | 5 施工完成（退回上一节点） | 不变 | 不推送 |
| 7 历史归档 | —（历史订单） | — | 不流转 | 不变 | 不推送 |
| 任意（符合条件） | 作废退款终审 | 总经办 | -1 作废退款 | 按关联单据处理 | 按关联单据处理 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 状态长时间不前进 | 当前处理人未处理/消息未送达 | 到待办查看；联系当前处理人 |
| 状态回退到 0 且草稿标记=1 | 部长/财务退回发起人 | 修改后重新提交，生成新实例 |
| 状态与订单实际进度不一致 | 回调失败/消息丢失 | 联系管理员在异常处理中心重推/手动推进 |
| 状态=-1 但列表仍有订单 | 作废订单保留审计 | 正常；统计已排除 |
| 施工中处理人不是预期施工员 | 派工动态指派上门员工 | 正常；如需施工员固定处理，派工选施工员为上门员工 |

### 【注意事项】

1. 业务状态不是供应链单据审核状态；不要用业务状态判断库存是否已扣。
2. 退回发起人会生成新实例，旧实例保留历史；不要重复提交。
3. 财务暂缓只保存字段、不推进状态；处理人仍在财务核对节点。
4. 作废订单保留列表但排除统计，财务对账时注意筛选。

### 【测试验证要点】

1. 提交后状态 0→1，部长待办出现。
2. 部长通过→2，财务待办出现；退回→0 且草稿标记=1。
3. 财务通过→3；暂缓停留 2。
4. 派工提交→4，动态指派上门员工。
5. 施工完成→5；完工验收→6；验收不通过退回→5。
6. 完工验收通过→完成；历史订单归档为 7，不再流转。
7. 作废退款终审→-1，统计排除。
8. 状态与待办/当前处理人一致。

### 【常见问题】

> **Q：状态显示“财务核对”，但财务说没收到待办？**
> A：检查财务角色是否绑定、范围是否匹配订单归属组织；如配置了运营商财务指定审批人，确认指定人有效。仍无待办时联系管理员查看工作流实例。

> **Q：退回后订单编号会变吗？**
> A：不会。退回草稿保留原订单编号，修改重提后生成新流程实例，编号不变。

> **Q：为什么状态到“施工完成”库存还没扣？**
> A：库存扣减发生在销售出库审核/物料核销通过，不是业务状态本身；请检查关联出库单/领用单状态。

## 5.4 审批流

### 【功能说明】

业务数据订单使用 `biz_order_flow` 工作流，按“部长审核 → 财务核对 → 派工出库 → 施工中 → 施工完成 → 完工验收”推进。部长/财务/派工按企业角色+范围解析处理人；派工出库把上门员工动态指派给施工中节点；施工完成由施工员确认，完工验收由订单主经办人处理（不再使用“验收员/售后”角色）。各节点动作会落业务数据、生成供应链单据、写流程留痕。

### 【适用角色】

- 部长：部长审核节点（订单归属组织）。
- 财务：财务核对节点（订单归属组织；可选运营商财务指定审批人）。
- 派工员：派工出库节点（订单归属组织）。
- 施工员/上门员工：施工中节点（动态指派优先），并在施工完成节点确认完工说明/现场照片。
- 订单主经办人：完工验收节点（按订单 `agent_phones` 第一个手机号动态解析）。
- 经办人：提交、查看进度、退回后修改重提、完工验收。
- 历史角色“验收员/售后”已从标准流程移除，仅用于历史数据/旧配置。
- 【不可见项】城市合伙人没有总经办/运营商财务角色时，相关节点由运营商处理；外部施工员只能处理被指派的施工任务。

### 【操作入口】

- H5 → 待办任务（`pages/employee/flow-todo`）→ 任务卡片 → 任务处理（`pages/employee/flow-task`）。
- PC → 我的待办/工作流任务（平台主站）。
- 公众号模板消息点击 → H5 任务处理页。

### 【前置条件】

1. 工作流 `biz_order_flow` 已发布并启用；
2. 各组织已创建并绑定对应角色（部长、财务、派工员、施工员）；订单主经办人已维护手机号；
3. 订单已提交并生成实例；
4. 处理人已登录且与任务匹配。

### 【操作步骤】

#### 部长审核

1. 部长在待办打开任务，查看订单基础信息、商品、金额、凭证。
2. 填写审核意见（驳回时必填）。
3. 点击“通过”进入财务核对；点击“退回发起人”回 0（草稿），经办人修改后重新提交。

#### 财务核对

1. 财务填写：收据号、财务收款日期、资金动态表横排数、是否收款、核对结论（通过/不通过/暂缓）、核对备注。
2. 通过：进入派工出库；不通过：退回发起人；暂缓：保存字段但停留在财务核对。
3. 财务核对通过后，系统事务提交后触发以旧换新采购单自动审核（如订单含旧品）。

#### 派工出库

1. 派工员选择：工单类型（施工/入户随访）、上门员工、期望上门时间、施工商品（可选）、随访任务说明。
2. 提交后系统调用 SCM 生成销售出库草稿；如填写物料清单，同事务生成物料领用单（状态0，领用人=上门员工）。
3. 施工派工把下一节点“待接受”任务指派给该员工（入户随访直接进入施工中）。
4. 入户随访不出库；施工出库按物料清单生成物料领用单（状态0）。

#### 施工中

1. 上门员工在待办打开任务，填写施工说明/完工说明，上传现场照片（如需要）。
2. 提交后进入施工完成。

#### 施工完成

1. 施工员确认完工说明/现场照片（按节点表单），提交后进入完工验收。
2. 施工完成提醒旧品入库（如含以旧换新）。

#### 完工验收

1. 订单主经办人在待办打开完工验收任务。
2. 填写“验收结论”（通过/不通过，必填）和“验收意见”（必填，最多 500 字）。
3. 上传现场图片或短视频作为验收凭证：至少 1 个；图片最多 9 张，视频最多 1 段且不超过 30 秒。
4. 通过：流程完成；不通过：退回上一节点“施工完成”（业务状态回到 5），施工员重新确认后再验收。
5. 验收通过后，如关联销售出库单已审核，则扣减销售库存；物料领用单核销通过才扣减物料库存；验收本身不直接改库存。

> 历史“售后维护”节点已不再新增；存量已完结订单归档为“历史归档”（状态 7），不重新进入验收。

### 【字段说明】

| 节点 | 关键字段 | 是否必填 | 说明 |
|---|---|---|---|
| 部长审核 | 审核意见 | 驳回时必填 | 通过/退回发起人 |
| 财务核对 | 收据号 | 是 | 与订单凭证核对 |
| 财务核对 | 财务收款日期 | 是 | 收款日期 |
| 财务核对 | 资金动态表横排数 | 否 | 数字 |
| 财务核对 | 是否收款 | 是 | 是/否 |
| 财务核对 | 核对结论 | 是 | 通过/不通过/暂缓 |
| 财务核对 | 核对备注/原因 | 否 | 最多 500 字 |
| 派工出库 | 工单类型 | 是 | 施工/入户随访 |
| 派工出库 | 上门员工 | 是 | 派工对象 |
| 派工出库 | 期望上门时间 | 是 | 日期时间 |
| 派工出库 | 施工商品 | 否 | 选择商品 |
| 派工出库 | 随访任务说明 | 否 | 最多 500 字 |
| 施工中 | 施工说明/完工说明 | 否 | 最多 1000 字 |
| 施工完成 | 完工说明/现场照片 | 否 | 施工员确认；照片可选 |
| 完工验收 | 验收结论 | 是 | 通过/不通过 |
| 完工验收 | 验收意见 | 是 | 最多 500 字 |
| 完工验收 | 图片/视频凭证 | 是 | 至少 1 个；图片≤9 张，视频≤1 段/≤30 秒 |

### 【业务规则与校验】

1. 角色名必须与工作流配置完全一致；改名会导致节点无人接收。
2. 审批范围：部长/财务/派工默认“订单归属组织”；运营商财务可作为指定审批人加入财务节点；完工验收按订单主经办人动态解析（`ORDER_HANDLER`）。
3. 施工中处理人优先取派工返回的 `assigneeUserId`（上门员工），角色“施工员”仅兜底。
4. 驳回：部长/财务退回发起人（回 0，草稿）；派工/施工/完工验收退回上一节点（派工→2，施工→3，完工验收→5）。
5. 财务暂缓只保存字段、不推进状态；不通过退回发起人。
6. 节点动作同步回调失败不推进流程；异步状态回调失败进入异常中心，可重推/手动推进。
7. 派工出库生成销售出库草稿，保存即推进订单执行状态；出库审核才扣库存。
8. 物料清单生成的领用单不扣库存；施工员接受任务自动确认；修改后由部长审批；核销通过才扣物料库存。
9. 驳回意见长度：驳回不少于 5 个字；恢复操作原因不少于 10 个字（如异常中心恢复）。
10. 完工验收不得空提交：验收结论、验收意见、图片/视频凭证缺一不可；附件按任务处理人归属校验。验收通过后流程完成，不通过退回施工完成。
11. “验收员/售后”角色已从标准流程移除；如旧配置仍引用，需按迁移脚本清理，否则节点可能无人接收。

### 【操作结果】

- 每节点通过后业务状态推进，下一处理人待办出现；
- 财务核对通过触发旧品采购单自动审核（如含旧品）；
- 派工生成销售出库草稿/物料领用单（状态0）；
- 施工完成提醒旧品入库；
- 驳回后退回指定状态，经办人可修改重提。

### 【状态流转表】

| 当前节点 | 动作 | 操作角色 | 下一节点/状态 | 关联单据 | 库存变化 |
|---|---|---|---|---|---|
| 部长审核 | 通过 | 部长 | 财务核对 / 2 | 无 | 不变 |
| 部长审核 | 退回发起人 | 部长 | 经办人上报 / 0（草稿） | 无 | 不变 |
| 财务核对 | 通过 | 财务 | 派工出库 / 3 | 旧品采购单自动审核 | 不变 |
| 财务核对 | 不通过 | 财务 | 经办人上报 / 0（草稿） | 无 | 不变 |
| 财务核对 | 暂缓 | 财务 | 财务核对 / 2 | 无 | 不变 |
| 派工出库 | 提交 | 派工员 | 待接受（WAIT_ACCEPT） | 销售出库草稿、物料领用单（状态0） | 不扣 |
| 施工中 | 提交 | 上门员工 | 施工完成 / 5 | 施工记录 | 不变（核销通过另计） |
| 施工完成 | 确认完工 | 施工员 | 完工验收 / 6 | 完工说明/照片 | 不变 |
| 完工验收 | 通过 | 订单主经办人 | 完成 | 验收记录/图片/视频 | 出库审核后扣 |
| 完工验收 | 不通过 | 订单主经办人 | 施工完成 / 5 | 无 | 不变 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 待办无人接收 | 角色名不一致/未绑定/范围不匹配 | 核对工作流节点角色名与组织角色绑定 |
| “当前节点无审批人” | 角色无人/范围为空 | 管理员补充角色人员或指定审批人 |
| 派工提交失败“缺少派工来源业务订单信息” | 订单未关联业务订单 | 联系管理员检查派工参数 |
| 派工提交失败“派工单没有可出库商品” | 商品清单为空/未匹配 | 检查施工商品/物料清单 |
| 财务核对通过但采购单未自动审核 | 默认供应商/仓库失效/回调失败 | 查看采购单自动审核失败原因；运营商重新触发 |
| 施工中任务给错人 | 派工上门员工选错 | 由派工员重新派工/管理员转交任务 |
| 节点动作失败 | 网络/回调异常 | 重试；仍失败联系管理员在异常中心处理 |
| 驳回意见太短 | 少于 5 字 | 补充意见 |

### 【注意事项】

1. 角色名是审批人解析键，不要随意改名；改名需同步工作流配置。
2. 财务暂缓不是驳回，不会退回经办人；订单仍停在财务。
3. 派工出库生成的是销售出库草稿，库存未扣；销售出库审核后才扣销售库存，物料核销通过才扣物料库存。
4. 物料领用单不扣库存；施工员接受任务自动确认；修改后部长审批；核销通过才扣库存。
5. 完工验收不通过会退回施工完成节点（状态 5），施工员重新确认后再验收；不是直接退回施工中。
6. 驳回后修改重提会生成新实例，旧实例保留历史。

### 【测试验证要点】

1. 各节点处理人解析正确（部长/财务/派工员/施工员/订单主经办人）。
2. 运营商财务指定审批人可处理下辖订单（如配置）。
3. 财务通过/不通过/暂缓三种结果状态正确。
4. 财务通过触发旧品采购单自动审核。
5. 派工提交生成销售出库草稿/物料领用单（状态0）；施工任务进入待接受并指派上门员工。
6. 施工完成→完工验收（6）；验收通过完成，不通过退回施工完成（5）。
7. 完工验收必须填验收意见并上传图片/视频，缺项被拒绝。
8. 驳回意见长度校验；异常中心可重推/手动推进。
9. 角色改名后待办无人接收（验证风险点）。

### 【常见问题】

> **Q：为什么部长审核通过后，财务没有收到待办？**
> A：检查财务角色是否绑定、范围是否为订单归属组织；如配置了运营商财务指定审批人，确认指定人有效。

> **Q：财务“暂缓”和“不通过”有什么区别？**
> A：暂缓保存字段但不推进，订单仍在财务核对；不通过退回发起人，订单回 0 草稿。

> **Q：派工后施工中任务为什么给了别人？**
> A：施工中处理人优先取派工选择的上门员工；这是设计行为。若需固定施工员，请派工选施工员为上门员工。

## 5.5 待办事务

### 【功能说明】

待办是工作流为当前节点处理人创建的任务。H5 底部“待办”、工作台“待办任务”卡片、PC“我的待办”看到的是同一批任务。处理人从待办进入任务处理页，完成节点动作后任务消失并流转到下一处理人。

### 【适用角色】

- 所有被工作流解析为节点处理人的员工（部长/财务/派工员/施工员/订单主经办人）。
- 经办人：可在业务数据查看进度，但待办只显示需要自己处理的节点。
- 【不可见项】无处理权限的员工看不到他人待办；外部施工员只看到被指派的施工任务。

### 【操作入口】

- H5 底部导航“待办”（`pages/employee/flow-todo`）。
- H5 工作台“待办任务”卡片（显示待办数量徽标）。
- PC 平台主站 → 我的待办/工作流任务。
- 公众号模板消息点击 → 任务处理页。

### 【前置条件】

1. 已登录 H5/PC，且当前组织与任务归属匹配；
2. 任务为 `PENDING` 状态且处理人是当前用户（或角色匹配）；
3. 任务对应业务单据未被终止/作废。

### 【操作步骤】

1. 打开“待办任务”页，查看待办列表：节点名称、提交时间、业务摘要、发起人。
2. 点击卡片“去处理”，进入任务处理页。
3. 按当前节点表单填写/核对信息（部长意见、财务字段、派工信息、施工/验收记录等）。
4. 点击“通过/提交/退回”等动作。
5. 成功后任务从列表消失，下一处理人待办出现；页面提示下一审批人（如有）。
6. 如需查看历史，到“工作业务日志”或订单详情查看流程记录。

### 【字段说明】

| 字段 | 说明 | 示例 |
|---|---|---|
| 节点名称 | 当前待办节点 | 财务核对 |
| 提交时间 | 任务进入时间 | `2026-11-19 10:00` |
| 业务摘要 | 订单摘要/客户/金额 | `业务订单 09001 张三` |
| 发起人 | 订单发起员工 | 李四 |
| 操作 | 去处理 | — |

### 【业务规则与校验】

1. 待办与工作台卡片共用同一套过滤/排序口径，顺序一致。
2. 派工待办会过滤不满足条件的任务（如订单已出库/不满足派工条件），避免无效处理。
3. 任务处理必须由当前处理人/角色完成；越权/已处理任务会提示。
4. 处理动作成功即流转；失败不推进，可重试。
5. 任务被终止/作废后从待办消失；历史仍可在日志/异常中心查看。
6. 待办数量徽标只统计 PENDING 任务；物料领用角标只统计当前登录人状态0/1领用单。

### 【操作结果】

- 处理成功后待办消失，下一节点待办出现；
- 订单业务状态推进；
- 历史记录可在订单详情/工作业务日志查看；
- 处理失败时任务保留，可重试。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “暂无待办任务” | 没有 PENDING 任务/已完成 | 正常；查看日志或联系管理员 |
| “任务信息不完整，请返回重试” | 任务参数缺失 | 返回列表刷新；仍失败联系管理员 |
| “加载待办失败，请稍后重试” | 网络/接口异常 | 重试；检查登录状态 |
| 点击任务提示无权限 | 不是当前处理人/角色不匹配 | 确认账号/组织；联系管理员转交 |
| 任务已处理但列表仍有 | 缓存/并发 | 下拉刷新；勿重复处理 |
| 处理后状态未变 | 回调失败 | 查看订单详情；联系管理员在异常中心处理 |

### 【注意事项】

1. 待办是“需要我处理”的任务，不是全部订单列表；查看全部请到业务数据。
2. 派工待办可能被过滤（订单已出库等），不是系统丢任务。
3. 处理后不要重复点击；如网络异常，先刷新确认状态。
4. 任务转交/跳过由管理员在异常处理中心操作，普通用户不要自行绕过。

### 【测试验证要点】

1. 各节点待办出现在正确处理人列表。
2. 待办卡片信息、数量徽标正确。
3. 处理成功后待办消失、下一处理人出现。
4. 越权/重复处理被拒绝。
5. 派工待办过滤无效任务。
6. 终止/作废后待办消失，历史可查。
7. 工作台与待办页顺序一致。

### 【常见问题】

> **Q：为什么我看不到某个订单的待办？**
> A：待办只显示当前需要你处理的节点；查看全部订单请到“业务数据”。角色不匹配也不会出现该待办。

> **Q：待办数量和工作台卡片不一致？**
> A：两处共用同一套过滤/排序口径；刷新后应一致。仍不一致时截图联系管理员。

## 5.6 公众号审批消息

### 【功能说明】

工作流在任务创建、通过、驳回、终止、抄送时，通过运营商服务号发送微信模板消息。员工点击消息可跳转 H5 任务处理页；未登录会先登录再回到任务。消息发送失败会落发送日志并进入异常中心，可重新推送。

### 【适用角色】

- 所有关注运营商服务号并完成微信绑定的内部员工：接收待办/结果消息。
- 管理员：配置消息模板、查看发送失败日志、在异常中心重推。
- 【不可见项】未关注公众号/未绑定微信的员工收不到消息；外部施工员如未绑定也收不到。

### 【操作入口】

- 微信 → 服务号会话 → 模板消息卡片 → 点击进入 H5。
- 平台主站 → 工作流 → 消息模板（管理员配置）。
- 平台主站 → 异常处理中心 → 消息发送失败 → 重新推送。

### 【前置条件】

1. 员工已关注运营商服务号；
2. 员工已完成微信绑定（见 1.2）；
3. 管理员已在平台配置对应场景的模板 ID、字段映射与跳转链接；
4. 工作流实例/任务有效，未被终止。

### 【操作步骤】

1. 微信收到服务号模板消息，标题如“业务订单待办通知”。
2. 点击消息卡片，微信打开 H5 任务处理页（链接带 `taskId/instanceId`）。
3. 如未登录，先进入员工登录页；登录成功后回到任务页。
4. 按节点表单处理；通过/驳回后收到结果类消息（如已配置）。
5. 如消息打不开/提示任务不存在，回待办列表刷新或联系管理员。

### 【字段说明】

| 变量 | 含义 | 示例 |
|---|---|---|
| `{businessSummary}` | 业务摘要 | `业务订单 09001 张三` |
| `{businessAddress}` | 客户名称+小区+详细地址（thing 限 20 字，超出截断） | `张三 阳光小区 3-501` |
| `{nodeName}` | 当前节点名称 | 财务核对 |
| `{submitTime}` | 提交时间 | `2026-11-19 10:00` |
| `{initiatorName}` | 发起人 | 李四 |
| `{approverName}` | 接收人 | 王五 |
| `{taskId}` / `{instanceId}` | 任务/实例 ID | `123/456` |
| `{jumpUrl}` | 渲染后的跳转链接 | `https://boss.jdzn99.com/ops/?route=...` |

### 【业务规则与校验】

1. 消息按事件自动发送：任务创建（待办）、通过、驳回、终止、抄送、告警；无需逐节点绑定。
2. 接收人：节点审批人/角色解析出的员工；结果类发给发起人+全部审批人；告警发运营商管理员。
3. 跳转链接：待办 `https://boss.jdzn99.com/ops/?route=pages/employee/flow-task&taskId={taskId}&instanceId={instanceId}`；结果类跳 `flow-todo`。
4. 微信模板字段有长度限制（thing 20 字、phrase 5 字等），超长自动截断；完整信息以 H5 为准。
5. 发送异步；失败落 `wf_message_send_log` 与异常中心，可重新推送。
6. 员工未关注/未绑定不会收到消息，但系统内待办仍存在。
7. 消息点击后若任务已处理/终止，提示任务不存在或已处理，不会重复处理。

### 【操作结果】

- 处理人收到待办消息，点击进入任务；
- 通过/驳回后收到结果消息（如配置）；
- 发送失败可在异常中心重推；
- 系统内待办与消息指向同一任务。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 收不到消息 | 未关注公众号/未绑定微信/模板未配置 | 关注并绑定；联系管理员检查模板 |
| 点击消息提示“任务不存在” | 任务已处理/终止/链接参数缺失 | 回待办列表刷新；联系管理员 |
| 点击消息跳登录后没回任务 | 登录回跳失败 | 重新点击消息；仍失败从待办进入 |
| 消息字段为空/截断 | 变量未传/超长 | 检查模板映射；以 H5 信息为准 |
| 消息重复发送 | 重试/多实例 | 以任务状态为准；重复消息可忽略 |
| 发送失败告警 | 公众号接口异常/接收人未绑定 | 异常中心重推；补绑定 |

### 【注意事项】

1. 收不到消息先检查是否关注服务号并完成微信绑定，不一定是系统故障。
2. 消息只是提醒，最终以 H5 待办/任务状态为准。
3. 模板字段长度有限，地址/摘要会截断，不要依赖消息展示完整信息。
4. 任务已处理/终止后，旧消息点击不会重新打开任务。
5. 管理员修改模板后先发测试消息验证字段映射。

### 【测试验证要点】

1. 任务创建后处理人收到待办消息。
2. 点击消息跳转正确任务页；未登录先登录再回跳。
3. 通过/驳回后收到结果消息（如配置）。
4. 未关注/未绑定员工收不到消息，但系统待办存在。
5. 发送失败在异常中心可重推。
6. 字段超长截断不报错。
7. 任务已处理/终止后点击消息提示合理。

### 【常见问题】

> **Q：为什么同事收到消息我没收到？**
> A：检查是否关注运营商服务号并完成微信绑定；同一节点多人或签时，只有被解析为处理人的员工收到消息。

> **Q：消息里的地址不完整？**
> A：微信 thing 字段限 20 字，超长会截断；完整地址请打开 H5 任务页查看。

> **Q：点击消息提示任务不存在？**
> A：任务可能已被处理/终止，或消息过期；回“待办任务”刷新查看最新任务。
