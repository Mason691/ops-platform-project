# 第六章 业务订单回退与作废

本章解决两类“订单已经提交、但需要撤销/退回”的场景：

1. **业务订单回退（退回草稿）**：订单还在部长/财务审核阶段（业务状态 0/1/2），经办人把订单退回草稿，修改后重新提交；不产生退款。
2. **业务订单作废（作废退款）**：订单需要整体作废并退款，走独立流程 `biz_order_void_flow`（部长 → 财务 → 总经办）；终审后订单状态=-1，提成归零。

两类操作都要求：订单未派工出库、未上报集团、未生成以旧换新采购单、无进行中的退款申请；且只能由**订单经办人**在本组织发起。

## 6.1 业务订单回退（退回草稿）

### 【功能说明】

经办人在订单进入派工出库之前，可以把订单退回草稿：系统终止当前正常审批流程，订单回到“0 经办人上报”并标记草稿；经办人用 5 步制单向导修改内容后重新提交，订单编号保持不变，新提交生成新的审批实例。适用于客户信息填错、商品/金额需调整、审批被驳回后需要大改等场景。

### 【适用角色】

- 订单经办人（`agent_phones` 中的任一手机号，或订单创建人）：可发起退回草稿。
- 同组织其他员工：不可操作（提示“仅订单经办人可执行该操作”）。
- 【不可见项】外部施工员不可操作（提示“外部用户暂不可操作业务订单”）；非本组织员工不可操作。

### 【操作入口】

- H5 → 业务数据（`pages/employee/business-data`）→ 订单详情（`pages/employee/order-detail`）→ “退回草稿”。
- 订单详情仅在 `canReturnDraft=true` 时显示按钮。

### 【前置条件】

1. 当前用户是订单经办人/创建人，且属于订单组织；
2. 订单业务状态为 0/1/2（经办人上报/部长审核/财务核对），未到派工出库及之后；
3. 订单不是草稿（`draft_flag≠1`）；
4. 没有进行中的作废退款申请；
5. 订单未产生销售出库单、未上报集团、未生成以旧换新采购单。

### 【操作步骤】

1. 打开订单详情，确认当前业务状态在 0/1/2。
2. 点击“退回草稿”。
3. 在确认框“退回后订单将回到草稿状态，需重新提交审批”点击确认。
4. 系统终止当前正常流程（待办 SKIPPED、发送终止消息），订单状态回到 0，`draft_flag=1`，清空流程实例/节点字段。
5. 提示“已退回草稿”；订单详情状态显示“草稿 · 待重新提交”。
6. 点击“编辑”进入 5 步制单向导，修改后提交；提交成功后草稿标记清除，重新进入部长审核。

### 【字段说明】

| 字段 | 说明 | 示例 |
|---|---|---|
| 业务状态 | 退回后固定为 0 | 0 经办人上报 |
| 草稿标记 | `draft_flag=1` | 1 |
| 流程实例 | 退回后清空 | 空 |
| 当前节点 | 退回后清空 | 空 |
| 订单编号 | 保持不变 | `09001` |
| 批次 | 保持不变 | `广河-202611` |

### 【业务规则与校验】

1. 仅业务状态 0/1/2 可退回；到 3 派工出库及之后提示“业务状态已到派工出库及之后，不可退回草稿”。
2. 订单已是草稿时提示“订单已是草稿状态，无需重复退回”。
3. 有进行中的作废退款申请时提示“订单正在作废退款审批中，不可退回草稿”。
4. 已产生销售出库单时提示“该订单已产生销售出库单，不可退回草稿或发起退款”。
5. 已上报集团时提示“该订单已上报集团，不可退回草稿或发起退款”。
6. 已生成以旧换新采购单（含 PENDING/SUCCESS）时提示“该订单已生成以旧换新采购单，不可退回草稿或发起退款”。
7. 退回会终止当前正常流程；已产生的待办任务被跳过，审批人收到终止通知（如配置）。
8. 退回不改变订单编号、批次、商品明细；修改后重新提交生成新实例，旧实例保留历史。
9. 退回不产生退款、不改变库存、不改变提成（提成在作废时归零）。

### 【操作结果】

- 订单状态=0，草稿标记=1，流程实例/节点清空；
- 订单详情显示“草稿 · 待重新提交”，出现“编辑”入口；
- 当前审批人的待办消失（SKIPPED）；
- 经办人修改后提交，重新进入部长审核。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| 0/1/2 | 退回草稿 | 经办人 | 0 经办人上报（草稿） | 不变 | 不推送 |
| 0 草稿 | 编辑并重新提交 | 经办人 | 1 部长审核（新实例） | 不变 | 不推送 |
| 3 及之后 | 退回草稿 | 经办人 | 不允许 | — | — |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “业务状态已到派工出库及之后，不可退回草稿” | 状态≥3 | 走作废退款流程或联系管理员 |
| “订单已是草稿状态，无需重复退回” | 已退回 | 直接编辑提交 |
| “订单正在作废退款审批中，不可退回草稿” | 有 PENDING 退款 | 等待退款审批结果 |
| “该订单已产生销售出库单，不可退回草稿或发起退款” | 已派工出库 | 由派工/供应链侧处理，不能退草稿 |
| “该订单已上报集团，不可退回草稿或发起退款” | 已上报 | 联系财务/管理员 |
| “该订单已生成以旧换新采购单，不可退回草稿或发起退款” | 含旧品且采购单已生成 | 由供应链侧关闭/作废采购单后再评估 |
| “仅订单经办人可执行该操作” | 非经办人 | 由经办人操作 |
| “外部用户暂不可操作业务订单” | 外部施工员 | 仅内部员工可操作 |
| 退回后编辑提交失败 | 网络/校验 | 按提示修正；草稿仍在，可重试 |

### 【注意事项】

1. 退回草稿会终止当前审批，已处理的节点记录保留在历史实例，但当前流程不再继续。
2. 退回后订单编号不变；重新提交生成新实例，不要重复提交。
3. 已出库/已上报/已生成以旧换新采购单的订单不能退回，需走对应业务处理。
4. 退回不是作废：不退款、不提成归零；作废请走 6.2。
5. 退回后修改商品/金额可能影响提成与统计，提交前核对。

### 【测试验证要点】

1. 状态 0/1/2 可退回；3 及之后被拒绝。
2. 重复退回被拒绝。
3. 有 PENDING 退款时退回被拒绝。
4. 已出库/已上报/已生成采购单时退回被拒绝。
5. 退回后 state=0、draft_flag=1、wf 字段清空。
6. 待办消失，终止消息（如配置）发送。
7. 编辑重新提交后进入部长审核，订单编号不变，新实例生成。
8. 非经办人/外部用户被拒绝。

### 【常见问题】

> **Q：退回草稿和作废退款有什么区别？**
> A：退回草稿只是撤回审批、修改后重新提交，不退款；作废退款是整体作废并退款，走部长→财务→总经办，终审后状态=-1、提成归零。

> **Q：退回后订单编号会变吗？**
> A：不会。订单编号和批次保留，重新提交只生成新的审批实例。

> **Q：为什么我没有“退回草稿”按钮？**
> A：只有订单经办人、状态 0/1/2、且未出库/未上报/未生成采购单/无 PENDING 退款时才显示；不满足条件时按钮隐藏或接口拒绝。

## 6.2 业务订单作废（作废退款）

### 【功能说明】

订单需要整体作废并退款时，经办人发起“作废退款”申请：系统终止正常审批流程，启动独立作废流程 `biz_order_void_flow`（部长审核 → 财务审核 → 总经办审核）。终审通过后订单业务状态=-1（作废退款），明细计算状态=已作废、提成归零并锁定；退款记录保留。适用于客户取消、订单录错无法修改、业务终止等场景。

### 【适用角色】

- 经办人：发起作废退款、查看退款进度、驳回后重新提交。
- 部长：作废流程一级审核；驳回退回经办人。
- 财务：作废流程二级审核；驳回退回经办人。
- 总经办：作废流程终审；驳回退回上一节点（财务）。
- 【不可见项】非经办人不能发起；外部施工员不可操作；非本组织员工不可操作。

### 【操作入口】

- H5 → 业务数据 → 订单详情 → “发起退款申请”。
- 退款申请弹窗（`BusinessRefundSheet`）；订单详情“作废退款”卡片展示最新退款记录。
- 待办任务 → 作废退款节点任务。

### 【前置条件】

1. 当前用户是订单经办人/创建人，且属于订单组织；
2. 订单业务状态 0/1/2，未到派工出库及之后；
3. 无进行中的作废退款申请（PENDING）；
4. 订单未产生销售出库单、未上报集团、未生成以旧换新采购单；
5. 订单应付合计 >0（退款金额基数）。

### 【操作步骤】

#### 发起作废退款

1. 打开订单详情，点击“发起退款申请”。
2. 在弹窗中填写“退款金额”：默认订单应付合计，可下调，但不得超过应付合计。
3. 填写“退款原因”（必填，最多 500 字）。
4. 如退款金额低于应付合计，必须在“备注”中说明调整理由（最多 500 字）。
5. 可上传“补充附件”（JPG/PNG/PDF，最多 5 份，单个≤10MB）。
6. 点击“提交退款申请”。
7. 系统创建退款记录（状态 PENDING），终止正常流程，启动作废流程；提示提交成功，显示下一审批人（部长）。

> 【截图 6-3：H5 发起退款申请弹窗】
>
> 图注：退款金额（默认应付合计，不得超过）、退款原因（必填）、备注（下调金额时必填）、补充附件（最多5份）、提交退款申请。此处需补充实际界面截图。

#### 部长审核

1. 部长在待办打开作废退款任务，查看订单、退款金额、原因、附件。
2. 填写意见，点击“通过”进入财务；点击“驳回”退回经办人。
3. 驳回后订单恢复原业务状态，流程字段清空，退款记录状态=已驳回。

#### 财务审核

1. 财务核对退款金额/原因/附件，填写意见。
2. 通过进入总经办；驳回退回经办人。

#### 总经办终审

1. 总经办审核后点击“通过”：订单业务状态=-1，明细计算状态=已作废，提成归零并锁定，退款记录状态=已通过。
2. 驳回退回上一节点（财务）重新处理。

#### 驳回后的处理

1. 退款被驳回/终止后，订单恢复原业务状态（`original_biz_status`），流程字段清空。
2. 订单详情显示“重新提交审批”按钮（`canRestartFlow=true`）：可重新发起正常审批。
3. 如仍需作废，可再次“发起退款申请”（`canApplyRefund=true`）。
4. 作废审批期间经办人不可编辑、不可退回草稿、不可重复发起退款。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 退款金额 | 必填 | >0 且不超过订单应付合计；默认应付合计 | `2499.00` |
| 退款原因 | 必填 | 最多 500 字 | 客户取消订单 |
| 备注 | 下调金额时必填 | 最多 500 字，说明调整理由 | 已使用部分商品，扣除 500 |
| 补充附件 | 选填 | 最多 5 份，JPG/PNG/PDF，≤10MB/份 | `客户取消说明.pdf` |
| 退款单号 | 系统生成 | `RF{orderId}-{时间戳}` | `RF123-...` |
| 退款状态 | 系统带出 | 待审批/已通过/已驳回/已终止 | 待审批 |
| 当前节点 | 系统带出 | 部长审核/财务审核/总经办审核 | 财务审核 |
| 原业务状态 | 系统记录 | 发起时订单业务状态 | 2 财务核对 |

### 【业务规则与校验】

1. 仅业务状态 0/1/2 可发起；到派工出库及之后提示“业务状态已到派工出库及之后，不可发起退款申请”。
2. 已有 PENDING 退款时提示“该订单已有进行中的作废退款申请，请勿重复发起”。
3. 已产生销售出库单/已上报集团/已生成以旧换新采购单时拒绝（提示见 6.1）。
4. 退款金额 >0 且不超过应付合计；金额为空默认应付合计；下调金额必须备注理由。
5. 退款原因必填，最多 500 字；备注最多 500 字；附件最多 5 个。
6. 发起时先创建退款记录，再终止正常流程、启动作废流程；作废流程启动失败会补偿性重启正常流程，避免订单停在无流程状态。
7. 作废流程：部长审核 → 财务审核 → 总经办审核；部长/财务驳回退回经办人，总经办驳回退回财务。
8. 终审通过：`biz_status=-1`、`calc_status=已作废`、`total_commission=0`、明细提成=0；退款记录=已通过。
9. 驳回/终止：订单恢复原业务状态，清空流程字段；退款记录=已驳回/已终止。
10. 作废审批期间不可编辑/退草稿/重复退款；驳回后可重新提交正常审批或重新发起退款。

### 【操作结果】

- 发起后订单显示“作废审批中”，正常流程停止，部长待办出现；
- 逐级审批通过后订单状态=-1、提成归零、退款记录已通过；
- 驳回后订单恢复原状态，可重新提交或重新发起退款；
- 作废订单保留列表供审计，但排除销售/提成统计。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| 0/1/2 | 发起退款申请 | 经办人 | 作废审批中（部长审核） | 不变 | 不推送 |
| 作废审批中 | 部长通过 | 部长 | 财务审核 | 不变 | 不推送 |
| 作废审批中 | 财务通过 | 财务 | 总经办审核 | 不变 | 不推送 |
| 作废审批中 | 总经办通过 | 总经办 | -1 作废退款 | 按关联单据（本流程不直接改库存） | 按关联单据 |

| “仅订单经办人可执行该操作” | 非经办人 | 由经办人操作 |
| “外部用户暂不可操作业务订单” | 外部施工员 | 仅内部员工 |
| 作废流程启动失败 | 工作流/回调异常 | 系统会补偿重启正常流程；联系管理员排查 |
| 部长/财务驳回后订单状态没恢复 | 回调异常 | 查看订单详情；联系管理员在异常中心处理 |

### 【注意事项】

1. 作废不是删除：订单保留列表与历史，统计排除；退款记录保留。
2. 作废审批期间不能编辑/退回草稿/重复发起退款；驳回后才可操作。
3. 下调退款金额必须备注理由，避免无依据少退。
4. 总经办驳回是退回财务，不是退回经办人；财务需重新处理。
5. 作废不直接改变库存；如已产生关联供应链单据，应先按对应流程处理（退草稿/作废前置校验会拦截）。
6. 作废后提成归零并锁定，财务/提成统计已排除，不要重复计算。

### 【测试验证要点】

1. 经办人状态 0/1/2 可发起；3 及之后被拒绝。
2. 退款金额默认应付合计，不得超过；下调必须备注。
3. 退款原因必填；附件最多 5 个。
4. 发起后正常流程终止、作废流程启动、部长待办出现。
5. 部长→财务→总经办逐级通过，终审后状态=-1、提成归零。
6. 部长/财务驳回退回经办人；总经办驳回退回财务。
7. 驳回后订单恢复原状态，可重新提交审批/重新发起退款。
8. PENDING 期间不可编辑/退草稿/重复退款。
9. 已出库/已上报/已生成采购单时拒绝。
10. 作废订单排除统计，退款记录保留。

### 【常见问题】

> **Q：作废退款和退回草稿能同时用吗？**
> A：不能。作废审批期间不可退回草稿；退回草稿也不产生退款。两者互斥。

> **Q：退款金额可以少于应付合计吗？**
> A：可以，但必须在备注中说明调整理由；金额不能超过应付合计。

> **Q：总经办驳回后为什么回到财务，不是退回经办人？**
> A：作废流程配置总经办驳回退回上一节点（财务）；财务重新核对后可再次提交总经办。

> **Q：作废后订单还能查到吗？**
> A：能。订单保留在列表供审计，状态=-1，统计（销售/提成/汇总）排除。

> **Q：已经派工出库的订单能作废吗？**
> A：不能直接作废。系统会拦截“已产生销售出库单”；需先按派工/出库/验收流程处理。
