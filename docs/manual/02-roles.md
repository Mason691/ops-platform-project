# 第二章 权限与角色

平台采用“组织 + 企业角色 + 菜单/按钮权限”的模型。组织决定数据边界，角色决定在组织内能做什么，菜单/按钮权限决定能看到哪些入口。理解这三层关系，才能解释“为什么同一个页面，不同人看到的按钮不一样”。

## 2.1 角色定义

### 【功能说明】

角色是组织内的岗位集合，绑定到员工后授予对应的菜单、按钮和审批人资格。平台的标准角色包括运营商管理员、财务、总经办、部长、库管、派工员、施工员、业务员等。角色名称同时被工作流节点用作审批人解析依据，因此**角色名称必须与工作流配置完全一致**，改名会导致待办无人接收。

### 【适用角色】

- 运营商管理员：维护本组织角色与用户；
- 城市合伙人管理员/负责人：维护本组织员工角色；
- 财务、总经办、部长、库管、派工员、施工员、业务员：被授予对应角色；
- 超管：查看平台级配置，不代替组织分配业务角色。

【不可见项】普通员工看不到“角色管理”“用户管理”菜单；城市合伙人看不到运营商本级的财务、总经办角色（标准配置）。

### 【操作入口】

- 平台主站 → 系统管理 → 角色管理（`/role`）；
- 平台主站 → 系统管理 → 用户管理（`/user`）→ 选择用户 → “绑定角色”；
- 平台主站 → 系统管理 → 菜单管理（`/menu`）→ 给角色授权菜单/按钮；
- 工作流配置 → 节点审批人：按企业角色名 + 范围解析。

### 【前置条件】

1. 当前账号是组织管理员（`sys_user_corp.is_admin=1`）或拥有角色管理权限；
2. 目标组织状态为启用；
3. 角色名称已与工作流节点配置对齐（部长、库管、财务、总经办、派工员、施工员等）；
4. 给员工分配角色前，员工已加入该组织并有有效任职。

### 【操作步骤】

#### 查看与新建角色

1. 登录平台主站，进入“系统管理 → 角色管理”。
2. 页面按当前组织展示角色列表；运营商管理员默认看到本级角色，城市合伙人管理员看到本组织角色。
3. 点击“新增角色”。
4. 填写角色名称（如“部长”“财务”“派工员”），填写描述，选择状态。
5. 保存后，在角色列表点击“菜单权限”，勾选该角色可访问的菜单和按钮。
6. 保存授权。

| 库管 | 运营商 / 城市合伙人 | 打印物料领用单（首次打印即发放）、审核物料核销 | 待办、物料领用、物料核销 | 订单归属组织 |
| 派工员 | 运营商 / 城市合伙人 | 业务订单派工出库：指定上门员工、时间、施工商品、物料清单与领用仓库 | 待办、业务订单流程处理 | 订单归属组织 |
| 施工员 | 运营商 / 城市合伙人；可授外部用户 | 施工中记录、施工完成确认；接受派工任务、修改领用明细、发起核销 | 待办、任务处理、物料领用、物料核销 | 被指派的订单 / 本组织 |
| 业务员 | 城市合伙人（基础角色，自动授予） | 制单、查看本人业务数据、发起物料领用/核销、发起作废退款 | 员工工作台、业务数据、新增业务 | 本组织 + 本人经办 |
| 普通员工 | 运营商 / 城市合伙人 | 按被授予的具体角色执行；无角色时仅能使用基础工作台 | 工作台、待办 | 本组织 |
| 外部施工员 | 城市合伙人 / 运营商（外部用户） | 被派工后处理施工任务、修改本人领用明细、发起核销；不能进入 PC 管理菜单 | H5 待办、任务处理、物料领用/核销 | 仅被指派的订单 / 本人领用单 |

**关于“总经办、财务仅运营商拥有”**：标准种子脚本只在运营商组织（生产为 `corp_id=4`）创建“财务”“总经办”角色，工作流节点的审批范围分别为“订单归属组织”和“运营商及全部下级”。城市合伙人组织默认只有“业务员”基础角色，以及按需创建的“部长”“派工员”“施工员”。因此在本手册的标准配置下，**财务、总经办是运营商岗位，城市合伙人不可见、不可审批**。如果某城市合伙人组织自行创建了同名“财务”角色，节点范围又配置为“订单归属组织”，则该角色可能被解析为审批人；这属于配置变更，需要业务与管理员确认，不能默认开启。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 角色名称 | 必填 | 同一组织内唯一；建议与工作流节点配置完全一致 | 部长 |
| 描述 | 选填 | 说明岗位职责，便于审计 | 城市合伙人部长：业务订单审核 |
| 状态 | 必填 | 启用/停用；停用后不再解析为新审批人 | 启用 |
| 菜单权限 | 选填 | 勾选菜单与按钮；未勾选的入口不显示 | 待办、业务数据 |
| 数据范围 | 由组织与节点决定 | 组织级隔离由后端 `corp_id` 保证，不通过角色配置扩大 | 本组织 |

### 【业务规则与校验】

1. 角色按组织隔离：运营商的“部长”和城市合伙人的“部长”是两条独立记录，不能跨组织授权。
2. 角色名称禁止使用“管理员/超级管理员/Admin”等保留字；企业管理员由 `sys_user_corp.is_admin=1` 标识，不依赖同名角色。
3. 城市合伙人组织会自动创建“业务员”基础角色，新员工默认拥有；移除该角色前必须保证员工仍有可用的工作台权限。
4. 工作流节点审批人按“企业角色名 + 范围”实时解析：部长/财务/库管按订单归属组织，总经办按运营商及全部下级，派工员按订单归属组织，施工员优先动态指派、无动态指派时按角色兜底。
5. 施工员角色允许外部用户（`allow_external=1`）；外部施工员由派工员在现场新增，系统自动绑定施工员角色。
6. 2026-11-18 起“验收员”“售后”角色已从标准流程移除：施工完成由施工员确认，完工验收由订单主经办人处理；历史配置如仍引用旧角色，需按迁移脚本清理。
7. 角色停用或改名会让工作流节点解析不到审批人，任务会落异常中心并告警；改名前必须先改工作流节点配置或同步新建角色。

### 【操作结果】

- 角色列表新增/更新一条记录；
- 绑定该角色的员工在重新登录或切换组织后看到对应菜单与按钮；
- 工作流节点能按角色名解析出审批人；
- 角色停用后，新任务不再分配给该角色员工，历史任务保留。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 工作流节点提示“未解析到审批人” | 角色名称不一致、角色停用、组织内无该角色员工 | 核对角色名称与节点配置；给员工绑定角色；检查员工状态 |
| 员工看不到待办 | 未绑定对应角色，或角色没有待办菜单权限 | 绑定角色并授权“我的待办”菜单；重新登录 |
| 城市合伙人看不到财务/总经办菜单 | 标准配置下这两个角色仅运营商拥有 | 属于权限设计；如需下级财务审批，需业务确认后单独配置 |
| 角色改名后旧待办无人处理 | 工作流按角色名实时解析，旧名称不再匹配 | 改名前同步修改节点审批人配置；或新建同名角色并迁移员工 |
| 无法删除角色 | 角色仍被员工或菜单引用 | 先解除员工绑定、清理菜单授权，再停用/删除 |
| 外部施工员无法被授予施工员角色 | 施工员角色未设置 `allow_external=1` | 执行施工员角色初始化脚本，或由管理员调整角色属性 |

### 【注意事项】

1. 角色名称是工作流的“接口”，不是普通显示文案；改名影响审批流，必须走变更评审。
2. 不要给城市合伙人随意创建“财务”“总经办”同名角色，除非同步调整节点范围和内控要求。
3. 一个员工可以有多个角色，权限取并集；审批人解析按节点配置的角色，不看员工的其他角色。
4. 企业管理员身份由 `is_admin` 决定，不要通过创建“管理员”角色来提权。
5. 角色变更后，员工需要重新登录或切换组织刷新令牌，权限才立即生效。

### 【测试验证要点】

1. 运营商与城市合伙人各自创建同名角色，互不影响。
2. 绑定部长角色的员工能看到部长审核待办；移除角色后待办不再分配给他。
3. 财务/总经办角色在标准配置下只出现在运营商组织；城市合伙人组织列表不显示。
4. 角色改名后，工作流节点解析失败并落异常中心；恢复名称后新任务正常。
5. 施工员角色可授予外部用户；外部用户只能看到被指派的 H5 任务。
6. 多角色员工权限取并集，菜单与按钮符合预期。
7. 角色停用后不能作为新任务审批人，历史任务仍可查。
8. 城市合伙人“业务员”基础角色不能被随意移除到无工作台权限。

### 【常见问题】

> **Q：为什么城市合伙人没有“财务”“总经办”角色？**
> A：标准配置下这两个角色只在运营商组织创建，分别负责财务核对、采购核审、作废终审等运营商级职责。城市合伙人默认使用“业务员 + 部长 + 库管 + 派工员 + 施工员”的组合（库管按组织创建，用于物料领用打印与核销审批）；如业务确需下级财务审批，需要单独评估并调整工作流节点范围。

> **Q：角色改名后为什么待办没人处理？**
> A：工作流节点按角色名称实时解析审批人。改名后旧名称匹配不到员工，任务会进入异常中心。请在改名同时修改节点审批人配置，或新建角色并迁移员工。

> **Q：一个人可以有多个角色吗？**
> A：可以。菜单和按钮权限取并集；审批人解析只看节点配置的角色。比如“业务员 + 部长”既能制单，也能审批本组织的部长节点。

## 2.2 用户指定角色

### 【功能说明】

管理员在用户管理中给员工分配组织角色。角色按“组织任职关系”绑定，不是按自然人全局绑定；同一员工在不同组织可以有不同角色。角色变更后，员工重新登录或切换组织即可获得新权限。

### 【适用角色】

- 运营商管理员、企业管理员：维护本组织及下辖组织用户；
- 城市合伙人管理员：维护本组织用户；
- 超管：可查看用户，但不代替组织分配业务角色。

【不可见项】普通员工看不到用户管理菜单；城市合伙人管理员不能修改运营商本级或其他城市合伙人的用户角色。

### 【操作入口】

平台主站 → 系统管理 → 用户管理 → 找到用户 → “绑定角色”。

### 【前置条件】

1. 当前账号是组织管理员或有用户管理权限；
2. 目标用户已加入当前组织（存在 `sys_user_corp` 任职记录），状态正常；
3. 目标角色属于当前组织，且角色状态为启用；
4. 角色名称与工作流节点配置一致（如部长、财务、派工员、施工员）。

### 【操作步骤】

1. 登录平台主站，进入“系统管理 → 用户管理”。
2. 使用手机号/姓名搜索目标用户；列表只显示当前组织及权限范围内的用户。
3. 确认用户的“所属组织”和“当前状态”正确。
4. 点击用户行操作列的“绑定角色”。
5. 在弹窗中勾选一个或多个角色；角色下拉只列出当前组织的角色。
6. 点击“保存”。
7. 提示“角色已更新”后，通知员工重新登录或切换组织，使新权限生效。
8. 如需移除角色，取消勾选后保存；移除“业务员”基础角色前，系统会校验员工是否仍有工作台权限。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 用户 | 必填 | 通过手机号/姓名搜索选择；必须在当前组织有任职 | 张三 / 13812345678 |
| 所属组织 | 系统带出 | 当前任职组织；角色只影响该组织 | 康乐公司 |
| 角色 | 必填（可多选） | 只能选择当前组织的启用角色 | 业务员、部长 |
| 当前状态 | 系统带出 | 在职/离职/停用；停用用户不能分配新任务 | 在职 |

### 【业务规则与校验】

1. 角色按 `sys_user_corp.id`（用户组织任职）绑定；同一员工在不同组织可以有不同的角色集合。
2. 用户列表强制按当前组织等值过滤，不含下级组织；运营商查看下辖用户需切换到对应组织，或使用平台提供的跨组织用户视图（如已开通）。
3. 跨组织新增存量用户时，姓名/昵称只读；角色、停用、移除按当前组织的任职关系操作。
4. 移除任职只把 `sys_user_corp.status` 置 0，不删除 `sys_user`；该员工在其他组织的任职不受影响。
5. 城市合伙人新员工自动获得“业务员”基础角色；可以再叠加部长、派工员、施工员等角色。
6. 角色变更不影响历史审批记录；已创建的任务仍按创建时的审批人处理，新任务按新角色解析。
7. 角色变更后 JWT 中的权限不会即时刷新；员工重新登录或切换组织后生效。

### 【操作结果】

- 用户列表该用户的角色列更新；
- 员工重新登录/切换组织后看到新增或减少的菜单、按钮；
- 工作流新任务按新角色解析审批人；
- 移除角色后，该员工不再收到对应节点的待办。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 角色下拉为空 | 当前组织没有角色，或用户不属于当前组织 | 先在角色管理创建角色；确认用户任职组织 |
| “只影响「组织」的任职角色” | 提示文案，不是错误 | 确认当前组织正确后保存 |
| 保存后菜单没变化 | 权限写在令牌中，未刷新 | 让员工重新登录或切换组织 |
| 无法移除业务员角色 | 移除后员工将没有工作台权限 | 先授予其他可用的工作台角色，再移除 |
| 用户列表看不到目标员工 | 员工不在当前组织，或已被停用/移除 | 切换到正确组织；确认任职状态 |
| 角色变更后待办没有转给新角色 | 历史任务审批人已固定 | 新任务生效；历史任务需管理员在待办/工作流处理 |

### 【注意事项】

1. 角色是“组织内岗位”，不是“平台全局身份”；同一人在 A 组织是部长，在 B 组织可以是业务员。
2. 不要给员工叠加互相冲突的审批角色来“方便审批”；审批人按节点角色解析，多角色不会自动扩大节点范围。
3. 角色变更属于权限变更，建议保留操作日志并通知员工；涉及财务、总经办的角色变更应经过审批。
4. 离职/停用员工先移除任职，再停用账号；不要直接删除用户，以免历史单据失去关联。
5. 外部施工员的角色由派工现场新增流程自动绑定，不建议手工在用户管理里创建外部用户。

### 【测试验证要点】

1. 管理员给员工绑定部长角色，员工重新登录后能看到部长待办。
2. 同一员工在两个组织分别绑定不同角色，切换组织后权限不同。
3. 移除角色后，员工重新登录不再看到对应菜单/待办。
4. 城市合伙人管理员看不到运营商本级用户，也不能修改其角色。
5. 移除“业务员”基础角色时，系统校验工作台权限。
6. 角色变更不影响历史审批记录，新任务按新角色解析。
7. 外部施工员不能被手工分配内部管理角色。
8. 操作日志记录角色变更人、时间、变更前后角色。

### 【常见问题】

> **Q：给员工加了角色，为什么他那里没变化？**
> A：权限写在登录令牌中。请让员工退出重新登录，或在 H5/PC 切换一次组织刷新令牌；仍不生效时检查角色菜单授权。

> **Q：可以给城市合伙人员工分配“财务”角色吗？**
> A：标准配置下不建议。财务角色只在运营商组织创建，工作流财务节点按订单归属组织解析；如果城市合伙人组织自建同名财务角色，可能改变审批人，需要业务与管理员确认后实施。

> **Q：员工离职后角色怎么处理？**
> A：先移除该员工在当前组织的任职（`sys_user_corp.status=0`），再停用账号；不要删除用户。历史单据、审批记录仍保留，审计可追溯。
