# 第四章 供应链管理

本章覆盖采购、销售、退货、盘点、库存六条业务链。所有页面在**平台主站**：`https://boss.jdzn99.com` 登录后，左侧“供应链管理”菜单进入。供应链单据的通用规则先说明：

1. **数据边界**：单据归属组织（来源组织）= 当前组织时才可编辑、审核、删除；运营商可查看下辖城市合伙人单据，但只能查看/核审，不能代下级修改。
2. **双状态分离**：审批状态（`approval_status`）与审核状态（`audit_status`）分离；审批未通过前绝不推送金蝶。
3. **推送失败不回滚**：本地审核与库存变更先落库，金蝶推送失败只置“推送失败”，可在列表重试。
4. **库存以批次为最小粒度**：批次管理商品的库存按 `(仓库, 商品, 批次)` 追踪；审核/反审核都写独立库存流水，不修改原流水。
5. **以旧换新是特殊来源**：由业务订单自动生成，不走人工审批，由业务订单“财务核对”触发自动审核；详见 4.1.4。

## 4.1 采购订单

### 【功能说明】

采购订单用于向供应商采购商品。支持三种手工来源（直接采购、业务数据、商城订单）和一种系统来源（业务订单以旧换新自动生成）。订单经审批（城市合伙人）或直接审核（运营商自建）后推送金蝶，并可按剩余数量生成采购入库。采购订单本身不改变库存，库存变化发生在采购入库审核时。

### 【适用角色】

- 运营商：可查看本级 + 下辖全部采购订单；可新建直接采购/业务数据/商城订单、审核本级订单、关闭订单、生成入库、重试推送；可核审下辖城市合伙人提交的订单。
- 城市合伙人：只能查看/操作本组织采购订单；新建后需“提交审批”，由运营商总经办核审通过后才能审核推送；不能核审下辖（无下辖）。
- 【不可见项】城市合伙人看不到其他城市合伙人的采购订单；无 `scm:pur-order:review` 权限看不到“核审”按钮；无 `scm:pur-order:export` 权限看不到“汇总导出”。

### 【操作入口】

- 平台主站 → 供应链管理 → 采购订单（`/subsystem/scm/purchase`）。
- 公众号 H5 → 员工工作台 → 已核对业务 → “发起采购申请”（生成 `BUSINESS_DATA` 草稿，供应商/仓库/单价留空，由 PC 完善）。
- 以旧换新自动采购单由业务订单提交时自动生成，不在 PC 手工新建。

### 【前置条件】

1. 供应商、商品、仓库已从金蝶同步；商品已同步金蝶（有金蝶 ID）；
2. 新建订单必须有供应商、收货仓库、商品、数量、含税单价；
3. 业务数据来源：来源业务订单必须已完成**财务核对**（`biz_status=2`），且未派工出库；
4. 商城订单来源：商城订单必须已付款；
5. 以旧换新自动生成：运营商已设置默认供应商，业务订单归属组织已设置默认仓库，旧品全部在商品库且已同步金蝶。

### 【操作步骤】

#### 新建采购订单（直接采购）

1. 进入“供应链管理 → 采购订单”，点击“新建采购订单”。
2. 选择“单据日期”（默认当天）。
3. “数据来源”选择“直接采购”。
4. “供应商”下拉选择已同步供应商；支持输入名称/编码搜索。
5. “收货仓库”下拉选择仓库；系统优先预填当前组织默认仓库。
6. 在“分录”区点击“+ 添加分录”，选择商品；系统带出名称、品牌、规格型号、单位。
7. 填写“数量”（大于 0，最多 4 位小数）和“含税单价”（≥0，最多 4 位小数）。
8. 核对“本次应付账款”（所有行数量×单价之和）。
9. 点击“保存”生成草稿；如需连续录入，点击“保存并新增”。

#### 新建采购订单（业务数据来源）

1. 数据来源选择“业务数据”。
2. 点击“选择业务数据（仅财务核对）”。
3. 在查询弹窗中按收据号/订单编号/客户/手机号查询；列表只显示已财务核对的业务订单。
4. 勾选一个或多个订单/收据，点击确认；系统按商品合并数量，带出来源信息。
5. 选择供应商、收货仓库；逐行填写含税单价（业务数据只带数量，不带采购价）。
6. 保存草稿。

#### 新建采购订单（商城订单来源）

1. 数据来源选择“商城订单”。
2. 点击“选择商城订单（仅已付款）”。
3. 选择已付款商城订单，系统带出商品与数量。
4. 选择供应商、收货仓库，填写含税单价。
5. 保存草稿。

#### 提交审批（城市合伙人）

1. 草稿在本人组织列表中找到，点击“提交审批”。
2. 系统展示下一审批人（总经办）姓名/角色；确认后提交。
3. 审批状态变为“审批中”，当前节点/审批人显示在列表。
4. 审批通过后审批状态变为“已通过”，审核状态仍为草稿；此时才可“审核”。

>
> 图注：提示“您将把单据提交给 总经办：XXX 审批，确认提交？”，确认提交/取消。此处需补充实际界面截图。

#### 核审（运营商总经办）

1. 总经办在“待办”或采购订单列表找到“审批中”订单。
2. 点击“核审”，查看订单详情、供应商、金额、分录。
3. 填写审批意见（驳回时不少于 5 个字）。
4. 点击“通过”或“驳回”。
5. 通过后审批状态=已通过，订单回到归属组织；驳回后审批状态=已驳回，归属组织修改后可重新提交。

#### 审核并推送金蝶

1. 运营商自建订单（审批状态=无需审批）或城市合伙人订单（审批状态=已通过）且审核状态=草稿时，点击“审核”。
2. 系统先本地置为已审核，再推送金蝶（保存即审核）。
3. 提示“审核完成（金蝶推送 save → audit）”，金蝶推送状态变为“已同步金蝶”，金蝶单号回填。
4. 推送失败时提示失败原因，单据保持已审核、推送状态=推送失败；点击“重试推送”重试，不回滚已审核。

#### 生成入库

1. 已审核且执行状态不是“全部下推”的订单，点击“生成入库”。
2. 系统跳转采购入库页面并带入来源订单、供应商、仓库和剩余可入库分录。
3. 录入本次入库数量（不得超过剩余可入库数量），保存入库草稿。
4. 入库单审核后，订单入库状态按审核数量推进（详见 4.2）。

#### 关闭订单

1. 仅“已审核”订单可关闭；点击“关闭”，确认。
2. 审核状态变为“已关闭”；不改变库存、不推送金蝶关闭。
3. 已关闭订单不能再生成入库、不能再修改。

#### 删除草稿

1. 仅本组织、草稿、非审批中的订单可删除。
2. 点击“删除”，确认；如已有入库草稿，需先删除入库草稿。
3. 以旧换新自动单不允许删除，应关闭或作废来源业务订单。

#### 以旧换新自动采购单（系统生成）

1. 员工在 H5 提交含以旧换新的业务订单后，系统自动生成采购订单草稿（数据来源=业务订单以旧换新，来源类型=系统自动）。
2. 生成时自动带出**默认供应商（运营商级）**和**业务订单归属组织的默认仓库（组织级）**；未配置/停用/未同步时**生成失败**，H5 订单详情显示失败原因。
3. 采购订单列表显示“系统自动”标签，审批状态=无需审批，审核状态=草稿，自动审核列=待财务核对。
4. 业务订单进入“财务核对”并提交后，系统自动二次校验默认供应商/仓库/商品 → 审核并推送金蝶。成功后自动审核列=已审核。
5. 二次校验失败时，自动审核列=失败，详情显示“自动审核失败原因”，采购单保持草稿；运营商修复默认配置后点击“重新触发审核”。
6. 以旧换新自动单**不允许手动提交审批、不允许手动审核、不允许删除**；可在草稿状态编辑供应商/仓库/单价（旧品分录不可增删/替换），修复后由运营商重新触发。

### 【业务规则与校验】

1. **供应商、收货仓库、采购单价在任何来源下必填**；业务数据/商城订单只带商品与数量，不带采购价。
2. 业务数据来源必须已完成财务核对，且未派工出库；商城订单必须已付款；前端无法绕过，后端二次校验。
3. 城市合伙人订单必须先提交审批，审批通过（APPROVED）才能审核推送；运营商自建订单默认无需审批（`approval_status=NONE`），可直接审核，除非配置开启运营商审批。
4. 审核前校验单据完整性：供应商、收货仓库、单价、分录不能为空；历史以旧换新草稿还必须把“其他旧品”映射到真实商品。
5. 审核时先本地置为已审核，再推送金蝶；推送失败不回滚审核状态，置“推送失败”，可重试。
6. 生成入库的前置：订单审批通过（或运营商自建/以旧换新自动单）、订单已审核、执行状态不是全部下推；入库数量不得超过剩余可入库数量。
7. 订单保存入库草稿即推进执行状态（未入库/部分入库/全部入库）；订单入库状态按入库单**审核**数量推进。
8. 关闭仅对已审核订单生效；关闭不改变库存、不推送金蝶关闭；关闭后不能生成入库。
9. 删除仅对草稿、非审批中、非以旧换新自动单生效；有入库草稿时先删除入库草稿。
10. 以旧换新自动单：生成时取默认供应商/默认仓库，落草稿不推送；财务核对触发二次校验后自动审核并推送；**禁止手动提交审批/审核**；不允许删除；只能关闭。
11. 推送前会用原子方式抢占“推送中”，避免自动推送与人工重试并发用同一单号重复建金蝶单。

### 【操作结果】

- 保存后生成草稿，列表出现新单号；
- 提交审批后审批状态=审批中，待办出现在总经办；
- 核审通过后审批状态=已通过，可审核；驳回后可修改重提；
- 审核后审核状态=已审核，金蝶推送成功=已同步金蝶，失败=推送失败；
- 生成入库后订单执行状态按保存数量推进；入库审核后入库状态按审核数量推进；
- 关闭后审核状态=已关闭，不再参与入库；
- 以旧换新自动单财务核对后自动变已审核并推送，无需人工操作。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| （无） | 新建/保存 | 运营商/城市合伙人 | 草稿 / 无需审批 | 不变 | 不推送 |
| 草稿 / 无需审批 | 提交审批 | 城市合伙人 | 审批中 | 不变 | 不推送 |
| 审批中 | 总经办通过 | 运营商总经办 | 已通过 / 草稿 | 不变 | 不推送 |
| 审批中 | 总经办驳回 | 运营商总经办 | 已驳回 / 草稿 | 不变 | 不推送 |
| 已通过 / 草稿 | 审核 | 归属组织 | 已审核 | 不变 | 推送（save→audit） |
| 草稿 / 无需审批 | 审核 | 运营商 | 已审核 | 不变 | 推送（save→audit） |
| 草稿（以旧换新自动单） | 业务订单财务核对且二次校验通过 | 系统 | 已审核 | 不变 | 推送（save→audit） |
| 草稿（以旧换新自动单） | 财务核对但二次校验失败 | 系统 | 草稿（记录失败原因） | 不变 | 不推送 |
| 已审核 | 生成入库并保存 | 归属组织 | 已审核 / 未入库→部分→全部 | 不变（占用剩余数量） | 不推送 |
| 已审核 | 入库单审核 | 归属组织 | 已审核 / 入库状态推进 | 库存增加（入库单） | 入库单推送 |
| 已审核 | 关闭 | 归属组织 | 已关闭 | 不变 | 不推送 |
| 草稿 | 删除 | 归属组织 | 已删除 | 不变 | 不推送 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “审批未通过，不能审核或推送金蝶（当前审批状态：…）” | 城市合伙人订单未提交/未通过审批 | 先提交审批，等待总经办通过；驳回后修改重提 |
| “以旧换新采购订单由业务订单财务核对后自动审核，不支持手动提交审批” | 对自动单点了提交审批 | 正常拦截；等待财务核对或由运营商重新触发 |
| “以旧换新采购订单由业务订单财务核对后自动审核，不支持手动审核” | 对自动单点了审核 | 正常拦截；修复默认配置后重新触发审核 |
| “采购申请未完善：请先选择供应商 / 请先选择收货仓库 / 请先填写采购单价” | 业务数据/H5 采购申请草稿未完善（三条独立提示） | 编辑草稿补齐供应商、仓库、单价后再提交/审核 |
| “其他旧品未完善：请先在编辑页选择入库商品” | 以旧换新旧品含手工商品 | 编辑草稿，为手工旧品选择真实入库商品 |
| “当前运营商未设置默认供应商，无法自动生成采购订单” | 运营商未设默认供应商 | 运营商在供应商管理设置默认供应商后重试 |
| “当前组织未设置默认仓库，无法自动生成采购订单” | 业务订单归属组织未设默认仓库 | 该组织在仓库信息设置默认仓库后重试 |
| “默认供应商已变更/默认仓库已变更，请重新生成或完善采购单” | 财务核对前默认值被改 | 编辑草稿使供应商/仓库与新默认一致，或重新生成；运营商可重新触发 |
| “采购订单未审核，不可创建采购入库” | 订单还是草稿 | 先审核订单并推送金蝶 |
| “采购订单审批未通过，不能生成入库（当前审批状态：…）” | 审批未通过 | 先完成审批 |
| “来源采购订单尚未成功推送金蝶，请先推送订单” | 订单推送失败/未推送 | 在采购订单列表“重试推送”，成功后再审核入库 |
| “入库数量超出剩余可入库数量：XXX” | 本次入库数量超过订单剩余 | 减小数量或先处理已存在的入库草稿 |
| “仅已审核订单可关闭” | 草稿/关闭单点关闭 | 仅已审核可关闭 |
| 推送失败“金蝶保存响应未返回单据 ID” | 金蝶接口异常/参数缺失 | 检查推送失败原因；补齐供应商/单价/仓库后重试；仍失败联系管理员 |

### 【注意事项】

1. 城市合伙人不要试图绕过审批直接审核；后端会校验审批状态并拒绝。
2. 以旧换新自动单的供应商/仓库来自默认配置，**不要手工把自动单改成其他供应商/仓库**后再触发；二次校验会按默认值比对。
3. 采购订单审核后才推送金蝶；入库单推送前还要求来源订单已成功推送金蝶（`sync_status=AUDITED` 且有金蝶 ID），这是硬顺序。
4. 关闭订单不等于作废：库存、入库单、金蝶单据都不变；如需作废请走业务订单作废/退款流程（见第 6 章）。
5. 删除草稿前先确认没有入库草稿；有入库草稿时先删除入库草稿，否则会提示占用。
6. 业务数据来源的订单必须财务核对且未派工出库；商城订单必须已付款，不要用未付款订单制单。

### 【测试验证要点】

1. 直接采购草稿保存后，列表显示草稿、无需审批、未推送。
2. 城市合伙人提交审批后，总经办待办出现；通过后审批状态=已通过，驳回后=已驳回。
3. 未审批通过的城市合伙人订单审核被拒绝；运营商自建订单可直接审核。
4. 审核后金蝶推送成功，金蝶单号回填；模拟推送失败后状态=推送失败，重试不影响已审核状态。
5. 业务数据来源只能选财务核对订单；未核对订单不可选/后端拒绝。
6. 商城订单来源只能选已付款订单。
7. 以旧换新自动单生成时带默认供应商/仓库；未配置时生成失败并提示明确。
8. 财务核对触发自动审核：成功后已审核+推送；二次校验失败保持草稿并记录原因；重复触发幂等。
9. 自动单不能手动提交审批/审核/删除；可编辑草稿后重新触发。
10. 生成入库数量不超过剩余；保存推进执行状态，审核推进入库状态。
11. 关闭仅已审核可操作；关闭后不能生成入库。
12. 推送失败重试、并发抢占不重复建金蝶单。

### 【常见问题】

> **Q：为什么我的采购订单没有“审核”按钮？**
> A：城市合伙人订单需先提交审批，审批状态=已通过后才显示“审核”；运营商自建订单（无需审批）可直接审核；以旧换新自动单不显示“审核”，由财务核对触发。

> **Q：以旧换新采购单显示“待财务核对”，需要我做什么？**
> A：不需要人工操作。业务订单进入财务核对并提交后，系统会自动审核并推送金蝶；若显示“失败”，查看自动审核失败原因，修复默认供应商/默认仓库后由运营商点“重新触发审核”。

> **Q：采购订单审核了但金蝶推送失败，库存会变吗？**
> A：采购订单本身不改变库存；推送失败不回滚审核状态，订单保持已审核、推送失败，可重试。库存变化发生在采购入库审核时。

## 4.2 采购入库

### 【功能说明】

采购入库用于把采购订单的商品收入仓库，或在不关联订单的情况下自由入库。入库单保存后只占用订单剩余数量、推进执行状态；**审核后才增加库存**并推送金蝶。审核后可反审核：本地回草稿并插入负向库存冲销记录，同时同步金蝶反审核。

### 【适用角色】

- 运营商：可查看本级 + 下辖入库单；可对本级单据新增、编辑、审核、反审核、删除草稿、打印；对下辖单据只读。
- 城市合伙人：只能操作本组织入库单；来源订单必须是本组织且已审核。
- 【不可见项】非归属组织看不到编辑/审核/反审核/删除按钮；运营商看下辖单据只有详情/打印。

### 【操作入口】

- 平台主站 → 供应链管理 → 采购入库（`/subsystem/scm/pur-inbound`）。
- 采购订单列表 → 已审核订单 → “生成入库”（自动带入来源订单）。

### 【前置条件】

1. 来源订单（如从订单下推）：归属本组织、审批通过（或运营商自建/以旧换新自动单）、已审核、未全部下推；
2. 供应商、仓库、商品已同步；商品批次/保质期属性完整；
3. 非赠品分录含税单价 >0；赠品单价必须为 0；
4. 来源订单已成功推送金蝶（`sync_status=AUDITED` 且有金蝶 ID），否则入库审核推送会被拒绝。

### 【操作步骤】

#### 从采购订单生成入库

1. 在采购订单列表找到已审核、未全部下推的订单，点击“生成入库”。
2. 系统打开采购入库弹窗，“来源订单”已带入且不可更改。
3. 供应商、收货仓库自动带出；表体锁定为订单剩余可入库分录。
4. 逐行填写本次入库数量（1 ~ 剩余可入库数量，整数）。
5. 批次管理商品填写“生产日期”，系统按 `PC + yyyyMMdd` 生成批次号，按保质期计算到期日；非批次商品不显示批次。
6. 赠品行打开“是否赠品”，单价自动置 0。
7. 点击“保存”生成入库草稿。

>
> 图注：来源订单下拉已锁定；供应商、收货仓库；表体商品、数量（max=剩余）、含税单价、赠品、批次号、生产日期、到期日；底部本次应付账款。此处需补充实际界面截图。

#### 自由入库（不关联订单）

1. 在采购入库列表点击“新增入库”。
2. “来源订单”留空（不选）。
3. 选择供应商、收货仓库；系统优先预填本组织默认仓库。
4. 点击“+ 添加分录”，选择商品，填写数量、含税单价。
5. 批次管理商品填写生产日期；保质期管理商品必须填写生产日期。
6. 赠品行打开“是否赠品”，单价置 0。
7. 点击“保存”生成入库草稿。

#### 编辑/删除草稿

1. 草稿行点击“编辑”，可修改供应商、仓库、日期、数量、单价、批次/生产日期、赠品标记。
2. 从订单下推的草稿，表体仍锁定来源分录，数量不得超过剩余可入库数量。
3. 草稿行点击“删除”，确认后删除；从订单下推的单据会释放订单占用数量（`pushed_qty`），并重算执行状态。

#### 审核并推金蝶

1. 草稿行点击“审核并推金蝶”。
2. 系统校验：分录非空、非赠品单价>0、赠品单价=0、来源订单已成功推送金蝶。
3. 本地状态置为已审核，写入库存增加流水，推进订单入库状态，再推送金蝶（保存即审核）。
4. 成功提示“审核成功：库存已更新并推送金蝶”；金蝶推送状态=已同步金蝶。
5. 推送失败时本地已审核、库存已增加，推送状态=推送失败；点击“重试推送”重试，不回滚库存。

>
> 图注：审核按钮、审核成功提示“库存已更新并推送金蝶”，以及列表中已审核/推送状态标签。此处需补充实际界面截图。

#### 反审核并同步金蝶

1. 已审核且金蝶推送状态=已同步金蝶的入库单，点击“反审核并同步金蝶”。
2. 确认提示“将撤销审核、写入负向库存冲销记录，并同步金蝶反审核（金蝶库存自动扣减）”。
3. 确认后本地状态回草稿，插入负向库存流水；金蝶侧调用反审核。
4. 成功提示“已反审核：本地已回未审核并写入负向冲销记录，金蝶已同步反审核”。
5. 金蝶反审核失败时，本地仍已反审核；错误记录在金蝶反审核状态，需排查后重新对齐（可再次审核并推送以重新同步）。

#### 打印

1. 勾选多张入库单，点击“批量打印”（按 241×280mm 一等分模板）。
2. 或在单行/详情点击“打印”。
3. 打印内容包含单据编号、供应商、仓库、商品、数量、单价、批次、生产日期/到期日。

#### 拉取金蝶数据

1. 点击“拉取金蝶数据”，从金蝶同步入库单状态/数据；用于金蝶侧发生变更时的对齐。
2. 同步结果以列表刷新为准；本地未审核草稿不会被覆盖为已审核。

| 字段 | 是否必填 | 填写规则 | 示例 |

| 收货仓库 | 必填 | 本组织仓库；默认预填本组织默认仓库 | `CK00011 美家本部仓` |

| 本次应付账款 | 系统计算 | 所有非赠品行合计金额之和 | `19990.00` |

### 【业务规则与校验】

1. **保存不扣/不加库存**：保存只推进订单 `pushed_qty` 与执行状态（未入库/部分入库/全部入库）；审核才写库存增加流水。
2. 从订单下推：必须携带来源分录 ID；数量 ≤ `订单数量 - 已下推数量`；保存/删除/修改草稿都会重算订单占用。
3. 批次管理商品：批次号自动生成 `PC+yyyyMMdd`（同组织冲突追加 `-NNN`）；保质期管理商品必须填写生产日期；到期日按商品保质期计算，也可人工填写；生产日期不得晚于今天，到期日必须晚于生产日期。
4. 非批次商品：批次号为空，不进入批次唯一键，同商品可重复入库。
5. 赠品：单价必须为 0，不计入应付账款；非赠品单价必须 >0，否则审核推送被拒绝。
6. 审核顺序：先校验来源订单已成功推送金蝶，再本地审核+写库存，再推送入库单；推送失败不回滚本地库存与审核。
7. 反审核：本地回草稿并写入负向库存流水（`is_reversal=1`，独立记录，不修改原流水）；金蝶反审核失败不回滚本地反审核。
8. 反审核不校验库存下限（允许冲销后账面为负，便于纠错）；金蝶侧库存不足会拦截并透传提示，平台不自动开启负库存。
9. 已审核入库单不能直接修改/删除；需先反审核。
10. 删除草稿会释放订单占用并重算执行状态；已审核入库单不能删除。

### 【操作结果】

- 保存后生成草稿，订单执行状态推进（部分/全部入库）；
- 审核后库存增加，订单入库状态推进（部分/全部），金蝶推送；
- 反审核后本地回草稿、库存负向冲销、金蝶反审核；
- 推送失败时本地状态不变（已审核/库存已增加），可重试；
- 打印输出入库单。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| （无） | 保存入库草稿 | 归属组织 | 草稿 | 不变（推进订单占用） | 不推送 |
| 草稿 | 修改/删除 | 归属组织 | 草稿/已删除 | 不变（重算占用） | 不推送 |
| 草稿 | 审核并推金蝶 | 归属组织 | 已审核 | 增加（写 INBOUND 流水） | 推送（save→audit） |
| 已审核 | 重试推送 | 归属组织 | 已审核 | 不变 | 重试推送 |
| 已审核 | 反审核并同步金蝶 | 归属组织 | 草稿 | 减少（写 UNAUDIT_REVERSAL 负向流水） | 反审核同步 |
| 已审核 | 打印 | 归属组织/运营商只读 | 已审核 | 不变 | 不推送 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “采购订单未审核，不可创建采购入库” | 来源订单还是草稿 | 先审核采购订单并推送成功 |
| “采购订单审批未通过，不能生成入库（当前审批状态：…）” | 来源订单审批未通过 | 完成审批后再生成入库 |
| “采购订单已全部下推入库” | 订单执行状态=全部下推 | 不能继续生成；核对是否重复下推 |
| “入库数量超出剩余可入库数量：XXX” | 数量超过剩余 | 减小数量；检查是否有其他入库草稿占用 |
| “保质期管理商品必须填写生产日期：XXX” | 商品保质期管理=是但未填生产日期 | 填写生产日期（不得晚于今天） |
| “生产日期不允许晚于当前日期” | 生产日期选未来 | 改为今天或更早 |
| “到期日必须晚于生产日期” | 到期日早于/等于生产日期 | 修正到期日或检查保质期设置 |
| “赠品含税单价必须为 0：XXX” | 赠品行填了价格 | 赠品单价改为 0；或取消赠品标记 |
| “分录缺少含税单价，无法推送金蝶：XXX” | 非赠品单价为空/0 | 补填单价 |
| “来源采购订单尚未成功推送金蝶，请先推送订单” | 来源订单推送失败/未推送 | 在采购订单列表重试推送，成功后再审核入库 |
| 审核成功但提示“推送失败” | 金蝶接口异常/参数缺失 | 查看推送失败原因；点击“重试推送”；库存已增加，不要重复审核 |
| 反审核提示“金蝶反审核失败（可重试）” | 金蝶侧库存不足/接口异常 | 本地已冲销；排查金蝶库存/接口后重新审核并推送对齐 |
| 反审核按钮不显示 | 未审核或金蝶未同步成功 | 仅“已审核 + 推送状态=已同步金蝶”可反审核 |
| 删除按钮不显示 | 非草稿或非本组织 | 仅本组织草稿可删除；已审核需先反审核 |

### 【注意事项】

1. 保存入库单不等于入库；只有“审核并推金蝶”才增加库存。
2. 审核前确认来源采购订单已成功推送金蝶；否则入库推送会被拒绝。
3. 反审核写的是独立负向流水，不是删除原流水；库存查询会看到正负两条记录，这是正常审计痕迹。
4. 反审核可能使库存为负；请先确认货物未被领用/出库，避免金蝶侧库存不足。
5. 批次号与生产日期影响库存批次和近效期；打印前核对批次、到期日。
6. 赠品不计入应付账款，但仍会增加库存；赠品单价必须为 0。

### 【测试验证要点】

1. 从订单生成入库带出剩余分录，数量超过剩余被拦截。
2. 保存草稿推进订单执行状态（部分/全部），但不增加库存。
3. 删除草稿释放订单占用并重算状态。
4. 批次商品自动生成批次号，保质期商品必须填生产日期，到期日计算正确。
5. 非批次商品批次为空，同商品可重复入库。
6. 赠品单价强制 0，不计入应付；非赠品单价 0 审核被拒绝。
7. 审核后库存增加、订单入库状态推进、金蝶推送成功。
8. 模拟金蝶推送失败：本地已审核/库存已增加，状态=推送失败，重试成功。
9. 反审核后本地回草稿、负向库存流水、金蝶反审核；金蝶失败不回滚本地。
10. 已审核单不能编辑/删除；反审核后才能。
11. 打印内容包含批次/生产日期/到期日。
12. 运营商看下辖入库单只读，不能审核/反审核。

### 【常见问题】

> **Q：入库单保存了，为什么库存没变？**
> A：保存只占用订单数量、推进执行状态；必须点击“审核并推金蝶”才增加库存。

> **Q：批次号可以手工改吗？**
> A：系统按 `PC+生产日期` 自动生成，冲突追加 `-NNN`；当前页面批次号只读。如需指定批次，请在备注中说明并联系管理员确认。

> **Q：审核成功但金蝶推送失败，需要重新审核吗？**
> A：不需要。本地已审核、库存已增加；点击“重试推送”即可，重复审核不会重复增加库存。

> **Q：反审核后库存为什么出现负数记录？**
> A：反审核写的是独立负向冲销流水，原入库流水保留，用于审计追溯；两条记录相加即为当前库存。

> **Q：入库单已审核发现数量错了怎么办？**
> A：先“反审核并同步金蝶”回草稿，再修改数量重新审核；不要直接删除已审核单。

## 4.3 销售订单

### 【功能说明】

销售订单用于向客户销售商品，是销售出库的来源之一。销售订单审核后推送金蝶，并按剩余数量生成销售出库。销售订单本身不改变库存；库存变化发生在销售出库审核时。销售订单没有审批流，归属组织审核即推送金蝶。

### 【适用角色】

- 运营商：可查看本级 + 下辖销售订单；可新建、审核、重试推送、生成出库、删除本级草稿；对下辖订单只读。
- 城市合伙人：只能操作本组织销售订单；可新建、审核、重试推送、生成出库、删除草稿。
- 【不可见项】非归属组织看不到编辑/审核/删除/生成出库按钮；“从金蝶同步”仅运营商可用（城市合伙人调用会被拒绝）。

### 【操作入口】

- 平台主站 → 供应链管理 → 销售订单（`/subsystem/scm/sale-order`）。

### 【前置条件】

1. 客户已同步（客户管理中存在且已同步金蝶）；
2. 发货仓库已同步且归属本组织/可见；
3. 商品已同步；数量、单价已填写；
4. 生成销售出库：销售订单已审核、执行状态不是“全部下推出库”。

### 【操作步骤】

#### 新建销售订单

1. 进入“供应链管理 → 销售订单”，点击“新增订单”。
2. 选择“单据日期”（默认当天）。
3. “客户”下拉选择已同步客户；支持搜索。
4. “发货仓库”下拉选择仓库。
5. 点击“+ 添加分录”，选择商品，填写数量（>0）和单价（≥0）。
6. 核对每行小计与金额合计。
7. 点击“保存”生成草稿；或“保存并新增”连续录入。

> 【截图 4-11：销售订单新增弹窗，展示客户、发货仓库、分录】
>
> 图注：单据编号（保存后生成）、单据日期、客户下拉、发货仓库下拉；分录列商品编码、商品名称、品牌、规格型号、单位、数量、单价、小计、删除；底部金额合计。此处需补充实际界面截图。

#### 编辑/删除草稿

1. 草稿行点击“编辑”，可修改客户、发货仓库、日期、分录。
2. 已有出库单时不能修改/删除（先删除出库草稿）。
3. 草稿行点击“删除”，确认后删除。

#### 审核并推送金蝶

1. 草稿行点击“审核并推金蝶”。
2. 系统校验分录非空，本地置为已审核，推送金蝶（保存即审核）。
3. 成功提示“已审核并推送金蝶”，同步状态=已同步金蝶。
4. 推送失败时本地已审核，状态=推送失败；点击“重试推送”重试，不回滚审核。

#### 生成销售出库

1. 已审核且执行状态不是“全部下推出库”的订单，点击“生成销售出库”。
2. 系统打开销售出库弹窗，数据来源=销售订单，订单已带入。
3. 表体带出订单剩余可出库分录；同商品不同批次可拆多行。
4. 保存出库草稿后，订单执行状态按保存数量推进（部分/全部下推）；出库审核后出库状态按审核数量推进。

#### 从金蝶同步（运营商）

1. 点击“从金蝶同步”，系统增量拉取金蝶销售订单，按单号/金蝶 ID 匹配本地单据，补回金蝶 ID/金蝶单号。
2. 同步不覆盖本地审核状态；本地已审核单据仍保持已审核。
3. 城市合伙人点击同步会被拒绝（仅运营商可执行）。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 单据编号 | 系统生成 | 保存时后端生成 `XS` 前缀 | `XS-20261119-001` |
| 单据日期 | 必填 | 默认当天 | `2026-11-19` |
| 客户 | 必填 | 已同步客户；不存在提示先同步 | `KH-WY-001 武威商贸` |
| 发货仓库 | 必填 | 本组织可见仓库 | `CK00011 美家本部仓` |
| 商品 | 必填 | 已同步商品 | `SP00012` |
| 数量 | 必填 | >0，最多 4 位小数 | `2` |
| 单价 | 必填 | ≥0，最多 4 位小数 | `2999.00` |
| 小计 | 系统计算 | 数量 × 单价 | `5998.00` |
| 金额合计 | 系统计算 | 所有行小计之和 | `5998.00` |
| 审核状态 | 系统带出 | 草稿/已审核/已关闭 | 已审核 |
| 执行状态 | 系统带出 | 未出库/部分出库/全部出库（出库单保存即推进） | 部分出库 |
| 出库状态 | 系统带出 | 未出库/部分出库/全部出库（出库单审核才推进） | 部分出库 |
| 金蝶推送 | 系统带出 | 待推送/已推送/已同步金蝶/推送失败 | 已同步金蝶 |

### 【业务规则与校验】

1. 客户必须已同步；提示“客户不存在或未同步，请先同步客户”。
2. 分录不能为空，数量必须大于 0；单价不能为负。
3. 销售订单没有审批流，归属组织审核即推送金蝶。
4. 审核时先本地置为已审核，再推送金蝶；推送失败不回滚审核。
5. 生成销售出库前置：订单已审核、执行状态不是全部出库；出库数量不能超过订单剩余。
6. 销售出库保存即推进订单执行状态；出库审核才推进出库状态。
7. 草稿可编辑/删除；已有出库单时拒绝（先删除出库草稿）；已审核需先反审核出库才能改。
8. 从金蝶同步仅运营商可执行；同步只补金蝶标识，不覆盖本地审核状态。
9. 销售订单本身不改变库存；库存变化在销售出库审核时。

### 【操作结果】

- 保存后生成草稿，列表出现单号；
- 审核后状态=已审核，金蝶推送成功=已同步金蝶；
- 生成出库后执行状态按保存数量推进，出库审核后出库状态按审核数量推进；
- 推送失败可重试，不影响单据已审核状态。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| （无） | 新建/保存 | 归属组织 | 草稿 | 不变 | 不推送 |
| 草稿 | 审核 | 归属组织 | 已审核 | 不变 | 推送（save→audit） |
| 已审核 | 重试推送 | 归属组织 | 已审核 | 不变 | 重试推送 |
| 已审核 | 生成出库并保存 | 归属组织 | 已审核 / 执行状态推进 | 不变（占用订单数量） | 不推送 |
| 已审核 | 出库单审核 | 归属组织 | 已审核 / 出库状态推进 | 库存减少（出库单） | 出库单推送 |
| 草稿 | 删除 | 归属组织 | 已删除 | 不变 | 不推送 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “客户不存在或未同步，请先同步客户” | 客户未同步/编码不存在 | 到客户管理同步或新建客户 |
| “分录不能为空” | 未添加商品行 | 添加至少一行分录 |
| “分录数量必须大于 0：XXX” | 数量为 0/负数 | 修改数量 |
| “销售订单未审核，不可创建销售出库” | 订单还是草稿 | 先审核订单并推送成功 |
| “销售订单已全部下推出库” | 订单执行状态=全部 | 不能继续下推；核对是否重复 |
| “出库数量超过剩余可出库量（X）：XXX” | 出库数量超过订单剩余 | 减小数量或拆分批次/先处理草稿 |
| “该出库单已推送金蝶，不能直接修改” | 出库已推送 | 先反审核出库再修改 |
| 城市合伙人点“从金蝶同步”被拒绝 | 同步仅运营商 | 由运营商执行同步 |
| 审核成功但推送失败 | 金蝶接口/参数异常 | 查看推送失败原因；点击“重试推送” |

### 【注意事项】

1. 销售订单没有审批流，归属组织审核即推送；不要与采购订单的审批流程混淆。
2. 销售订单审核不等于出库；生成出库并审核后库存才减少。
3. 订单外新增出库行不占用订单执行量；订单行出库数量不能超过剩余。
4. 已有出库草稿时不能修改/删除销售订单；先处理出库草稿。
5. 城市合伙人不能执行“从金蝶同步”，避免跨组织数据混入。

### 【测试验证要点】

1. 新建销售订单要求客户、仓库、商品、数量、单价完整。
2. 客户未同步时保存被拒绝。
3. 审核后金蝶推送成功，金蝶单号回填；失败可重试。
4. 生成出库带出剩余分录，保存推进执行状态，审核推进出库状态。
5. 已有出库草稿时修改/删除订单被拒绝。
6. 城市合伙人执行同步被拒绝，运营商可同步。
7. 销售订单本身不改变库存。

### 【常见问题】

> **Q：销售订单为什么没有“提交审批”？**
> A：销售订单当前不配置审批流，归属组织审核即推送金蝶；采购订单才有城市合伙人审批。

> **Q：销售订单审核了，库存怎么没变？**
> A：销售订单不改变库存；需要生成销售出库并审核，库存才减少。

## 4.4 销售出库

### 【功能说明】

销售出库用于把商品发给客户，是库存实际减少的环节。支持业务数据、销售订单、商城订单三种手工来源，以及 ops 派工自动生成的派工来源。审核时逐行校验 `(仓库, 商品, 批次)` 可用库存，不足整单拒绝；审核后扣减库存并推送金蝶，反审核写独立正数冲销流水恢复库存。

### 【适用角色】

- 运营商：可查看本级 + 下辖出库单；可新建业务数据/销售订单/商城订单出库、审核、反审核、删除草稿、打印；对下辖单据只读。
- 城市合伙人：只能操作本组织出库单；可使用三种手工来源；派工来源由派工流程生成。
- 【不可见项】非归属组织看不到编辑/审核/反审核/删除；派工来源不显示编辑/删除（由派工单侧处理）。

### 【操作入口】

- 平台主站 → 供应链管理 → 销售出库（`/subsystem/scm/sale-outbound`）。
- 销售订单列表 → 已审核订单 → “生成销售出库”。
- 公众号员工工作台 → 派工出库 → 系统自动生成派工来源销售出库草稿。

### 【前置条件】

1. 客户已同步；出库仓库已同步且可见；商品已同步；
2. 业务数据来源：业务数据属于当前组织，商品可匹配到商品库；
3. 销售订单来源：订单已审核、未全部下推出库；
4. 商城订单来源：商城订单已付款；
5. 批次管理商品必须选择批次；非批次商品批次必须为空；
6. 审核前逐行可用库存必须足够。

### 【操作步骤】

#### 新建业务数据来源出库（默认）

1. 进入“供应链管理 → 销售出库”，点击“新增出库”。
2. 数据来源选择“业务数据”。
3. 点击“查询业务数据（手机号/名称/收据号）”，在弹窗中按手机号/客户名称/收据号查询。
4. 勾选一条或多条业务数据，点击确认；系统按商品合并数量并带出来源收据。
5. 选择“金蝶客户”（表头结算/开票客户）和“出库仓库”；收货地址可修改。
6. 表体核对商品、批次、即时库存、数量、单价；批次商品必须选择批次。
7. 核对“本次应收金额”。
8. 点击“保存”生成草稿；或“保存并新增”。

1. 数据来源选择“销售订单”。
2. 选择“销售订单”（只列出已审核且未全部下推的订单）。
3. 系统带出客户、发货仓库、订单剩余可出库分录。
4. 可对同商品不同批次拆多行；订单外新增行不占用订单执行量。
5. 填写数量、单价、批次；保存草稿。

1. 数据来源选择“商城订单”。
2. 点击“选择商城订单”，选择已付款商城订单。
3. 系统带出商品、数量、来源客户、收货地址；金蝶客户按商城订单派生并锁定。
4. 填写批次/数量/单价；保存草稿。

#### 编辑/删除草稿

1. 草稿行点击“编辑”，可修改客户、仓库、地址、分录；数据来源锁定，不可切换。
2. 销售订单来源的草稿，订单行数量不能超过剩余；删除草稿会释放订单占用。
3. 派工来源草稿不可编辑/删除，需由派工单侧处理。
4. 已推送金蝶的草稿不能直接修改/删除。

#### 审核并推金蝶

1. 草稿行点击“审核并推金蝶”。
2. 系统逐行校验 `(仓库, 商品, 批次)` 可用库存；任一行不足整单拒绝，提示具体商品/批次/可用量。
3. 校验通过后本地置为已审核，逐行写负向库存流水（扣减），再推送金蝶（保存即审核）。
4. 成功提示“已审核并推送金蝶”，同步状态=已同步金蝶。
5. 推送失败时提示“本地已审核并扣减库存，但金蝶推送失败：…，可稍后重试推送”；库存不回滚。

#### 反审核并同步金蝶

1. 已审核且同步状态=已同步金蝶的草稿，点击“反审核并同步金蝶”。
2. 确认后本地回草稿，逐行写独立正数冲销流水（恢复库存），同步金蝶反审核。
3. 成功提示“已反审核，库存已冲销恢复”。
4. 金蝶反审核失败时提示“本地已反审核并冲销库存，但金蝶反审核失败，请稍后重试同步”；本地库存已恢复。

#### 重试推送

1. 已审核但同步状态不是“已同步金蝶”的单据，点击“重试推送”。
2. 系统按原单号重推金蝶；不重复扣减库存。

#### 打印

1. 勾选多张出库单点击“批量打印”，或单行/详情点击“打印”。
2. 按 A4 210×297mm 一等分模板输出，包含客户、来源、批次、数量、单价、金额、收货地址。

| 字段 | 是否必填 | 填写规则 | 示例 |

| 数据来源 | 必填 | 业务数据/销售订单/商城订单；派工来源系统生成 | 业务数据 |

| 金蝶客户 | 必填 | 本次结算/开票客户；销售订单来源锁定为订单客户 | `KH-WY-001` |
| 来源客户 | 系统带出 | 业务数据/商城订单的来源客户，仅追溯 | `张三 / 138...` |
| 出库仓库 | 必填 | 本组织可见仓库；默认预填本组织默认仓库 | `CK00011` |
| 收货地址 | 选填 | 业务数据/商城订单可自动带出，可修改 | `XX小区 1-101` |

| 单价 | 必填 | ≥0 | `2999.00` |
| 小计 | 系统计算 | 数量 × 单价 | `5998.00` |
| 本次应收金额 | 系统计算 | 所有行小计之和 | `5998.00` |
| 审核状态 | 系统带出 | 草稿/已审核 | 已审核 |
| 金蝶推送 | 系统带出 | 待推送/已推送/已同步金蝶/推送失败 | 已同步金蝶 |

### 【业务规则与校验】

1. 三种手工来源：业务数据、销售订单、商城订单；派工来源由 ops 派工自动生成，手工界面不可选。
2. 业务数据/商城订单只用于带出商品明细；表头“金蝶客户”是本次结算客户，可与来源客户不同。
3. 业务数据查询按手机号/名称/收据号，结果按订单聚合，上限 500 行；只读，不修改业务数据。
4. 商城订单仅已付款可出库；来源客户/收货地址由服务器从商城订单派生。
5. 销售订单来源：订单必须已审核、未全部下推；订单行数量 ≤ 剩余可出库量；订单外新增行不占用执行量。
6. 批次管理商品必须选批次；非批次商品批次必须为空；同商品不同批次分行，同商品+批次不能重复。
7. 审核时逐行校验 `(仓库, 商品, 批次)` 的可用库存；不足整单拒绝，禁止按商品汇总校验。
8. 审核顺序：先校验库存 → 本地置已审核 → 写负向扣减流水 → 推送金蝶；推送失败不回滚扣减。
9. 反审核：插入独立正数冲销流水（`OUTBOUND_REVERSAL`），不修改原扣减流水；金蝶反审核失败不回滚本地库存。
10. 保存出库草稿推进销售订单 `pushed_qty`/执行状态；审核推进 `audited_out_qty`/出库状态；反审核回退。
11. 派工来源出库单不可编辑/删除；如派工有误，由派工单侧处理。
12. 已推送金蝶的草稿不能直接修改/删除；需先反审核。

### 【操作结果】

- 保存后生成草稿；销售订单来源推进订单执行状态；
- 审核后库存减少（负向流水），金蝶推送成功=已同步金蝶；
- 推送失败时本地已扣减，状态=推送失败，可重试；
- 反审核后库存恢复（正数冲销），金蝶反审核；
- 打印输出出库单。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| （无） | 保存出库草稿 | 归属组织 | 草稿 | 不变（订单来源推进执行状态） | 不推送 |
| 草稿 | 编辑/删除 | 归属组织 | 草稿/已删除 | 不变（释放订单占用） | 不推送 |
| 草稿 | 审核并推金蝶 | 归属组织 | 已审核 | 减少（负向 SALE_OUTBOUND 流水） | 推送（save→audit） |
| 已审核 | 重试推送 | 归属组织 | 已审核 | 不变 | 重试推送 |
| 已审核 | 反审核并同步金蝶 | 归属组织 | 草稿 | 增加（正数 OUTBOUND_REVERSAL 流水） | 反审核同步 |
| 已审核 | 打印 | 归属组织/运营商只读 | 已审核 | 不变 | 不推送 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “可用库存不足：XXX 批次[YYY] 可用 X，本次出库 Y” | 该批次可用库存不足 | 减少数量、换批次，或先做采购入库补充库存 |
| “该商品启用批次管理，请选择批次：XXX” | 批次商品未选批次 | 在批次列选择批次 |
| “该商品未启用批次管理，批次必须为空：XXX” | 非批次商品填了批次 | 清空批次 |
| “出库数量超过剩余可出库量（X）：XXX” | 订单行数量超过剩余 | 减小数量或先处理其他出库草稿 |
| “销售订单未审核，不可创建销售出库” | 订单未审核 | 先审核销售订单 |
| “销售订单已全部下推出库” | 订单执行状态=全部 | 不能继续下推 |
| “派工单生成的出库单不可编辑/不可删除，请由派工单侧处理” | 派工来源 | 到派工单/员工工作台处理 |
| “该单据已推送金蝶，不能直接删除” | 已推送 | 先反审核再删除 |
| “仅草稿可修改，已审核请先反审核” | 已审核 | 先反审核 |
| 审核成功但提示“金蝶推送失败” | 金蝶接口/参数异常 | 库存已扣减；点击“重试推送”，不要重复审核 |
| 反审核提示“金蝶反审核失败” | 金蝶接口异常 | 本地库存已恢复；稍后重试同步/联系管理员 |

### 【注意事项】

1. 审核前务必确认批次与数量；库存校验按批次粒度，批次选错会导致整单拒绝。
2. 审核成功但金蝶推送失败时，库存已扣减；不要重复审核，点“重试推送”。
3. 反审核写正数冲销流水，原扣减流水保留；库存查询会看到正负两条记录。
4. 派工来源出库单由派工流程生成，不能手工改/删；派工错误请在派工单侧处理。
5. 销售订单来源的订单外新增行不占用订单执行量，但会扣减库存；制单时确认用途。
6. 城市合伙人只能操作本组织单据；运营商看下辖单据只读。

### 【测试验证要点】

1. 三种来源均可制单；派工来源不出现在手工来源选项。
2. 业务数据查询按手机号/名称/收据号，多选合并；金蝶客户可与来源客户不同。
3. 商城订单只能选已付款；来源客户/地址自动带出。
4. 销售订单来源只能选已审核且未全部下推订单；数量超过剩余被拦截。
5. 批次商品必须选批次，非批次商品批次必须为空。
6. 审核时逐行校验可用库存，任一行不足整单拒绝。
7. 审核后库存减少、金蝶推送；推送失败不回滚库存，可重试。
8. 反审核后库存恢复（正数冲销），金蝶反审核；失败不回滚本地。
9. 派工来源不可编辑/删除。
10. 已推送草稿不能修改/删除。
11. 打印包含批次、来源、收货地址、金额。

### 【常见问题】

> **Q：为什么审核提示“可用库存不足”，但商品明明有库存？**
> A：库存按 `(仓库, 商品, 批次)` 校验。请检查仓库和批次是否选对；不同批次库存不合并。

> **Q：审核后金蝶推送失败，库存会退回来吗？**
> A：不会。本地审核与扣减已生效，推送失败只标记状态；请点“重试推送”，不要重复审核。

> **Q：派工来源的出库单为什么不能改？**
> A：派工来源由员工工作台派工流程生成，数量/商品来自派工单；需要调整请在派工单侧处理，避免两端口径不一致。

## 4.5 销售退货

### 【功能说明】

销售退货用于客户退回商品。支持业务数据、销售订单、商城订单三种来源；审核后库存增加并推送金蝶，反审核库存扣回。退货不校验即时库存下限，数量上限是“可退数量”（已退数量包含未审核草稿）。业务数据来源审核时会向 ops 原订单反写负数金额分录并重算提成。

### 【适用角色】

- 运营商：可查看本级 + 下辖退货单；可新建、审核、反审核、重推、删除本级草稿；对下辖单据只读。
- 城市合伙人：只能操作本组织退货单；可新建、审核、反审核、重推、删除草稿。
- 【不可见项】非归属组织看不到编辑/审核/反审核/删除按钮；金蝶反审核失败后，草稿行显示“重试反审同步”。

### 【操作入口】

- 平台主站 → 供应链管理 → 销售退货（`/subsystem/scm/sale-return`）。

### 【前置条件】

1. 客户已同步；退货仓库已同步且可见；商品已同步；
2. 业务数据来源：业务数据属于当前组织，商品可匹配/手选；
3. 销售订单来源：订单已审核且已有出库；可退数量 = 已审核出库 − 已退；
4. 商城订单来源：商城订单已付款；可退数量 = 订单数量 − 已退；
5. 批次管理商品必须选择批次。

### 【操作步骤】

#### 新建销售退货（业务数据来源）

1. 进入“供应链管理 → 销售退货”，点击“新建销售退货”。
2. 数据来源选择“业务数据”。
3. 点击“查询业务数据（手机号/名称/收据号）”，选择业务数据；系统按商品带出销售数量、已退数量、可退数量、即时库存。
4. 选择“金蝶客户”和“退货仓库”；收货地址、备注可填。
5. 表体核对商品、批次、可退数量、数量、单价；数量不能超过可退数量；批次商品选择批次，可按批次拆分行。
6. 核对“应退金额”。
7. 点击“保存”生成草稿。

> 【截图 4-15：销售退货新增弹窗-业务数据来源，展示可退数量】
>
> 图注：数据来源单选、查询业务数据按钮、金蝶客户、退货仓库、收货地址、备注；表体列商品、批次、即时库存、可退数量、数量、单价、退款金额。此处需补充实际界面截图。

#### 新建销售退货（销售订单来源）

1. 数据来源选择“销售订单”。
2. 选择已审核且已有出库的销售订单。
3. 系统带出订单客户、发货仓库、已出库分录、可退数量。
4. 填写退货数量/批次；同一来源行可按批次拆多行，合计不能超过可退数量。
5. 保存草稿。

#### 新建销售退货（商城订单来源）

1. 数据来源选择“商城订单”。
2. 选择已付款商城订单。
3. 系统带出商品、订单数量、来源客户、收货地址；金蝶客户按商城订单派生并锁定。
4. 填写退货数量/批次；保存草稿。

#### 编辑/删除草稿

1. 草稿行点击“编辑”，可修改客户、仓库、地址、备注、分录。
2. 数据来源锁定，不可切换。
3. 已推送金蝶的退货单不能直接修改（提示删除后重新制单）。
4. 草稿行点击“删除”，确认后删除。

#### 审核并推金蝶

1. 草稿行点击“审核并推金蝶”。
2. 系统按来源分组校验可退数量（已退含其他未审核草稿，排除本单）；超出整单拒绝。
3. 本地置为已审核，逐行写正数库存流水（增加库存）；业务数据来源先向 ops 原订单反写负数金额分录。
4. 推送金蝶（保存 `sal_in_bound` → 审核）。
5. 成功提示“审核并推送成功”；推送失败时提示“本地审核成功（金蝶未同步，可重推）”，库存已增加。

#### 反审核

1. 已审核退货单点击“反审核”。
2. 本地回草稿，逐行写负数冲销流水（扣回库存）；业务数据来源回退 ops 负数分录并重算提成。
3. 同步金蝶反审核。
4. 金蝶反审核失败时提示“金蝶反审核失败，可再次点击反审核重试”；本地库存已扣回。
5. 金蝶失败后草稿行显示“重试反审同步”，点击只重试金蝶反审核，不重复扣库存。

#### 重推

1. 已审核但同步状态不是“已同步金蝶”的单据，点击“重推”。
2. 按原单号重推金蝶；不重复增加库存。

#### 从金蝶同步

1. 点击“从金蝶同步”，增量拉取金蝶销售退货单，按单号/金蝶 ID 匹配本地单据并回填金蝶标识。
2. 同步不覆盖本地审核状态；城市合伙人也可触发（账套路由到所属运营商，本地仅匹配本组织单据）。

### 【字段说明】

| 字段 | 是否必填 | 填写规则 | 示例 |
|---|---|---|---|
| 数据来源 | 必填 | 业务数据/销售订单/商城订单；编辑时锁定 | 业务数据 |
| 销售订单 | 销售订单来源必填 | 已审核且已有出库 | `XS-20261119-001` |
| 业务数据 | 业务数据来源选填 | 手机号/名称/收据号查询 | `09001` |
| 商城订单 | 商城订单来源必填 | 仅已付款 | `M20261119001` |
| 金蝶客户 | 必填 | 结算客户；订单来源锁定订单客户；商城来源锁定 | `KH-WY-001` |
| 来源客户 | 系统带出 | 业务数据/商城订单来源客户 | `张三 / 138...` |
| 退货仓库 | 必填 | 本组织可见仓库 | `CK00011` |
| 收货地址 | 选填 | 自动带出，可修改 | `XX小区 1-101` |
| 商品 | 必填 | 已同步商品；业务数据/订单带入行只读，未匹配商品可手选 | `SP00012` |
| 批次 | 批次商品必填 | 批次管理商品必须选择 | `PC20261119` |
| 可退数量 | 系统带出 | 业务数据=销售−已退；订单=已审核出库−已退；商城=订单数量−已退 | `2` |
| 数量 | 必填 | >0，且不超过可退数量；同来源行拆批次合计≤可退 | `1` |
| 单价 | 必填 | ≥0 | `2999.00` |
| 退款金额 | 系统计算 | 数量 × 单价 | `2999.00` |
| 应退金额 | 系统计算 | 所有行退款金额之和 | `2999.00` |
| 审核状态 | 系统带出 | 草稿/已审核 | 已审核 |
| 同步状态 | 系统带出 | 待推送/已推送/已同步金蝶/推送失败/SYNC_FAILED | 已同步金蝶 |

### 【业务规则与校验】

1. 退货库存方向与出库相反：审核增加库存（正数 `SALE_RETURN`），反审核扣回（负数 `SALE_RETURN_REVERSAL`）。
2. **退货不校验即时库存下限**；即时库存仅参考，不是数量上限。
3. 可退数量按来源计算，已退数量包含其他未审核草稿（排除本单）：
   - 业务数据：业务数据销售数量 − 同来源行/收据已退；
   - 销售订单：已审核出库数量 − 已退；
   - 商城订单：订单商品数量 − 已退。
4. 同一来源行按批次拆多行时，合计数量必须 ≤ 可退数量；同商品+批次不能重复。
5. 数量必须 >0，且不超过金蝶上限 9999999999；单价不能为负。
6. 批次管理商品必须选批次；非批次商品批次必须为空。
7. 业务数据来源审核/反审核会调用 ops 接口反写/回退负数金额分录，并触发提成重算；ops 调用失败则本地审核/反审核回滚。
8. 金蝶：先保存 `sal_in_bound`，再 `common_operate` 审核；客户传 `customer_id`。
9. 已推送金蝶的退货单不能直接修改；反审核后若金蝶仍有单据，也不能编辑，需删除后重新制单。
10. 反审核金蝶失败本地不回滚；草稿行出现“重试反审同步”，只重试金蝶反审核。
11. 草稿不可推送金蝶；必须先审核。

### 【操作结果】

- 保存后生成草稿；
- 审核后库存增加、业务数据负数回写、金蝶推送；
- 反审核后库存扣回、业务数据回退、金蝶反审核；
- 推送失败可重推，不重复加库存；
- 金蝶反审核失败可重试，不重复扣库存。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|
| （无） | 保存退货草稿 | 归属组织 | 草稿 | 不变 | 不推送 |
| 草稿 | 编辑/删除 | 归属组织 | 草稿/已删除 | 不变 | 不推送 |
| 草稿 | 审核并推金蝶 | 归属组织 | 已审核 | 增加（正数 SALE_RETURN 流水） | 推送（save→audit） |
| 已审核 | 重推 | 归属组织 | 已审核 | 不变 | 重试推送 |
| 已审核 | 反审核 | 归属组织 | 草稿 | 减少（负数 SALE_RETURN_REVERSAL 流水） | 反审核同步 |
| 草稿（金蝶反审失败） | 重试反审同步 | 归属组织 | 草稿 | 不变 | 重试反审核 |

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| “退货数量超过可退数量：XXX 可退 X，本次 Y” | 超过来源可退上限 | 减小数量；检查是否有其他退货草稿占用 |
| “退货数量必须大于 0” | 数量为 0/负数 | 修改数量 |
| “单价不能为负数” | 单价为负 | 改为 ≥0 |
| “存在重复的商品+批次行，请先合并：XXX” | 同商品+批次重复 | 合并为一行或拆不同批次 |
| “该商品启用批次管理，请选择批次” | 批次商品未选批次 | 选择批次 |
| “来源单据不存在、不属于当前组织或已无可退数量” | 来源失效/已退完 | 重新选择来源或核对可退数量 |
| “该退货单已推送金蝶，不能直接修改，请删除后重新制单” | 已推送后反审核 | 删除草稿重新制单 |
| “仅草稿可修改，已审核请先反审核” | 已审核 | 先反审核 |
| “草稿不可推送金蝶，请先审核” | 草稿点重推 | 先审核 |
| “金蝶反审核失败（可重试）” | 金蝶接口异常 | 点“重试反审同步”，仅重试金蝶 |
| 审核成功但提示“金蝶未同步” | 推送失败 | 库存已增加；点“重推”，不要重复审核 |

### 【注意事项】

1. 退货数量上限是可退数量，不是即时库存；不要因为“库存少”而不敢退货。
2. 已退数量包含未审核草稿；删除/修改草稿会释放可退数量。
3. 业务数据来源会回写 ops 订单负数分录并影响提成；审核前确认客户、收据、数量。
4. 反审核金蝶失败时，本地库存已扣回；不要重复反审核，点“重试反审同步”。
5. 已推送金蝶的退货单不能修改；反审核后若需改数量，删除草稿重新制单。
6. 商城订单来源客户/地址由服务器派生，不能手工改成其他客户。

### 【测试验证要点】

1. 三种来源均可制单；可退数量按来源正确计算，已退含草稿。
2. 数量超过可退被拦截；同来源行拆批次合计超可退被拦截。
3. 批次商品必须选批次；重复商品+批次被拦截。
4. 审核后库存增加、业务数据负数回写、金蝶推送。
5. 审核推送失败不回滚库存，可重推。
6. 反审核后库存扣回、业务数据回退、金蝶反审核。
7. 金蝶反审核失败后“重试反审同步”只重试金蝶，不重复扣库存。
8. 已推送后反审核的草稿不能编辑，删除后重新制单。
9. 草稿不能推送金蝶。
10. 城市合伙人可同步金蝶且只匹配本组织单据。

### 【常见问题】

> **Q：退货为什么提示“可退数量不足”，但客户确实退回来了？**
> A：可退数量按来源计算，已退包含其他未审核草稿。检查是否有其他退货草稿占用；删除或调整草稿后再试。

> **Q：退货审核后库存增加了，为什么金蝶没同步？**
> A：本地审核与库存已生效，金蝶推送失败只标记状态；点“重推”即可，不要重复审核。

> **Q：反审核后还能改数量吗？**
> A：如果该单已推送过金蝶，反审核后仍不能直接修改，需删除草稿重新制单；未推送过的草稿可以直接编辑。

> **Q：业务数据退货会影响原订单吗？**
> A：会。审核时向 ops 原订单反写负数金额分录并重算提成；反审核会回退。审核前确认退货数量与金额。

## 4.6 盘点任务与盘点单（含盘点处理）

### 【功能说明】

盘点用于核对实物库存与账面库存。盘点任务是一次盘点的分配容器：创建任务时选择仓库范围，系统先全量同步金蝶库存并固化“账存数”，再按仓库拆成多张盘点单；盘点单由仓库归属组织录入实盘数并审核；审核只锁定单据，不调整库存、不推送金蝶；最后由运营商财务在“盘点处理”中填写处理意见并推送金蝶，库存调整与金蝶盘盈/盘亏单在这一步才发生。

### 【适用角色】

- 运营商：可创建盘点任务（仅运营商可建）；可查看全部盘点单；可执行盘点处理/反处理/重试推送（后端校验运营商组织；该菜单通常只授予运营商财务角色）；对本级盘点单可执行、审核、反审核。
- 城市合伙人：可查看分配给本组织的盘点单，录入实盘数并审核；不能创建盘点任务，不能执行盘点处理（后端校验运营商组织）。
- 【不可见项】城市合伙人看不到“新建盘点任务”按钮；盘点处理页对城市合伙人只读，不显示处理/反处理/重试按钮。

### 【操作入口】

- 平台主站 → 供应链管理 → 盘点任务（`/subsystem/scm/stocktaking-task`）。
- 平台主站 → 供应链管理 → 盘点单（`/subsystem/scm/stocktaking-order`）。
- 平台主站 → 供应链管理 → 盘点处理（`/subsystem/scm/stocktaking-process`）。

### 【前置条件】

1. 金蝶账套授权可用，库存可同步；
2. 仓库已同步并已分配归属（盘点单归属=仓库归属组织）；
3. 创建任务仅运营商；盘点处理后端校验运营商组织（菜单通常授予运营商财务角色）；
4. 盘点单审核前必须所有行已录入“盘点数”。

### 【操作步骤】

#### 创建盘点任务（运营商）

1. 进入“供应链管理 → 盘点任务”，点击“新建盘点任务”。
2. 填写“任务名称”（必填，如“2026年11月广河分仓盘点”）。
3. “盘点仓库”多选（必填）；系统按仓库归属拆成多张盘点单，每张盘点单归属对应组织。
4. “库存日期”选择“即时库存”（当前版本“指定日期”不可用）；账存数在创建时按即时库存固化。
5. “商品来源”选择“有交易记录商品”或“全部商品”。
6. “盘点范围”选择“全盘”或“抽盘”；抽盘时至少指定商品类别、品牌、指定商品之一（取并集）。
7. 点击“创建”。系统先全量同步金蝶库存，再生成盘点单；等待创建成功提示。
8. 在“创建成功”弹窗查看每张盘点单的单据编号、归属组织、创建时间/操作人；可“返回盘点单列表”。

#### 执行盘点单（归属组织）

1. 进入“供应链管理 → 盘点单”，可按单据编号/仓库、审核状态、处理状态筛选。
2. 找到本组织草稿盘点单，点击“去盘点”。
3. 盘点单详情展示批次、生产日期、到期日、账存数、盘点数、盈亏数。
4. 逐行填写“盘点数”；盈亏数由系统按 `账存数 − 盘点数` 自动计算（正数=盘亏，负数=盘盈）。
5. 点击“保存”，提示“盘点数已保存”。
6. 全部行填写完成后，点击“审核”。系统校验所有行已盘点，锁定单据；提示“审核成功：单据已锁定，库存与金蝶均未变化”。

#### 盘点处理（运营商财务）

1. 进入“供应链管理 → 盘点处理”，默认筛选“待处理”。
2. 找到已审核、处理状态=待处理的盘点单，点击“处理”。
3. 查看账存合计、盘点合计、盈亏合计及明细。
4. 填写“处理意见”（必填，最多 1000 字，说明差异原因与处理方式）。
5. 可上传附件（jpg/jpeg/png/webp/pdf，单个≤10MB，最多 20 个）。
6. 点击“保存”只保存意见/附件，处理状态不变；点击“审核并推金蝶”执行处理。
7. 系统插入库存调整流水（盘盈 `STOCKTAKING_GAIN`/盘亏 `STOCKTAKING_LOSS`），推送金蝶盘盈/盘亏调整单。
8. 成功提示“库存已调整，金蝶已同步”，处理状态=已处理；失败提示“本地库存已调整，但金蝶推送失败：…，可重试或反处理”，处理状态=处理失败，本地库存不回滚。
9. 处理失败可点“重试推送”（不重复插入库存）；或点“反处理”回滚。

#### 反处理

1. 已处理或处理失败的盘点单，点击“反处理”。
2. 系统插入 `STOCKTAKING_REVERSAL` 反向库存流水，并同步金蝶反审核/删除调整单。
3. 成功提示“反处理成功：库存已冲销，金蝶调整单已反审核/删除”，处理状态=已反处理。
4. 金蝶反审核失败时提示“本地库存已冲销，但金蝶反审核失败，可再次点击反处理重试”；本地库存已冲销。
5. 反处理后如需重新盘点，先“反审核”回草稿，修改盘点数后重新审核、处理。

#### 反审核/删除

1. 盘点单审核后、未处理（处理状态=待处理或已反处理且金蝶反审成功）可“反审核”，回草稿，库存与金蝶均不变。
2. 已处理必须先反处理，不能直接反审核（提示“盘点单已处理，请先在盘点处理中执行反处理”）。
3. 草稿盘点单可“删除”；删除不影响库存（未处理）。
4. 反处理后金蝶反审失败时不能反审核/重新审核，需先“重试反处理”。

| 审核状态 | 系统带出 | 草稿/已审核 | 已审核 |
| 处理状态 | 系统带出 | 待处理/已处理/已反处理/处理失败 | 已处理 |
| 金蝶调整单 | 系统带出 | 盘亏/盘盈单号 | `PK-...` |

### 【业务规则与校验】

1. 创建任务先全量同步金蝶库存，再固化账存数；同步失败直接拒绝创建（提示“盘点前同步金蝶库存失败…”），避免用陈旧库存盘点。
2. 任务按仓库拆单：盘点单 `corp_id`=仓库归属组织；运营商可查看全部，城市合伙人只看本组织。
3. 状态两轴独立：`audit_status`（草稿/已审核）只表示审核；`process_status`（待处理/已处理/已反处理/处理失败）只表示处理。
4. 审核只校验全部行已盘点、重算盈亏并锁定单据；**不调整库存、不推送金蝶**。
5. 只有盘点处理才调整库存并推送金蝶：盘盈/盘亏按库存变化符号拆成金蝶库存调整单；同商品/批次/生产日期/到期日合并。
6. 处理失败（PROCESS_FAILED）本地库存已调整、金蝶未成功；重试推送不重复插入库存，反处理可回滚。
7. 反处理插入 `STOCKTAKING_REVERSAL` 反向流水，并同步金蝶反审核/删除；金蝶失败不回滚本地，可重试。
8. 已处理/处理失败不能直接反审核，必须先反处理；反处理金蝶失败未同步前不能重新审核。
9. 盘点处理后端校验运营商组织（`isOperator`），不额外校验“财务”角色；菜单通常只授予运营商财务角色，城市合伙人只读。
10. 处理意见最多 1000 字；附件最多 20 个、单个≤10MB、仅限指定扩展名。

### 【操作结果】

- 创建任务后生成按仓库拆分的盘点单，账存数固化；
- 录入盘点数并审核后单据锁定，库存与金蝶不变；
- 盘点处理后库存按盈亏调整，金蝶盘盈/盘亏单生成；
- 推送失败时本地库存已调整，可重试或反处理；
- 反处理后库存冲销、金蝶调整单反审核/删除。

### 【状态流转表】

| 当前状态 | 触发动作 | 操作角色 | 下一状态 | 库存变化 | 金蝶推送 |
|---|---|---|---|---|---|

| 已审核/待处理 | 处理推送失败 | 运营商财务 | 处理失败 | 已调整（不回滚） | 推送失败，可重试 |

| “仅处理推送失败（PROCESS_FAILED）的盘点单可重试推送” | 非失败状态 | 正常拦截；已处理无需重试 |

### 【注意事项】

1. 审核不等于处理：审核只锁定单据；库存与金蝶变化在盘点处理。
2. 已处理不能直接反审核；必须先反处理，否则会提示。
3. 处理失败时本地库存已调整，不要重复点“审核并推金蝶”；用“重试推送”或“反处理”。
4. 反处理金蝶失败时本地库存已冲销；不要重复反处理，点“重试反处理”。
5. 创建任务会先全量同步金蝶库存，可能耗时；同步失败时不要强行创建。
6. 盘点单归属仓库归属组织；运营商可处理下辖，城市合伙人只读处理页。

### 【测试验证要点】

1. 运营商可创建任务，城市合伙人看不到“新建盘点任务”。
2. 创建任务先同步金蝶库存，按仓库拆单，账存数固化。
3. 盘点数保存后盈亏计算正确（正=盘亏、负=盘盈）。
4. 未全部盘点时审核被拒绝。
5. 审核只改状态，库存与金蝶不变。
6. 盘点处理调整库存并推送金蝶；盘盈/盘亏单按符号拆分。
7. 处理失败本地库存不回滚，重试不重复插入库存。
8. 反处理冲销库存、金蝶反审核/删除；金蝶失败可重试。
9. 已处理不能直接反审核；反处理金蝶失败不能重新审核。
10. 城市合伙人处理页只读；运营商财务可处理。
11. 附件格式/大小/数量限制生效。

### 【常见问题】

> **Q：盘点审核了，为什么库存没变？**
> A：审核只锁定单据；库存调整与金蝶推送在“盘点处理”由运营商财务执行。

> **Q：盘亏/盘盈方向怎么算？**
> A：盈亏数 = 账存数 − 盘点数。正数=盘亏（库存减少），负数=盘盈（库存增加）；金蝶按库存变化符号拆成盘亏/盘盈单。

> **Q：处理失败后能直接重新处理吗？**
> A：可以点“重试推送”，不会重复插入库存；也可以“反处理”回滚后重新处理。

> **Q：为什么城市合伙人不能处理盘点？**
> A：盘点处理是财务动作，后端校验运营商组织（菜单通常授予运营商财务角色）；城市合伙人负责录入实盘数并审核。

## 4.7 库存查询

### 【功能说明】

库存查询用于按仓库、商品、批次、生产日期查看即时库存与可动用数量。平台库存以批次为最小粒度：同一商品同一仓库的不同批次分行展示；汇总行按 `(仓库, 商品)` 合并，展开后显示批次明细。库存来源包括金蝶同步基线、采购入库、销售出库、销售退货、盘点调整及各自冲销流水。

### 【适用角色】

- 运营商：可查看本级 + 下辖城市合伙人的库存；可执行“从金蝶同步库存”（需权限 `scm:inventory:sync`）。
- 城市合伙人：只能查看本组织库存；**不能执行“从金蝶同步库存”**（后端仅运营商可通过 `assertOperator` 校验）。
- 【不可见项】城市合伙人看不到其他组织库存；无同步权限看不到/无法执行同步；城市合伙人即使有 `scm:inventory:sync` 权限，同步接口仍会被拒绝。

### 【操作入口】

- 平台主站 → 供应链管理 → 库存查询（`/subsystem/scm/inventory`）。

### 【前置条件】

1. 金蝶账套授权可用（同步库存需要）；
2. 仓库、商品已同步；
3. 有“库存查询”菜单权限；同步需要 `scm:inventory:sync`。

### 【操作步骤】

#### 查询库存

1. 进入“供应链管理 → 库存查询”。
2. 输入筛选条件（可组合）：商品编码/名称、商品名称、条码、批次号、生产日期范围、仓库。
3. 点击“查询”。
4. 列表按 `(仓库, 商品)` 显示汇总行：仓库、商品编码、商品名称、条码、即时库存、可动用数量。
5. 点击行首展开箭头，查看批次明细：批次号、生产日期、到期日、变更类型、来源单据、即时库存、可动用数量、最后同步时间。
6. 到期日颜色：≤30 天标黄（临期），已过期标红；无保质期显示“—”。

#### 从金蝶同步库存（运营商）

1. 运营商账号点击“从金蝶同步库存”。
2. 系统按批次/保质期全量拉取金蝶库存，重建基线行；流水行保留。
3. 提示“同步 X 条，覆盖更新 Y 条（金蝶为库存基准）”。
4. 同步完成后刷新列表；平台合计应与金蝶批次合计一致。

| 生产日期 | 批次生产日期；无则为空 | `2026-11-01` |
| 到期日 | 按保质期计算；无保质期显示“—” | `2027-11-01` |

| 可动用数量 | 可用于出库的数量 | `100` |
| 最后同步时间 | 最近同步/变更时间 | `2026-11-19 10:00:00` |

### 【业务规则与校验】

1. 库存按批次粒度追踪：`(仓库, 商品, 批次)`；同商品不同批次分行，不同批次库存不合并。
2. 查询结果在 Java 端按 `(仓库, 商品)` 分组聚合：汇总行求和 `qty/valid_qty`，`details` 保留命中筛选的批次明细；筛选条件作用于明细行，汇总只统计命中的明细。
3. 数据范围：运营商看本级 + 下辖；城市合伙人只看本组织；商品按所属运营商共享域过滤。
4. 库存行分两类：
   - 流水行（`source_inbound_entry_id` 非空）：采购入库/销售出库/退货/盘点调整及冲销，逐笔保留；
   - 基线行（`change_type=JDY_SYNC`）：金蝶批次总量 − 流水净量，同步时替换。
5. 金蝶为库存基准：全量同步会清理旧基线行并重建；流水行保留，用于变更追溯。
6. 反审核写独立冲销行（采购负数、销售正数、盘点反向），不修改原流水；库存查询会看到正负两条记录。
7. 到期日哨兵 `1970-01-01` 表示无保质期，展示为“—”；≤30 天临期标黄、过期标红。
8. 同步需要 `scm:inventory:sync` 权限，且仅运营商可执行；城市合伙人即使有权限，后端 `assertOperator` 仍会拒绝（403）。
9. 库存查询只读，不提供本地调整入口；调整库存必须通过采购入库、销售出库/退货、盘点处理等业务单据。

### 【操作结果】

- 查询返回汇总行 + 批次明细；
- 同步后库存基线与金蝶一致，流水行保留；
- 临期/过期批次颜色提示；
- 各业务单据审核/反审核后库存即时变化。

### 【异常与处理】

| 现象 / 提示 | 原因 | 处理方式 |
|---|---|---|
| 库存为 0 或查不到 | 未入库/已出库/批次选错 | 检查业务单据与批次；确认仓库 |
| 汇总与明细合计不一致 | 筛选条件只命中部分明细 | 展开明细核对；清空筛选重查 |
| 同步提示失败 | 金蝶账套/授权/网络异常 | 检查金蝶账套配置与授权后重试 |
| 同步后数量与金蝶不一致 | 存在未同步的本地流水/同步未完成 | 查看变更明细；确认同步完整后重试 |
| 到期日显示“—” | 该批次无保质期（1970-01-01 哨兵） | 正常；非批次/无保质期商品 |
| 城市合伙人看到其他组织库存 | 数据范围异常 | 检查组织归属与权限；联系管理员 |
| 无同步按钮/同步 403 | 无 `scm:inventory:sync` 权限 | 联系管理员授权 |
| 导出找不到入口 | 当前页面未提供导出 | 【待确认】是否已上线其他导出入口 |

### 【注意事项】

1. 库存按批次校验出库；查询时务必看清批次，不能只看商品汇总。
2. 反审核后的正负流水都保留，汇总为净库存；不要误以为重复记录。
3. 金蝶同步是基准对齐，会重建基线行；本地流水不会丢。
4. 库存不能手工调整；盘盈/盘亏走盘点处理。
5. 临期/过期颜色只是提示，不阻止出库；是否允许出库由业务与金蝶参数决定。

### 【测试验证要点】

1. 按商品/条码/批次/仓库/生产日期筛选，结果正确。
2. 汇总行按 `(仓库, 商品)` 合并，展开显示批次明细。
3. 运营商看本级+下辖，城市合伙人只看本组织。
4. 采购入库审核后库存增加；销售出库审核后减少；退货审核后增加；盘点处理后调整。
5. 反审核后出现独立冲销行，汇总净额正确。
6. 金蝶同步后基线重建，流水行保留。
7. 临期≤30 天标黄、过期标红、无保质期显示“—”。
8. 无同步权限时不能同步。
9. 库存查询不能本地调整库存。

### 【常见问题】

> **Q：为什么同一商品有多行库存？**
> A：库存按 `(仓库, 商品, 批次)` 追踪；同一商品不同批次分行。汇总行按仓库+商品合并，展开可看批次明细。

> **Q：反审核后为什么库存没回到原来的数？**
> A：反审核写独立冲销行，原流水保留；汇总行是正负相抵后的净额。展开明细可看到两条记录。

> **Q：库存和金蝶不一致怎么办？**
> A：由运营商先点“从金蝶同步库存”做基线对齐；同步后仍不一致，查看变更明细与金蝶调整单，必要时走盘点处理。

> **Q：可以手工改库存吗？**
> A：不能。库存只能通过采购入库、销售出库/退货、盘点处理等业务单据变化；库存查询只读。
