# 员工微信授权登录 — 规格说明

> 状态：✅ 已实现（2026-11-12）
> 范围：ops 公众号 H5 员工入口（`frontend/src/pages/employee/`）+ 底座员工身份与绑定管理

## 一、功能概述

在保留原有「手机号 + 密码 + 图形验证码」登录的基础上，为公众号 H5 员工入口新增「微信授权登录」。两种方式最终都指向底座 `sys_user` / `sys_user_corp` 员工身份体系，签发相同的员工 JWT，登录成功后进入同一个员工工作台。

由于微信公众号网页授权（OAuth2.0）只能获取 openid，不能获取手机号，因此：

- **首次绑定**：员工先用密码登录，在「我的」中点击「绑定微信」完成 openid 绑定；
- **后续登录**：直接微信授权登录，无需密码；
- **未绑定微信**：微信授权登录会被拒绝，并引导使用密码登录，不允许未经授权的微信用户进入工作台；
- 不自动创建员工账号（员工账号仍由管理员在底座平台统一创建）。

## 二、用户故事

1. 已绑定微信的员工在公众号中打开员工入口，点击「微信授权登录」，授权后直接进入工作台。
2. 未绑定微信的员工点击微信登录，看到「该微信未绑定员工账号」提示，并可一键切到密码登录。
3. 使用密码登录的员工流程完全不变，验证码、频率限制、错误提示均保持原样。
4. 员工首次密码登录后，在「我的」看到「微信绑定 — 未绑定」，点击「绑定微信」完成授权；退出后再次微信授权登录可直接进入。
5. 底座管理员在「用户管理」中查看某员工的微信绑定关系，并可解绑（解绑后可重新绑定）。
6. 审计日志记录每次密码/微信登录的方式、员工 ID、时间、结果与失败原因。

## 三、验收标准

| # | 验收项 | 结果 |
|---|--------|------|
| 1 | 已绑定微信的员工微信授权登录，直接进入工作台，无需密码 | ✅ |
| 2 | 未绑定微信的员工点击微信登录，提示未绑定并引导密码登录 | ✅ |
| 3 | 原有手机号+密码+验证码流程不受影响 | ✅ |

## 四、流程

### 4.1 微信授权登录

```
员工登录页（微信登录 Tab）
  → GET /api/ops/auth/employee/wechat/authorize-url?mode=login&corpId=...
  → ops 生成一次性 state（5 分钟）+ 公众号授权 URL
  → 微信 OAuth（snsapi_base）→ 回调 https://boss.jdzn99.com/ops/?code=...&state=...
  → App.vue 落盘 code/state 并清理地址栏 → /pages/employee/wechat-callback
  → POST /api/ops/auth/employee/wechat/login { code, state }
  → ops 用 appId/appSecret 换取 openid
  → 底座 POST /api/auth/employee/wechat/login（X-Internal-Token）
      ├─ 已有 openid 绑定 → 取绑定员工
      ├─ 无绑定且有手机号 → sys_user.username 精确匹配 → 自动绑定
      └─ 均未命中 → 拒绝
  → 校验账号启用 + 所属组织有效 → 签发员工 JWT
  → 前端保存员工会话 → 员工工作台
```

### 4.2 首次绑定

```
员工已密码登录 → 我的 → 微信绑定卡片「绑定微信」
  → GET /authorize-url?mode=bind（要求员工 JWT；state 绑定当前 userId）
  → 微信 OAuth → 回调 → 回调页 POST /wechat/bind { code, state }
  → ops 换取 openid → 底座 POST /api/internal/user/wechat/bind
  → sys_user_wechat_bind 写入（唯一索引）
  → 返回「我的」
```

### 4.3 管理员解绑

```
底座 用户管理 → 微信绑定「查看」→ 绑定列表 → 解绑全部
  → DELETE /api/sys/user/{id}/wechat-bind
  → 物理删除绑定行（便于重新绑定）
```

## 五、API 设计

### ops（公众号 H5）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/ops/auth/employee/wechat/authorize-url?mode=login\|bind&corpId=` | login 公开 / bind 需员工 JWT | 返回 `{authorizeUrl, state, mode}` |
| POST | `/api/ops/auth/employee/wechat/login` | 公开（state + 频控） | `{code,state}` → 员工会话（与密码登录同结构 + `loginMode=wechat`） |
| POST | `/api/ops/auth/employee/wechat/bind` | 员工 JWT | `{code,state}` → `{bound, appId, openidMasked, bindTime}` |
| GET | `/api/ops/auth/employee/wechat/bind-status` | 员工 JWT | `{configured, bound, appId, binds[], error?}` |

### 底座（内部 / 管理）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/auth/employee/wechat/login` | X-Internal-Token | `{openid, appId, phone?, unionId?, clientIp?}` → 员工会话 |
| POST | `/api/internal/user/wechat/bind` | X-Internal-Token | `{userId, appId, openid, unionId?, clientIp?}` → 绑定结果 |
| GET | `/api/internal/user/wechat/bind-status?userId=&appId=` | X-Internal-Token | 绑定状态 / 列表 |
| GET | `/api/sys/user/{id}/wechat-bind` | 底座登录态 | 管理员查看绑定列表 |
| DELETE | `/api/sys/user/{id}/wechat-bind` | 底座登录态 | 管理员解绑全部（物理删除） |

## 六、数据模型

底座新增表 `sys_user_wechat_bind`：

| 列 | 类型 | 说明 |
|----|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 员工账号 ID（`sys_user.id`） |
| app_id | VARCHAR(64) | 公众号 AppID |
| openid | VARCHAR(128) | 微信 openid |
| union_id | VARCHAR(128) | 微信 unionid（可空） |
| create_time | DATETIME | 绑定时间 |
| delete_flag | INT | 保留审计字段；解绑使用物理删除 |

唯一索引：

- `uk_app_openid (app_id, openid)` — 一个微信只能绑定一个员工账号；
- `uk_app_user (app_id, user_id)` — 一个员工账号在同一公众号下只能绑定一个微信。

迁移脚本：`ai-native-platform/sql/migrate-user-wechat-bind.sql`（**必须先于底座新 JAR 执行**）。

## 七、安全与多租户

1. **state 防 CSRF**：一次性随机 32 位、5 分钟过期；绑定模式的 state 同时绑定发起时的员工 ID，回调时要求当前 JWT 用户一致。
2. **openid 只信任服务端交换**：浏览器只回传 code/state，ops 使用 appSecret 在服务端换取 openid；底座只信任 `X-Internal-Token`，不接收浏览器传入的 openid。
3. **绑定唯一性**：数据库唯一索引兜底并发；冲突转用户可读提示。
4. **未绑定不得进入**：微信登录未匹配到员工账号直接拒绝；所有员工接口仍走 JWT 鉴权。
5. **令牌隔离**：拒绝 `token_type=sso` 的会员令牌访问绑定/状态接口（`JwtTokenInspector`），与现有员工手工录入一致。
6. **不泄露内部错误**：微信 errcode/errmsg 只写日志，前端收到统一的中文提示。
7. **审计**：底座 `LogFileService` JSON-Lines 记录 `module=员工登录`，action=`密码登录`/`微信授权登录`，detail 含 result/reason/脱敏 openid。
8. **多租户**：绑定表无 `corp_id`，已加入 `TenantLineHandler.SKIP_TABLES`；员工账号与组织有效性仍由底座校验。管理员只能查看/解绑当前组织（超管除外）的用户。

## 八、配置与部署

1. 公众号后台配置「网页授权域名」为 `boss.jdzn99.com`（或实际域名）。
2. ops `application.yml`：
   ```yaml
   wechat:
     oauth:
       redirect-uri: ${WECHAT_OAUTH_REDIRECT_URI:https://boss.jdzn99.com/ops/}
       state-ttl-seconds: 300
       scope: snsapi_base
   ```
   `redirect-uri` 必须与公众号后台配置完全一致；微信会在其后追加 `?code=...&state=...`。
3. 部署顺序：底座迁移 → 底座 JAR → ops JAR → ops 前端。
4. 公众号需具备网页授权权限（服务号/已认证订阅号）；`snsapi_base` 静默授权即可获取 openid。

## 九、已知限制

- 公众号 OAuth 无法获取手机号；首次绑定必须经过密码登录。若未来接入可提供手机号的渠道（如小程序 `getPhoneNumber`），底座微信登录接口已预留 `phone` 参数，可按 `sys_user.username` 精确匹配并自动绑定。
- state 为单实例内存存储（与现有图形验证码一致）；ops 多实例部署时需改为共享存储（Redis）。
- 解绑为物理删除，不保留历史绑定记录；登录/解绑审计仍在操作日志中可查。
