# 员工制单「新建小区」— 规格说明

> 状态：✅ 代码已实现（2026-11-18）；生产发布待确认
> 范围：公众号员工 H5 业务订单制单（基础信息步骤）+ ops 后端 + 平台小区内部接口

## 一、功能概述

员工在公众号 H5「业务数据订单」制单的基础信息步骤选择小区时，若目标小区不存在：

- 小区标题右侧新增「＋ 新建小区」入口；创建成功后自动选中，无需离开制单页。
- 新小区自动归属当前员工组织（`corp_id` 来自员工 JWT），并关联到该组织在平台配置的所在区县
  （`sys_corp.region_id`，生产城市合伙人组织均为区县级）。
- 搜索框已输入关键词时，新建弹层自动预填名称。

## 二、关键决策

1. **区县来源**：只取组织自身 `sys_corp.region_id`，不接受前端传入区县；组织未配置区县时明确拒绝
   「组织未配置所在区县，请联系管理员」。
2. **租户隔离**：小区写入 `sys_community.corp_id = 当前员工组织`；同区县其他组织的同名小区保持独立行，
   不跨组织复用（订单落库仍按 id + corp 校验归属）。
3. **幂等**：同组织 + 同区县 + 同名（去首尾空白）返回已有小区，重复点击/重试不产生重复行。
4. **实现路径**：子系统不跨库写平台表；ops 后端经 `PlatformInternalClient` 调平台内部接口
   `POST /api/internal/community/create`（`X-Internal-Token`），平台侧落库。
5. **权限**：仅员工 JWT（`sso` 会员令牌与外部用户拒绝）；组织/操作人全部服务端派生。
6. **无表结构变更**：复用 `sys_community` 既有字段，不新增列、不新增迁移。

## 三、接口

### 平台（内部，X-Internal-Token）

`POST /api/internal/community/create`

```json
{ "corpId": 12, "name": "德保碧桂园", "operatorUserId": 577, "operatorName": "李四" }
```

成功：`{"code":200,"data":{"id":123,"name":"德保碧桂园","regionId":2401,"regionName":"德保县"}}`
失败：`code=403`（token 无效）/ `500`（组织不存在、未配置区县、名称为空/超长）。

### ops（员工 JWT）

`POST /api/ops/employee/business-data/communities`

```json
{ "name": "德保碧桂园" }
```

返回 `{ id, name, regionId, regionName }`；名称必填、≤200 字；`sso` 令牌返回 403。

## 四、后端实现

- 平台 `SysCommunityService.createForCorp(corpId, name, operatorUserId, operatorName)`：
  校验组织启用 + `region_id` 非空 → 名称 trim/长度校验 → `corp_id + region_id + community_name`
  查询已有 → 新建（`user_count=0`，记录创建人）→ 返回 `CommunityCreateResult`。
- 平台 `InternalCommunityController`：token 校验、参数校验、结果映射。
- ops `EmployeeBusinessEntryServiceImpl.createCommunity`：`assertEmployee` 后取 `corpId/员工ID/姓名`，
  调平台内部接口，透传平台错误信息；解析 `data` 返回。
- ops `EmployeeController` 新增端点（`@OperationLog`），拒绝 `sso` 令牌。

## 五、前端交互

- `BusinessStepBasic.vue`：小区标题行右侧「＋ 新建小区」；无小区时提示改为
  「组织暂未配置小区，可直接点击「新建小区」创建」。
- 新组件 `BusinessCommunityCreateSheet.vue`：底部弹层，名称必填 ≤200，提示
  「新小区将自动关联到本组织所在区县，创建后自动选中」；创建中禁用按钮；服务端错误就地展示。
- 创建成功：加入 `meta.communities` 并调用 `setCommunity` 自动选中；toast 提示关联区县。
- 草稿编辑复用同一向导，新建小区同样可用。

## 六、验收标准

1. 有小区列表时标题旁显示「＋ 新建小区」；列表为空时显示新建提示与入口。
2. 输入名称提交后创建成功并自动选中，表单可继续下一步。
3. 新小区 `corp_id` = 当前组织、`region_id` = 组织所在区县，可在下拉中再次选择。
4. 同一名称重复提交返回同一小区 ID，不产生重复行。
5. 名称为空/超 200 字、组织未配置区县时给出中文错误，不落库。
6. 会员 `sso` 令牌、外部用户调用接口被拒绝（403/业务异常）。
7. ops 与平台编译、H5/小程序构建通过。

## 七、部署顺序

1. 发布**平台后端 JAR**（新增内部小区接口）。
2. 发布 **ops 后端 JAR**（新增员工端点）。
3. 发布 **ops H5**（清空 assets 后上传，nginx reload）。
4. 冒烟：内部接口创建测试小区 → 核对 `sys_community.corp_id/region_id` → 删除测试行；
   员工 H5 新建并选中小区后提交订单。

无数据库迁移、无平台前端变更。

## 八、已知限制

- 并发双击极端场景下平台侧查询+插入非原子，理论上可能产生两行同名小区（前端已禁用重复提交；
  平台既有后台新增同样如此）；如需强约束可后续加 `(corp_id, region_id, community_name)` 唯一索引。
- 小区坐标/地址不在此入口采集，后续可在平台小区管理补充地址与地理编码。
- 组织区县变更后，已创建小区保留原 `region_id`（历史数据不迁移）。
