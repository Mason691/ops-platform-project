# 增值业务模块 — 功能规格说明

> 版本：1.1 | 最后更新：2026-11-06 | 状态：✅ 已实施

## 1. 模块概述

增值业务（Value-Added Business）是运营平台的扩展业务模块，用于管理增值产品、提成规则和业务销售数据。模块包含三个子功能：

| 子模块 | 说明 |
|---|---|
| 增值产品管理 | 维护增值产品目录（品牌/品类/型号/价格层级），作为业务数据导入时的价格参照 |
| 提成规则管理 | 管理个人提成规则和公司提成规则，用于业务数据提成计算 |
| 业务数据管理 | Excel 导入销售明细 → 匹配增值产品 → 计算提成 → 导出报表 |

## 2. 架构依赖

### 2.1 BaseEntity 继承

全部四张核心表实体继承 `com.aip.sdk.entity.BaseEntity`，标准审计字段由 `MybatisPlusConfig.MetaObjectHandler` 自动填充：

| 字段 | 填充时机 | 来源 |

| `createTime` / `modifyTime` | INSERT / INSERT+UPDATE | `LocalDateTime.now()` |
| `createUser` / `modifyUser` | INSERT / INSERT+UPDATE | `SecurityUtils.getCurrentUser().getUserId()` |
| `createUserName` / `modifyUserName` | INSERT / INSERT+UPDATE | `SecurityUtils.getCurrentUser().getUsername()` |
| `uniqueId` | INSERT | `IdWorker.get32UUID()` |
| `updateKey` | INSERT | `""` |

- `corp_id` 字段标记数据归属

- `operatorId` 字段标记为 `@Deprecated`，保留向后兼容但不用于新逻辑

## 4. API 端点

### 4.4 财务核对 — `PUT /api/ops/admin/business-data/{id}/finance-check`

**权限**：运营商管理员/超管，或当前组织内 corp 级角色名含「财务」的财务角色（生产角色：财务仓库/财务库存）。
运营商管理员按**用户级**判定：`sys_user.is_admin=1` 或当前组织 corp 级角色名含「管理员」；组织角色缺失/平台不可达时 fail-closed（不再把整组织员工放行）。
子公司经办人（无财务角色）不可见按钮，后端亦拒绝。

**请求体**：

```json
{
  "receiptNo": "0001234",
  "financeReceiptDate": "2026-11-03",
  "fundDynamicRows": 300,
  "isReceived": "是"
}
```

**校验与规则**：

1. 收据号必填（≤50 字符）；同一客户的多行可共用同一收据号（同订单拆分行，与导入侧组内一致性口径对齐），被**其他客户**占用时直接拦截并提示已有批次/客户。
2. 财务收款日期必填，且不得早于市场收款日期（市场日期可解析时）；市场日期为存量 varchar，兼容 `yyyy/M/d`、`yyyy.M.d`。
3. 资金动态表横排数可空；非空必须为 `>=0` 整数（JSON 小数也拒绝）。
4. 是否收款必填 是/否。
5. 已上报集团：前端按钮置灰，后端 `UPDATE ... WHERE calc_status != '已上报集团'` 二次拦截。
6. 是否收款=是且原业务数据无 `voucher_url`：弹窗提示凭证缺失，**不强制补传**（本次业务口径）。
7. 保存同时写入 `finance_check_user_id/user_name/time` 与审计字段；再次打开回显四项已填值，可修改重存。
8. 列表展示「是否收款」「财务核对（已核对/未核对，tooltip 显示核对人+时间）」；导出 Excel 增加「是否收款」列（收据号/财务收款日期/资金动态表横排数原已存在）。

### 4.4.1 批量财务核对（平台主站，2026-11-06）

- **入口**：业务数据列表勾选至少一条后，点击「批量删除」右侧的「财务核对」按钮；未勾选时点击提示「请先选择需要核对的业务数据」。按钮仅财务角色/运营商管理员可见。
- **展示**：全屏弹窗，按卡片逐条展示只读详情（批次号、客户名称/手机、品牌、品类、型号、销售单价/数量、收款金额、市场收款日期、经办人/手机号、是否特批、提成比例、当前计算状态）与四项补录表单。
- **保存**：每条卡片独立「保存本条」，前端逐条校验四项字段后调用 4.4 接口；失败提示就近展示在该卡片内，不影响其他记录。
- **状态**：已上报集团行锁定不可编辑；保存成功后该行置灰并标记「已保存」，按钮禁用，避免重复保存；关闭弹窗后列表刷新。
- **大数据量**：选中超过 10 条时弹窗内分页（每页 10 条），各页编辑草稿按行保留。
- **字段口径**：批量页按本次需求将「资金动态表横排数」设为必填（≥0 整数）；4.4 接口保持历史可空口径以兼容单条核对入口。

### 4.5 小区 / 详细地址 — 员工手工录入 / Excel / 供应链打印（2026-11-06）

**必填口径**：小区**选填**（会员查询自动带出、可手选；组织未配置小区时不阻断录入）；详细地址**必填**（H5 + 后端双校验）。

**H5 员工手工录入**（`/api/ops/employee/business-data/manual`）：

- `GET /manual/options` 返回 `communities: [{id, name}]`（当前员工 corp_id 下小区）。
- `GET /manual/member?phone=` 返回 `communityId`、`communityName`：优先 `sys_member.community_id`，缺失回退 `ops_gas_user` 同手机/会员的 `community_id`。
- `POST /manual` 请求 `communityId`（选填）、`detailAddress`（必填，≤200 字）；服务端按 `sys_community.id + corp_id` 校验归属并取名称，分别写入 `community_id/community_name` 与 `detailed_address`，不信任前端名称、不再拼接。

**Excel 导入**：

- 模板「业务数据」sheet **T 列=小区、U 列=详细地址**（T 原「收货地址」改名）；旧模板 T 列「收货地址」按表头名兼容映射到 `detailed_address`。
- 两列均可选（旧模板缺失/单元格空均允许，不阻断）；小区 ≤200 字、详细地址 ≤500 字，超长拒行。
- 小区名称按同 corp 精确匹配 `sys_community` 回填 `community_id`；未匹配留空，不阻断。
- 导入结果新增 `detailedAddressEmptyCount`（详细地址为空行数）。

**供应链销售出库打印**：

- `SaleOutboundDTO` 新增 `dataCommunityName`、`dataDetailedAddress`；仅 `dataSource=BUSINESS_DATA` 时按 `data_table_id` 从 `ops_business_data.community_name/detailed_address` 拉取，打印组合为「小区 + 详细地址」。
- 两者皆空时打印显示「未填写」，不阻断；非业务数据来源保持原 `contactAddress || customerAddress` 口径。

**列表/导出**：

- 主平台业务数据列表拆为「小区」「详细地址」两列；财务核对详情弹窗与批量核对卡片同步展示两字段；H5 月度明细分两行展示。
- 异步/同步导出在「客户」后增加「客户手机」「小区」「详细地址」，异步补「经办人手机号」；提成列统一为导入可识别的「提成比例」（异步 25→28 列、同步 26→28 列），导出文件可直接回导（四.3 往返验收）。

## 5. 提成计算逻辑

### 5.1 固定提成

```
提成金额 = salePrice × commissionRate / 100
```

### 5.2 阶梯提成

- `salePrice >= retailFloorPrice` → 全额提成 `salePrice × rate / 100`
- `retailFloorPrice > salePrice >= groupLowestPrice` → 中间档 `salePrice × 5%`
- `salePrice < groupLowestPrice` → 0 提成

## 6. 导入数据流

```
Excel (.xlsx) → Python openpyxl 解析 → TSV 行
  → 逐行验证（公司/品类有效性检查）
  → 匹配增值产品（brand|category|model）→ 获取底价
  → 写入 ops_business_data（calc_status="未计算"）
  → 返回 {success, fail, errors}
```
