# 城市合伙人「业务员」基础角色 — 规格说明

> 状态：✅ 已实现并部署（2026-11-18）；生产迁移已执行并自检通过
> 范围：底座（ai_platform 角色/员工任职）+ ops 公众号 H5 员工工作台 + SCM 采购 H5 接口

## 一、功能概述

在运营商体系下，为每个城市合伙人组织（`sys_corp.org_role_id = 5`）分别创建「业务员」角色（角色编码 `salesperson`，写入 `remark`）。业务员是组织内员工的基础角色：

- 组织内所有员工（含已另有部长、财务、派工员、施工员、验收员、售后等角色的员工）默认拥有；
- 新员工入职/加入组织时自动关联；
- 存量员工由迁移脚本批量补齐；
- 拥有公众号 H5 员工工作台除「已核对业务」外的全部功能。

「已核对业务」对应采购订单 H5 制单能力（权限码 `scm:pur-order:h5:create`）。业务员角色默认不授予该权限：

- 工作台首页不渲染「已核对业务」卡片；
- 直接打开 `/pages/employee/verified-business` 显示无权限拦截页；
- 直接调用 `GET /api/scm/pur-order/h5/finance-checked-orders`、
  `POST /api/scm/pur-order/h5/purchase-requests` 返回 403。

多角色权限取并集：员工若另有具备 `scm:pur-order:h5:create` 的角色（或为组织管理员，继承组织角色模板），仍可看到并使用「已核对业务」。

## 二、用户故事

1. 城市合伙人组织的新员工加入后，无需管理员手工配置角色，登录 H5 工作台即可使用业务数据、物资领用/核销、物料领取/核销、货款补录、待办、工作日志、AI 助手等全部常用功能。
2. 仅拥有业务员角色的员工在工作台看不到「已核对业务」，直接访问页面或接口被拦截并提示无权限。
3. 同时拥有业务员与部长/财务等角色的员工，仍可正常看到并使用「已核对业务」。
4. 组织管理员在平台「角色管理」中调整业务员角色的菜单权限，拥有该角色的员工按新权限渲染工作台（重新登录/切换组织后生效）。
5. 组织管理员试图移除某员工的业务员角色时，若移除后该员工将没有任何工作台权限，系统拒绝并提示先分配其他业务角色。
6. 业务员角色不可删除（避免全体员工失去基础权限）；可调整其菜单授权。

## 四、角色与权限设计

### 4.1 角色

- 表：`ai_platform.sys_corp_user_role`
- 名称：`业务员`；编码：`salesperson`（写入 `remark`，该表无 `role_code` 列）
- 归属：每个城市合伙人组织本级各一条，不复用角色 ID
- `description`：`组织基础角色：员工工作台全部功能（不含已核对业务）`

### 4.2 默认菜单（权限码）

| 权限码 | 功能 |
|--------|------|
| `wf:task:todo` | 我的待办 |
| `wf:task:initiated` | 我发起的审批 |
| `scm:material-pick:list` / `create` / `print` / `h5:create` | 物料领取 |
| `scm:material-write-off:list` / `create` / `h5:create` | 物料核销 |
| `h5:biz-order:balance-receive` | 货款补录 |

**不授予**：`scm:pur-order:h5:create`（已核对业务/采购 H5 制单）、`scm:pur-order:h5:review`（H5 核审，审批权限）。

> 业务数据、工作业务日志、AI 助手、个人中心等卡片当前无独立权限码，按平台既有逻辑不做单卡片鉴权；拥有业务员角色（权限非空）即可展示。

> **平台启动补充**：平台启动任务 `DataInitRunner` 会按既有全局行为给所有企业角色补授 `sys:org:ai-config` / `sys:org:public-search`（菜单 23/24）。业务员角色因此实际还会多出这两个 PC 组织设置按钮（生产验证角色实际 12 个菜单），但不影响 H5 工作台与「已核对业务」隔离（自检 2095 持有数为 0）。

### 4.3 前端渲染

- `frontend/src/utils/employeeSession.js` 导出 `PERM_VERIFIED_BUSINESS = 'scm:pur-order:h5:create'` 与 `hasEmployeePermission()`。
- 工作台 `dashboard.vue`：`canViewVerifiedBusiness` 由当前组织权限列表计算，无权限时不渲染卡片。
- `verified-business.vue`：进入页面先校验权限，无权限显示「无权限访问已核对业务」+ 返回工作台，不请求接口。

### 4.4 后端鉴权

- `H5PurOrderController.financeCheckedOrders()` / `createPurchaseRequest()` 要求 `scm:pur-order:h5:create`（超管放行）。
- 订单详情 `GET /{id}` 保持 `h5:create` 或 `h5:review`，总经办审批任务页不受影响。
- 工作流待办/审批接口继续按任务处理人鉴权；业务员不是审批角色，不会获得审批权限。

## 五、数据迁移

脚本：`sql/business_staff_role_migration.sql`（目标库 `ai_platform`，幂等）

1. 为所有未删除的城市合伙人组织创建业务员角色（已存在则跳过）；
2. 按权限码授予默认工作台菜单（`INSERT IGNORE`，不依赖固定菜单 ID）；
3. 收回业务员角色上可能误授予的 `scm:pur-order:h5:create`（兼容 SCM 菜单种子先执行的场景）；
4. 为所有在职任职（`sys_user_corp.status=1`）批量绑定业务员角色（`INSERT IGNORE`）；
5. 输出组织数、角色数、菜单数、已核对业务权限持有数（期望 0）、未绑定员工数自检结果。
6. 脚本显式 `SET NAMES utf8mb4`；建议在平台后端重启前执行，或执行后重启平台以清空 PermissionLoader 本地缓存。

## 六、多租户与安全

- 角色/员工绑定按 `corp_id` 分别落库，不跨组织复用角色 ID。
- 工作台权限只用于 UI 与接口能力控制，不改变数据范围；所有业务接口仍按 JWT `corp_id` 与经办人过滤。
- 业务员不自动获得工作流审批权限；审批人仍由工作流节点角色/审批人决定。
- 角色删除受保护；移除员工基础角色前校验剩余权限，避免工作台不可用。

## 七、已知限制

- 平台员工 JWT 内嵌权限码（有效期默认 12 小时）。角色/菜单调整后，员工需重新登录或切换组织才会拿到新权限（平台既有机制，本次未改动）。
- 业务员角色权限调整的「即时生效」受上述 JWT 机制限制。
- 迁移脚本为直连 SQL，绕过平台写路径，不会主动清空 `PermissionLoader` 本地缓存；建议在平台重启前执行迁移，或执行后重启平台。
- SCM 采购 PC 接口已统一要求 `scm:purchase:list`，防止绕过 H5 已核对业务权限；SCM 菜单种子重跑时会排除「业务员」角色，避免重新授予 `scm:pur-order:h5:create`。
