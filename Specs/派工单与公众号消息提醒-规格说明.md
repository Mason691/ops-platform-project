# 派工单 / 待处理 / 公众号消息提醒 — 规格说明

> 状态：✅ 已实现（2026-11-13）
> 涉及仓库：`ops-platform-project`（后端 + 公众号 H5）、`scm-mehome`（销售出库内部接口）、`ai-native-platform`（openid 内部接口 + 管理前端 + 菜单）

## 1. 功能概述

打通「财务核对完成 → 派工 → 公众号消息触达 → 员工接单 → 自动生成销售出库单」闭环：

1. 运营/财务在「增值业务 → 业务数据」订单列表对已完成财务核对（或含户内美装品类）的订单发起派工。
2. 派工单生成后异步推送公众号模板消息给被指派员工；推送失败记录原因并支持重发。
3. 员工在公众号 H5「待处理」查看工单，点击消息可直达工单详情（未登录先登录再回跳）。
4. 员工接受施工工单后，ops 调用 SCM 内部接口生成一张 `DRAFT`（未审核）销售出库单；
   入户随访工单不生成出库单。
5. 员工按工单执行并完成；派工单与出库单双向可追溯。

## 2. 用户故事

- 作为运营/财务，我可以对已财务核对的订单选择员工、期望上门时间、施工商品或随访说明并发起派工。
- 作为运营/财务，我可以查看派工单列表/详情、取消待接单工单、对推送失败的工单重发消息。
- 作为员工，我在公众号收到派工通知，点击进入工单详情，接受任务后系统自动生成销售出库单。
- 作为员工，我可以查看待接单/已接单/处理中/已完成工单，电话联系客户，开始处理并完成工单。
- 作为管理员，我可以配置公众号消息模板（模板ID、字段映射、场景、启用状态）。

## 3. 数据模型（mall_db）

### 3.1 `ops_dispatch_order`（派工单主表）

关键字段：`dispatch_no`（唯一）、`source_order_id/source_order_no/receipt_no`、`corp_id`、
`dispatch_type`（`CONSTRUCTION`/`VISIT`）、客户/小区/地址、`expect_time`、
`assignee_user_id/name/username`、`status`、`dispatch_by/time`、`accept_time`、`start_time`、
`complete_time`、`reject_time/reason`、`cancel_time/reason`、`stock_out_id/stock_out_no`、
`message_status/message_error`、`source_snapshot`（客户信息修改留痕 JSON）+ BaseEntity 字段。

状态机：
```
PENDING（待接单） → ACCEPTING（接单处理中，内部） → ACCEPTED（已接单） → PROCESSING（处理中） → COMPLETED（已完成）
PENDING → REJECTED（员工退回）
PENDING → CANCELLED（派发人取消）
```
`ACCEPTING` 仅在接单调用 SCM 期间存在，用于阻止并发取消；超过 10 分钟由
`DispatchAcceptRecoveryScheduler` 回退 `PENDING`，员工重试时 SCM 幂等返回已生成的出库单。

### 3.2 `ops_dispatch_order_item`（施工商品明细）

`dispatch_id`、`source_item_id`（`ops_business_order_item.id`）、品牌/品类/型号、数量、单位、销售单价。
仅施工类型；来源为四类商品（燃气灶 1 / 抽油烟机 2 / 热水器 3 / 壁挂炉 4）的正数分录，退货负数分录不纳入。

### 3.3 `ops_dispatch_message`（消息推送记录）

`corp_id`、`dispatch_id`、`scene_code`、`template_id`、`receiver_user_id`、`openid`（接口返回时脱敏）、
`send_status`（SUCCESS/FAILED/SKIPPED）、`error_msg`、`send_time`、`read_status/read_time`、`retry_count`。

### 3.4 `ops_wx_msg_template`（消息模板）

`owner_corp_id`（归属组织；0=平台全局）、`share_scope`（`PRIVATE`/`OPERATOR_TREE`/`PLATFORM`）、
`scene_code`、`template_id`、`title`、`content`、`variable_desc`、`field_mapping`、
`app_id`、`template_id_map`（按公众号 appId 映射模板ID）、`status`、`use_count`、`last_used_time`。
详见 `Specs/公众号消息模板组织共享-规格说明.md`。

### 3.5 `ops_dispatch_sequence`（派工单号流水）

`(company_code, seq_date)` 唯一，`current_no` 原子递增，上限 999。

### 3.6 SCM `scm_sale_outbound` 新增列

`source_dispatch_id`、`source_dispatch_no`；`data_source='DISPATCH'`。

## 4. 派工单号规则

`{公司代码}-PG-{yyyyMMdd}-{3位流水}`，如 `DB-PG-20251113-001`。

公司代码优先级：
1. `application.yml` 的 `ops.dispatch.company-codes`（按 `sys_corp.short_name` 映射，默认 德保=DB、康乐=KL、广河=GH）；
2. `sys_corp.org_code`（生产如 临洮=LT、武山=WH、广河=GH）；
3. `C{corpId}` 兜底。

并发安全：`ops_dispatch_sequence` 按 `(company_code, seq_date)` 行锁 + `dispatch_no` 唯一索引双重保障。

### 5.3 SCM 内部接口

`POST /api/internal/sale-outbound/from-dispatch`（`X-Internal-Token`）：
按 `dispatchId` 幂等，匹配型号 → 物料，取默认客户/仓库，批次商品自动选可用批次，
生成 `DRAFT` 出库单并记录来源派工单号。

### 5.4 底座内部接口

`GET /api/internal/user/wechat/openid?userId=&appId=`（`X-Internal-Token`）：
仅服务端返回员工原始 openid，供 ops 发送模板消息；前端可见接口仍返回掩码。

## 6. 权限与数据隔离

- 发起/取消派工：`FinancePermissionService.canCreateDispatch()` —— **任何员工均可**（员工/平台 JWT；会员 SSO 令牌 `token_type=sso` 拒绝）。数据范围由 `DataScopeService` 控制：城市合伙人仅本组织，运营商含下属组织。
- 员工可通过平台主站「增值业务 → 业务数据 → 发起派工」或公众号 H5 工作台「发起派工」入口操作；**H5 仅可对本组织订单发起**（`DispatchOrderService.createForCorp` 强制订单 `corp_id` = 当前 JWT `corp_id`，跨组织拒绝）。
- 列表/详情：`DataScopeService` 可见组织范围；超管全量，空集合视为无权限。
- 员工：只能查看/操作 `assignee_user_id = 当前员工` 的工单；`JwtTokenInspector` 拒绝会员 SSO 令牌。
- 消息模板：运营商维护本组织模板并可 `OPERATOR_TREE` 共享给下属；城市合伙人查看共享模板 + 维护本公司 `PRIVATE` 模板，共享模板只读；平台全局模板仅超管维护。详见 `Specs/公众号消息模板组织共享-规格说明.md`。
- ops 无自动租户拦截器，所有查询显式带 `corp_id` / 可见组织集合。

## 7. 验收标准

1. 已财务核对订单发起施工派工，商品明细只含四类商品，派工单号符合规则，消息记录生成。
2. 入户随访派工：表体只显示任务说明且必填，接单不生成出库单。
3. 员工点击公众号消息直达工单详情；未登录时先登录并回跳。
4. 员工接受施工工单：状态变已接单，SCM 生成未审核销售出库单，双向关联。
5. 重复点击接受任务不重复创建出库单（SCM 按 dispatchId 幂等）。
6. 员工未绑定微信：消息记录 FAILED，派工单提示原因，员工仍可在待处理看到工单。
7. 财务未核对且非户内美装的订单无法发起派工；已有进行中派工的订单不可重复派工。
8. 员工 A 看不到员工 B 的工单；运营只能操作可见组织范围内的订单。
9. 任意员工（如临洮 18623199820）工作台显示「发起派工」，可对本组织已核对订单派工；平台主站「业务数据」同样显示「发起派工」。
10. 员工调用跨组织订单详情/创建接口返回 403；会员 SSO 令牌调用派工管理接口被拒绝。

   ```
   location ^~ /ops/dispatch-order { proxy_pass http://172.17.0.1:9081; proxy_http_version 1.1; proxy_set_header Host $host; proxy_read_timeout 300s; proxy_buffering off; }
   ```

## 9. 已知限制 / 业务约定

- **户内美装**：口径为品类 6/8/9（户内美装销售/工程/运维）；此类订单未财务核对也允许派工，其余订单必须已财务核对。
- **施工商品**：仅四类正数分录；退货负数分录不纳入。
- **入户随访**：不生成销售出库单（无商品可出库）。
- **SCM 默认值**：自动出库使用 SCM 最近一次出库的客户/仓库；无历史时仓库取唯一可选仓库、客户取运营商关系表首个可见客户。若组织未配置仓库，接单会明确失败并提示先分配仓库。
- **批次商品**：自动选择可用量足够的首个批次；不足时接单失败并提示。
- **消息限制**：公众号模板消息要求员工已关注公众号；未关注/未绑定会失败并记录。
- **取消通知**：需另行配置 `DISPATCH_CANCELLED` 模板；未配置时记录 SKIPPED，不阻断取消。
- **来源订单退货/变更**：已接单工单不自动取消，由派发人人工处理。
- **单实例假设**：接单串行化使用内存锁；多实例部署需替换为分布式锁。
- **一单一出库**：`scm_sale_outbound.uk_source_dispatch` 保证同一派工单最多一张出库单；派工单生成的出库单在 SCM 侧**不可编辑/删除**（前端隐藏 + 后端拒绝），只能审核/反审核，避免破坏派工-出库关联。
