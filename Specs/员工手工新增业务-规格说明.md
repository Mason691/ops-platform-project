# 员工手工新增业务 — 规格说明

> 状态：✅ 已实现（2026-11-03）
> 入口：公众号 H5 → 员工登录 → 员工工作台 → 业务数据 → 新增业务

## 1. 功能概述

为经办人（员工）提供移动端手工录入业务数据的能力，替代必须依赖 Excel 导入的录入方式。新增数据写入 `ops_business_data`，自动归属员工当前登录组织（JWT `corp_id`），经办人姓名/手机号由服务端从平台 `sys_user` 派生，客户手机号匹配或自动创建 `sys_member` 并回写 `platform_member_id`。

## 2. 用户故事

- 作为经办人，我可以在未上报集团的批次下新增一条销售记录，无需等待管理员导入 Excel。
- 作为经办人，我可以新建当天批次，系统按 `公司-YYYYMMDD-001` 自动编号，连续新增时流水号递增。
- 作为经办人，我输入客户手机号后可查询会员姓名并自动填充客户名称。
- 作为经办人，我选择品牌、品类后，型号下拉自动联动筛选。
- 作为经办人，我选择「是否收款=是」时必须上传收款凭证，保存后可在业务数据明细中查看。
- 作为财务/管理员，我可以在既有业务数据列表/导出链路中看到新增数据，并参与提成计算。

## 3. 验收标准

1. 选择现有未上报批次新增，保存后员工业务数据列表按批次可查。
2. 新建批次号为 `{公司简称}-{yyyyMMdd}-{3位流水号}`，当天连续新增流水号递增。
3. 已存在会员手机号：查询后客户名称自动填充且可修改，保存后 `platform_member_id` 正确。
4. 不存在会员手机号：保存时自动创建 `sys_member` 并回写 `platform_member_id`。
5. 是否特批=是时提成比例必填（0–100）；=否时隐藏且按 0 落库。
6. 收款金额 = 销售单价 × 销售数量，前端实时显示，后端重算后入库一致。
7. 是否收款=是时未上传凭证禁止提交；上传后保存成功且明细可预览。
8. 已上报集团批次不出现在下拉列表，直接提交也会被后端拒绝。
9. 新增数据 `calc_status='未计算'`，可正常参与后续个人提成计算。

## 4. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ops/employee/business-data/manual/options` | 表单元数据：员工/公司、可选批次、品牌、品类、型号、新建批次前缀 |
| GET | `/api/ops/employee/business-data/manual/member?phone=` | 按手机号查询平台会员姓名（仅返回 id/姓名/是否找到） |
| POST | `/api/ops/employee/business-data/manual` | 保存手工录入业务数据 |

### 保存请求

```json
{
  "batchNo": "康乐-20261103-001",
  "newBatch": false,
  "customerPhone": "13800138000",
  "customer": "张三",
  "isSpecial": false,
  "commissionRate": 0,
  "brand": "万和",
  "category": "燃气灶",
  "model": "JZT-Q08",
  "salePrice": 1999.00,
  "saleQuantity": 2,
  "receiptDate": "2026-11-03",
  "isReceived": true,
  "voucherUrls": ["/uploads/ops/img/20261103/abcdef12.jpg"]
}
```

### 字段映射

| 表单 | `ops_business_data` | 说明 |
|---|---|---|
| 批次 | `batch_no` | 现有批次校验归属+未上报；新建批次原子取号 |
| 客户手机 | `customer_phone` | 11 位大陆手机号，NFKC 归一化 |
| 客户 | `customer` | 必填 |
| 是否特批 | `is_special` | 是/否 |
| 提成比例 | `commission_rate` | 特批写表单值；非特批写 0 |
| 品牌/品类/型号 | `brand`/`category`/`model` | 品牌、型号存名称；**品类存数据字典 itemKey**（见第 6 节） |

> 产品信息交互顺序：**品类 → 品牌 → 型号**。品类取自 SCM `scm_bd_material_group`（仍按 `PRODUCT_CATEGORY` 字典过滤）；品牌取自 `scm_bd_brand`，按已选品类在 `scm_bd_material` 中出现的品牌集合过滤；型号再按品类+品牌过滤。切换品类清空品牌/型号，切换品牌清空型号。
| 销售单价/数量 | `sale_price`/`sale_quantity` | 单价 >0；数量 ≥1 整数 |
| 收款金额 | `receipt_amount` | 服务端 `单价×数量` 重算 |
| 市场收款日期 | `receipt_date` | `yyyy-MM-dd`，默认当天 |
| 销售日期 | `sale_date` | 取市场收款日期（保证员工月度列表可见） |
| 财务收款日期 | `finance_receipt_date` | 留空（与导入允许留空口径一致） |
| 是否收款 | `is_received` | 是/否 |
| 凭证 | `voucher_url` | 最多 3 张，英文逗号分隔 |
| 会员 | `platform_member_id` | 按手机号匹配；未命中自动创建 |
| 组织/经办人 | `corp_id`/`agent`/`agent_phone` | 全部服务端从 JWT + `sys_user` 派生 |
| 状态 | `calc_status` | `未计算` |

## 5. 多租户与安全

- `corp_id` 只从 JWT 解析，不接受请求参数传入；员工只能向本人所属组织新增数据。
- `agent`/`agent_phone` 服务端从 `ai_platform.sys_user`（`userId` 来自 JWT）派生，忽略前端传值。
- 批次必须属于当前组织且不存在 `已上报集团` 行；否则拒绝。
- 品牌/品类/型号必须存在于供应链基础资料，品类必须命中 `PRODUCT_CATEGORY` 字典。
- 会员查询只返回姓名与会员 id，不返回其他画像字段。
- 已上报集团数据不可新增（批次级守卫）；员工核对仅允许本组织 + 本人数据。
- 会员令牌（`token_type=sso`）即使 `sys_member.id` 与 `sys_user.id` 撞号，也会被 `JwtTokenInspector` 拒绝。

## 6. 关键设计决策

- **品类存储口径**：需求原文要求「显示与存储均使用品类名称」，但 `ops_business_data.category` 在现网 5,324 行历史数据、`ops_personal_commission_rule.category`、`ops_value_added_product.category`、导出与作战地图 ETL 中均使用 `PRODUCT_CATEGORY` 字典 `itemKey`。若新增行存中文名称，提成规则匹配、品类筛选、ETL 品类聚合会出现新旧数据分裂。因此本实现：**表单显示与请求体使用 SCM 品类名称，落库映射为字典 itemKey**，与既有系统口径保持一致。
- **SCM 依赖**：品牌/品类/型号通过员工 JWT 调用 `scm-mehome-service` 基础资料接口；服务不可达时表单显示错误并禁止提交，不做本地兜底造假。
- **批次流水**：新增 `ops_batch_sequence(corp_id, seq_date, last_seq)` 唯一键表，`INSERT ... ON DUPLICATE KEY UPDATE last_seq=last_seq+1` 原子取号，避免 `SELECT MAX+1` 并发重号；已有批次保存前 `SELECT ... FOR UPDATE` 与「提成上报集团」串行化。
- **会员归属**：与导入链路一致——先在本组织燃气公司范围的燃气用户中按手机号匹配 `platform_member_id`，再全局 `uk_phone` 复用，最后自动建会员。
- **事务边界**：员工身份/组织/SCM 品牌品类型号校验（含 HTTP）在事务外完成；`TransactionTemplate` 只包裹批次取号/行锁、会员创建、业务数据 INSERT，避免数据库连接被外部 HTTP 长期占用。
- **员工核对**：`batchCheckOwned(corpId, agentPhone)` 仅更新本组织 + 本经办人的已计算行，不再允许任意 JWT 按批次号跨组织改状态。
- **提成底价**：手工行复用导入的 `matchProductExactOrKeyword` 匹配 `ops_value_added_product`，命中则写入零售底价/集团最低价，保证阶梯提成口径与导入一致。
- **凭证上限**：单条业务最多 3 张，单张压缩后上传，复用 `/api/ops/files/upload`（图片 ≤2MB）。
