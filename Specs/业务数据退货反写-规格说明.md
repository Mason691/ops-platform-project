# 业务数据退货反写（SCM 销售退货）规格说明

> 状态：✅ 已实现并部署生产（2026-11-12）  
> 关联模块：增值业务（ops）、供应链管理（SCM 销售退货）、平台主站业务数据订单页、ops H5 员工端

## 1. 功能概述

客户退货业务统一由「供应链管理 → 销售退货」发起与审批。业务数据订单页**不再提供退货申请/退货审批入口**，仅作为退货结果的承接方：SCM 审核通过后，按退货明细向原业务数据订单反写一条或多条**负数分录**；反审核时删除本单负数分录。

## 2. 数据模型

`ops_business_order_item`（业务数据订单分录）：

| 字段 | 变更 | 说明 |
|---|---|---|
| `sale_quantity` | 语义固定 | 正常分录恒为原始销售数量；退货分录为负数（绝对值=退货数量） |
| `receipt_amount` | 语义固定 | 正常=单价×数量；退货=负数（-单价×退货数量） |
| `commission_amount` | 语义固定 | 正常为正；退货为负（按原分录提成比例冲减） |
| `source_return_id` | 新增 | SCM 销售退货单 ID；空=正常销售分录 |
| `source_return_no` | 新增 | SCM 退货单号（展示/跳转）；历史迁移行=“历史退货” |
| `is_return` | 删除 | 退货事实由负数分录 + `source_return_id` 表达 |
| `return_quantity` / `return_amount` / `settle_quantity` / `return_status` / `original_receipt_amount` / `original_sale_quantity` | 删除 | 不再通过扣减原分录表达退货 |

`ops_business_order` 主表：`total_amount` = 正数产品组 MAX(收款金额) 之和 + 退货单产品组 MAX(负数收款金额) 之和；`total_commission` = 子表提成之和（正负相抵）。

## 3. 反写规则（SCM → ops）

接口：`POST /api/internal/business-data/scm-sale-return`（`X-Internal-Token`）。

审核（`auditStatus=AUDITED`）：
1. 按 `rowIds`（优先）或 `receiptNos` 定位原销售分录，只接受非负数分录；
2. 按「订单 + 品类 + 品牌 + 型号 + 单价」合并数量，锁订单全部明细（`FOR UPDATE`）；
3. 任一明细 `calc_status='已上报集团'` → 整笔拒绝（SCM 审核回滚）；
4. 校验累计退货 ≤ 原始销售数量；
5. 删除本退货单该产品组旧负数分录（支持数量变更重放）；
6. 按原分录**逐经办人**新增负数分录：继承订单号/批次/收据号/corp/客户/手机/会员/小区/地址/经办人/单价/底价/特批/提成比例；`sale_date / receipt_date / finance_receipt_date` 继承原销售分录；`commission_amount=0`、`calc_status='未计算'`；
7. 触发订单提成重算、主表合计/经办人汇总/状态同步。

反审核（`auditStatus=DRAFT`）：锁订单明细 → 校验未上报 → 删除本单负数分录 → 同订单其它 SCM 退货分录标记“未计算”并按新剩余重算 → 主表重算。

业务数据订单含退货分录时禁止物理删除（后端按订单加锁校验），需先在 SCM 反审核退货。

幂等：`ops_scm_return_sync(scm_return_id, group_key)` 记录本单已回写数量；重复回调 delta=0 跳过，数量变化则重建；反审核置 `delete_flag=1`。

一致性：SCM 在本地事务提交前同步调用；ops 失败抛异常使 SCM 回滚。SCM 事务在 ops 成功后仍回滚时，注册 `afterCompletion` 补偿反向调用（幂等）。

## 4. 提成口径

- 正常分录提成 = 提成规则（或特批比例）结果，多经办人按原规则均分；
- 退货分录提成 = `-原销售分录剩余提成（原提成 + 已冲减负数）× 本次退货数量 ÷ 剩余数量`，按原经办人提成占比分摊（末行吸收舍入差）；剩余提成为 0 时冲减 0；
- 反审核删除本单负数分录后，同订单其它 SCM 退货分录标记为“未计算”并按新剩余重算，消除多次退货/撤销的舍入漂移；
- 历史迁移：正数分录保留迁移前已缩放的提成，历史负数分录提成记 0 且 `已计算`，净提成与迁移前一致；后续退货按剩余提成比例冲减，不重复扣减；
- 订单计算状态由主表统一管理；新增退货分录后订单回到 `未计算` → 引擎计算后退货分录置 `已计算`；已上报集团订单禁止回写。

## 5. 前端

- 业务数据订单列表：删除退货审批按钮与退货数量/实际结算数量/退货状态列；
- 展开明细：正/负分录并列展示，退货行红色高亮 + “退货”标签 + 退货单号链接（跳转 `/subsystem/scm/sale-return?billNo=xxx`）；
- 订单行显示“含退货”标签；合计金额按正负分录之和展示；
- ops H5 员工月度明细：退货负数金额/提成红色展示，移除“申请退货”入口。

## 6. 导出与统计

- 导出 29 列：移除 退货数量/实际结算数量/退货状态，保留/新增「退货标识」（负数分录=是）；纯销售导出可直接回导，含退货的导出需先剔除退货行（导入只接受正销售数量，退货由 SCM 反审核/重审生成）；
- `aggregateStats/categoryStats/categoryCompanyStats` 去重键区分退货分录：退货不参与正向“同一收据号只计一次”去重，按退货单+产品组作为独立冲减项；
- 作战地图、员工业绩、会员台账、品类提成汇总按正负合计口径；会员台账设备/业务数排除退货分录。

## 7. 迁移

`sql/migrate_business_return_negative_entries.sql`：

1. 新建 `ops_scm_return_sync`；新增 `source_return_id/source_return_no` + 索引；
2. 历史 `return_quantity>0` 行按经办人生成负数分录（`source_return_id=0`、`source_return_no='历史退货'`、提成 0、已计算）；
3. 正数分录恢复 `sale_quantity`/`receipt_amount` 为原始值（提成保留缩放值）；按 `settle_quantity` 与 `sale_quantity` 是否相等兼容两种历史语义：HEAD 旧审批 `sale_quantity` 未扣减、未发布 SCM 改造 `sale_quantity=剩余数量`；
4. 删除旧退货字段/索引与 `ops_business_return` 表；
5. 重建兼容视图 `ops_business_data`；全量重算主表合计/提成/状态；
6. 末尾输出负数行数、无标记行数、遗留列数、主表差异数验证结果。

部署顺序：停 ops → 迁移 → 新 ops JAR → 新 SCM JAR → 前端。旧 SCM 查 `original_sale_quantity`，删列后会失败，必须同一窗口升级。

## 8. 验收

1. 业务数据订单页无退货入口；
2. SCM 销售退货审核通过 → 原订单新增负数分录（红色、数量/金额/提成为负、公共信息一致）；
3. 主表合计 = 正负分录之和；
4. 重复审核/回调不重复生成；
5. 订单提成合计 = 正数提成 + 负数冲减；
6. 导出/品类提成汇总/作战地图/员工业绩/会员台账含退货时正确冲减；
7. 已上报集团订单退货被拦截并有明确提示；
8. 旧退货列从前端/接口/导出移除；历史迁移后无重复扣减。
